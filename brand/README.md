# SellerKit 品牌标识 · 插槽 S（v1.0 / 2026-11-06）

一页式可视规范见同目录 `index.html`（可直接用浏览器打开，右上角可切换明暗主题）。本文件是文字版规范与接入说明。

## 1. 设计依据

设计前先对齐了项目现状，结论是「不另起一套视觉语言」：

| 现状                                                                                           | 对 logo 的约束                                                       |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `build/icon.png` 及 `build/icons/**` 仍是 **Electron 默认占位图**（蓝底白圆环）                | 需要一套正式图标源，但不能引入与界面无关的亮蓝                       |
| `src/core/AppShell.vue` 侧栏品牌位是 `w-8 h-8 rounded-lg` 底 + 文字「SK」                      | 主标必须是方形容器，圆角比例与 8px 同源                              |
| `src/styles/index.css` 为灰白黑冷色调，石墨主色 `#2b2f36`、冷灰强调 `#5a6472`，双主题、WCAG AA | 主色直接取现有 `--wb-*` 令牌，只新增一个信号色；且必须能在单色下成立 |
| 架构是「宿主 + 构建期模块裁剪 + 运行时插件 / 市场 UI 岛」，业务是「导入 → 归类 → 拿货 → 对账」 | 概念应表达「可拼装」与「一条流」，而不是通用购物袋/购物车            |

**概念**：一笔连续笔画构成 **S**（Seller/SellerKit）；腰部断开 10 单位并嵌入一块独立**模块**，对应可插拔的模块与 UI 岛；笔画从右上入、经中段、向左下出，呼应发货台数据流。识别靠形状不靠颜色——模块与笔画同色时断口自然合拢，退化成一个干净的 S，单色印刷与托盘图标均可用。

曾评估另两个方向，均未采用：模块矩阵（架构最直白，但 16px 下糊成方格）、SK 字标（最保守，但字体须转曲、记忆点弱）。

## 3. 几何规范（64 × 64 网格）

所有尺寸等比缩放，不单独重画。

| 参数     | 值                                 | 说明                                     |
| -------- | ---------------------------------- | ---------------------------------------- |
| 底板圆角 | `rx = 16`                          | 25% 边长，仅应用图标使用                 |
| 笔画宽度 | `10`                               | 圆头（`stroke-linecap=round`）、圆角连接 |
| 转折半径 | `6`                                | 上下两个 C 形弯                          |
| 中段断口 | `x 27 → 37`                        | 10 单位，与笔画等宽                      |
| 模块方块 | `10 × 10, rx 2.5`，居中 `(32, 31)` | 靛色；单色版取 `currentColor`            |
| 符号占位 | `x 11–55, y 11–51`                 | 四边留白 11–13 单位                      |

两段路径（唯一事实源，所有资产由此派生）：

```
M 50 16 H 22 A 6 6 0 0 0 16 22 V 25 A 6 6 0 0 0 22 31 H 27
M 37 31 H 43 A 6 6 0 0 1 49 37 V 40 A 6 6 0 0 1 43 46 H 16
```

≤24px 简化版合并为一条：

```
M 50 16 H 22 A 6 6 0 0 0 16 22 V 25 A 6 6 0 0 0 22 31 H 42 A 6 6 0 0 1 48 37 V 40 A 6 6 0 0 1 42 46 H 16
```

## 4. 配色与对比度

数值按 WCAG 2.x 相对亮度公式实算，非文本图形元素门槛为 3:1（1.4.11），正文为 4.5:1。

| 角色                             | 色值      | 来源                          | 实测对比                                  |
| -------------------------------- | --------- | ----------------------------- | ----------------------------------------- |
| Graphite 石墨（底板 / 浅色笔画） | `#2B2F36` | `--wb-primary`（浅）          | 白笔画 13.44:1；对画布 11.88:1            |
| Paper 反白（图标 S 笔画）        | `#FFFFFF` | `--wb-primary-contrast`（浅） | 13.44:1                                   |
| Signal 信号靛 · 浅（模块）       | `#5B74F0` | **新增**                      | 对石墨 3.33:1；对画布 3.57:1；对白 4.04:1 |
| Signal 信号靛 · 深（模块）       | `#8CA0FF` | **新增**                      | 对深表面 `#191C22` 6.98:1                 |
| Chalk 冷白（深色主题笔画）       | `#E4E7EB` | `--wb-primary`（深）          | 对深表面 13.76:1                          |
| Slate 冷灰（字标 Kit）           | `#5A6472` | `--wb-accent`（浅）           | 对画布 5.31:1（AA 正文达标）              |
| Canvas 画布                      | `#EFF1F5` | `--wb-bg`（浅）               | —                                         |

**红线**：信号靛最高只有 4.04:1，**禁止用作文字色**，只作图形模块。深色主题下界面标笔画取 `--wb-primary` 的冷白值。

## 5. 字标

`SellerKit`，系统字体栈（与 `body` 一致）：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif`。
`Seller` 用主文字色 + 600 字重，`Kit` 用冷灰 `#5A6472` + 400 字重，`letter-spacing: -0.02em`。两档字重形成层级，不是两种颜色。

> **未转曲**：组合标 SVG 中字标以 `<text>` 呈现。界面内使用与项目字体栈一致；用于对外印刷、市场物料或要求跨平台像素一致时，需先转为路径。

## 6. 留白 / 最小尺寸

- **安全留白**：四周净空 ≥ 1 个模块方块宽度（10/64 ≈ 16% 边长），最小不低于 8px。横版组合标中标志与字标间距 12px（标志 40px 时）。
- **完整版最低 32px**；16–24px 的**界面内联标**一律换 `logo-mark-sm.svg`。应用图标目录里的 16/24 是主图标经矢量重采样的等比缩小版（实测仍可辨），不受此限 —— 两者场景不同。
- 应用图标固定色，不随主题反相；只有透明底的主题化标志才跟随主题（Dock/桌面辨识需要稳定）。

## 7. 接入落地（2026-11-06）

实际做法与最初的「三步建议」有一处调整，**以本节为准**。

| 面           | 落地位置                                                                                       | 说明                                                                                        |
| ------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 应用图标     | `build/icon.png`、`build/icons/png/*`、`build/icons/mac/icon.icns`、`build/icons/win/icon.ico` | 由 `scripts/gen-icon.js` 从 `brand/logo-appicon.svg` 渲染，`npm run icons` 可复现           |
| macOS 托盘   | `build/tray-template.png` + `@2x`、`electron/main.ts#trayIconPath()`、`electron-builder.yml`   | 透明底单色模板图，1x 18px / 2x 36px；darwin 分支不再 resize，保留 @2x 表示                  |
| 侧栏品牌位   | `src/core/AppShell.vue`                                                                        | 文字「SK」→ `<AppLogo :size="32" />`                                                        |
| 设置 › 关于  | `src/core/components/SettingsModal.vue`                                                        | 文字「SK」→ `<AppLogo :size="36" />`                                                        |
| 单一引用点   | `src/core/components/AppLogo.vue`                                                              | 两处界面都只 import 这一份 SVG，避免改图标时漏改                                            |
| 页面 favicon | `index.html` → `./brand/logo-icon.svg`                                                         | Vite 按 `base:'./'` 重写成 assets 相对路径；消除浏览器盲请求 `/favicon.ico` 的 404          |
| Chrome 扩展  | 兄弟仓库 `SellerKitExtensions` 三个 MV3 扩展的 `icons/` + `manifest.json`                      | 复用 `build/icons/png/{16,32,48,128}`；补 `icons` 与 `action.default_icon`，并升 patch 版本 |

**方案调整（重要）**：界面内展示的是**应用图标**（固定色、与 Dock / 安装包同一张脸），不是透明底的主题化标志。因此**没有新增 `--wb-logo-signal` 令牌，也没有改 `WB_THEME_TOKENS`** —— 固定色图标不需要主题令牌，凭空加一个只有注入清单会用、界面却不用的令牌属于冗余。`logo-mark.svg` / `logo-mark-sm.svg` 保留给「真正需要主题化的内联场景」（如将来岛内、文档页眉），届时再按本节原建议加令牌并同步白名单。

`scripts/gen-icon.js` 原先是手写 Electron 默认占位图（蓝底白圆环）的生成器，每跑一次就会把品牌图标覆盖回去，属回退陷阱，已整份替换。渲染用无头 Chrome + CDP 拿透明 RGBA；**只给 `omitBackground: true` 实测仍输出 RGB（四角被合成白角），必须再叠加 `Emulation.setDefaultBackgroundColorOverride` 才生效** —— 这是本次踩到的坑。

**macOS 托盘为什么必须单独出一份图**：`nativeImage.setTemplateImage(true)` 让系统**只按 alpha 渲染剪影**、忽略 RGB。彩色应用图标带整块不透明底板 ⇒ 剪影退化成实心圆角方块，S 完全消失（已用 canvas 模拟实证）。故 `logo-tray-template.svg` 去掉底板与靛色模块，只留透明底纯黑 S 轮廓，并把腰部断口从 10 加大到 20 单位 —— 圆头端点各占约 5.5 单位，断口太窄会被两端点填满，又变回一条连续笔画。最终 18×18 的 y=9 中心行实测为两段 `(2,7)` 与 `(11,15)`，中间 3px 空隙；浅色 / 深色菜单栏剪影下 S 与断口均清晰。`electron-builder.yml` 的 `extraResources` 必须同时带 1x 与 `@2x`，漏一个高分屏会发虚或找不到模板图。

## 8. 禁用

不改线宽/转折半径/断口宽度/圆头端点 · 不拉伸压扁 · 不加渐变、投影、发光描边 · 不用品牌色之外的填充 · 不重绘字标字形 · 不用信号靛排文字 · 不给应用图标加主题反相变体 · **不要手改 `build/` 里的位图**（一律走 `npm run icons`）。
