# ADR-001: excel-copy / order-insight 的设置保留在岛内视图，不收编进宿主「设置」模态

## Status

Accepted (2026-09-22) — 决策人：项目方。取代 `HOST_REVIEW_2026-09-22.md` §6 待决策项 2 的
开放状态；该报告的「已知偏差」标注（§1.5 相关段落）应视为已被本 ADR 结案。

## Background

`AGENTS.md` §1.5 定下一条通则：**宿主是设置页的唯一入口**，业务功能设置一律收进
宿主「设置」模态，内容页只留高频操作。规则本身没错——它避免了设置入口碎片化。

但三轮下记之后出现了一个反例：`excel-copy` 与 `order-insight` 两个业务模块被下记为
市场 UI 岛，**它们的设置面板仍留在岛自己的视图里**，既没有声明 `manifest.settings`，
因此也不会出现在宿主设置模态的分类导航中。这与 §1.5 的通则不一致，
在 `HOST_REVIEW_2026-09-22.md` 中被记为已知偏差（M-04）。

不一致需要有个交代：要么改代码去符合通则，要么改通则去承认例外。悬着不处理，
下一个人读到 §1.5 时会以为这是个待修的 bug，从而"顺手修掉"——而那个修法是有害的
（见下）。

## Decision

**保留设置面板在岛内视图，不收编进宿主设置模态。**

具体：

1. `excel-copy` / `order-insight` 继续在岛视图内承载自己的设置，不声明
   `manifest.settings`，不进宿主设置模态的分类导航。
2. 岛内如需引导用户去宿主设置（例如插件管理、权限），仍走既有桥能力
   `sk.host.ui.openSettings(...)`；这是"从岛跳宿主"，与本 ADR 不冲突。
3. `AGENTS.md` §1.5 的通则保留不变，但其下方的偏差说明改为**引用本 ADR**，
   使通则与例外同时可见。

## Rationale

决定性理由是**编辑-预览回路**：

这两个插件的核心使用循环是「改模板 / 改字段规则 → 立刻看这份 Excel 的数据长什么样」。
设置面板与数据预览**在同一个视图里**时，改完一条规则能立刻看到结果，失败也立刻可见。
收编进宿主设置模态后，用户必须：打开设置 → 改规则 → 关闭设置 → 切回岛 → 看结果，
回路被打断成四步。这不是"入口美化"能补偿的体验损失，是核心价值的直接折损。

对照：`shop-accounts` 之所以适合收编（它已声明 `manifest.settings`），正因为它的
设置是**低频、与数据预览无关**的账号管理——改完不需要立刻看数据变化。
两者的差别不在"是不是设置"，而在"改完要不要立刻看结果"。

## Consequences

正面：

- 保住「改模板 → 立刻看预览」的联动循环，这是两个插件的核心价值。
- 零代码改动，零回归风险（收编需要同时改宿主设置模态与两个岛，且要处理状态同步）。
- 岛自带设置，对市场分发的第三方插件是同一套心智：设置跟着插件走。

负面（明确接受）：

- §1.5 的"唯一入口"通则出现两个例外，文档不再是单一规则。缓解：本 ADR +
  `AGENTS.md` 指向 ADR，使例外是**显式决策**而非**疏漏**。
- 用户可能在宿主设置里找不到这两个插件的设置项。缓解：设置项仍在岛视图内的固定位置，
  且岛是侧栏直达的，查找成本低于"猜它在宿主的哪个分类"。
- 若将来出现更多同类岛，例外数量会增长。触发重新评估的条件见下。

## When to revisit

出现以下任一情况时应重新评估本决策：

1. 宿主设置模态支持**同屏预览**（例如右侧抽屉 + 左侧数据区，改完即时生效）——
   届时收编不再打断回路，应统一收编。
2. 同类（设置与预览强耦合的）岛**达到第 3 个**——例外从"两个特例"变成"一类形态"，
   应改为在 §1.5 中新增一种形态分类，而不是继续加例外。
3. 用户反馈"找不到设置"成为可观察的痛点。
