00结论

先给判断，再给证据。

这个应用的控件层已经很干净（按钮、输入、标签、骨架五种结构都收敛到 src/styles/index.css 的 @layer components，字号硬编码只剩 23 处）。
真正让它"看起来还是一块灰"的，不是配色，是三种节奏缺失： 级差（标题 17 / 数字 15 / 正文 13，每级只差 2px，1440 宽屏上几乎看不出主次）、 留白（面板一律撑满容器，2 行数据下面留 400px 死白，读起来像"没加载完"）、 发声（全屏唯一彩色是警告橙，于是橙色从"注意"退化成"背景噪音"——同一屏出现过两条几乎一样的橙条）。
所以本方案的第一条纪律是：一个颜色都不加，只把级差拉开、把留白收住、把发声点从 N 处收到 1 处。
上手可发现性7.5默认包自洽，入口 2 级
术语友好度8.0已白话化，残留"款/产品/商品"
导航一致性7.0二级项像一级项
反馈完整性7.5空态四段已齐，死白无收束
视觉层级5.5级差过窄，焦点不唯一
键盘效率4.5有焦点环，无键盘动线

评分口径：只看"已经做出来的东西用户能不能用上"，不评功能缺口。视觉层级与键盘效率是本次的两个主战场。

01四个视觉病根（都可当场复核）

每一条都能在真实截图或代码里指到具体位置；不是审美偏好。

A · 级差过窄类型层级
页标题 17px、主数字 15px、正文 13px、说明 12.5px、表头 12px —— 五档挤在 12–17px 之间，相邻两级只差 0.5–2px。 在 1440 宽的窗口里，这等于没有层级：用户扫屏时找不到"从哪里开始读"。 取证：index.css 的 .wb-head__title 17px / .wb-metric b 15px / .wb-table 13px / .wb-head__desc 12.5px / .wb-table th 12px。
B · 数字不是主角信息权重
业务是"看数、点单"，但指标条里标签和数字写在同一行、只差 2.5px 字号， 「订单行 1 收入合计 165.18」读起来是一句话，用户得逐字读完才知道哪个是数。 取证：.wb-metric 为 inline-flex baseline，标签 12.5px muted、数字 15px —— 差值仅 2.5px，且横向串读。
C · 死白无收束留白节奏
面板一律 flex:1 撑满容器：2 行数据下面 400px 纯白，没有任何"到这为止"的信号。 用户看到的不是"内容少"，而是"是不是没加载完 / 是不是下面还有"。 取证：full-1440x900.png 左栏表格区 y≈400–555 全空；overview 页 y≈280–560 全空。
D · 发声点太多注意力经济
全屏唯一强色是警告橙 --wb-warning，而它同时出现在两条几乎相同的提示条上 （"1 家店还没登记，卖出去的挂不上款" / "1 家店还没登记，采回来的先认不了"）。 同一条根因拆成两条并列，用户的反应不是"去看"，而是"又来了"——从这一屏开始，橙色就失效了。 取证：full-1440x900.png y≈140 与 y≈168 两条 .wb-tag.is-warn 同款提示条。

02五条原则（后面所有取舍都由它们裁决）

原则要能当裁判用 —— 出现分歧时，能一句话判对错。

#原则判据（怎么用一句话裁决）
1一个焦点每一屏只允许一个实心主按钮 + 一个最大字号数字。出现第二个，就得说明它凭什么同级。
2级差 ≥ 1.25×相邻字级必须差 1.25 倍以上（13 → 16 → 20 → 26）。差 2px 的"层级"不算层级。
3安静默认，一处发声强色底（warn/danger/实心主色）同屏最多一处；同根因的多条合并为"N 条 › 去看"。
4位置恒定动作钉在它所作用的对象上（列表头 / 行尾 / 段尾），不随数据量漂移；常驻条只在有内容时存在。
5手不离键高频动线（导单 → 归类 → 拿货 → 对账）全程可键盘：↑↓ 选行 · Space 勾选 · Enter 进/提交 · Esc 退 · ⌘Z 撤。

03规范：字阶、数字、节奏

这是唯一需要"新写代码"的部分，其余都是重排。所有值都基于现有令牌，不新增颜色。

3.1 字阶：从"等差 2px"改成"比例级差"

角色现状建议倍率用在哪 / 为什么
Hero 数字15px26px / 650—每屏唯一的"今天要处理多少"。现被埋在 15px 里，与说明文字同级。
页标题17px17px / 6501.53×不动。17 是对的，问题在它下面的级差断了。
面板标题13px14px / 6501.17×与正文拉开半档，面板边界才"立"得起来。
正文 / 表格13px12.5px1.40×不升反降：桌面高密度工具，密度是资产。降 0.5px 换来上面三级能拉开。
表头 / 说明12px11.5px1.09×辅助信息，允许更小（仍在可读下限 11px 之上）。
徽标 / 单位12px10.5px1.10×只在 pill 内出现，配 tabular-nums。
纪律升的只有两处（Hero 数字、面板标题），降的是辅助级。总密度不变 —— 这是"拉开"而不是"放大"。

06键盘动线：这是"顺手"和"能用"的分界

这个软件一天要用很多次、每次做同样几件事 —— 这类工具的效率天花板在键盘上。 现状：焦点环已经补了（:focus-visible），但没有任何一条快捷键约定。

按键作用域行为
↑ ↓表格移动当前行（不改勾选：选中是"标记要处理"，移动是"看下一行"，两件事不能合并）
Space表格勾选 / 取消当前行
Enter表格 / 抽屉进详情 / 提交主操作
⌘ Enter抽屉提交并继续下一项 —— 连续录入（认款、批量改价）唯一省力的地方
Esc抽屉 / 弹层关闭；有未保存改动时先问一次
⌘ Z全局撤销上一步写操作（toast 上给「撤销」按钮，3 秒内有效）
⌘ K全局已有。建议补一层：把当前模块内的页签也搜进去（现在只列模块）
注意⌘K 纳入页签与既有裁定"七项只在模块内成立"冲突（notes/2026-10-30-ui-nav-and-tabs.md §9）。这条列为待拍板，不默认做。

本仓有硬约束：模板里的可见文本是冒烟断言的一部分（整段 textContent 拼串）。 所以批次按"是否触碰文本节点 / DOM 结构"来切，而不是按视觉收益切。

批次内容改动面风险与门禁
P0 ① .wb-metric 视觉顺序反转 + 主指标 26px
② 字阶令牌 --wb-fs-* 落地并替换 5 处骨架类
③ 侧栏二级项去图标 + 引导线
④ 面板 align-self:start
⑤ 双栏 38/62		 纯 CSS（index.css + 少量类名） 零文案、零 DOM 变化 ⇒ 冒烟断言不受影响。唯一坑：新增 --wb-fs-* 必须同步 WB_THEME_TOKENS，否则 uiIslandThemeTokens.spec 直接红。

P0 的验收方式（可复跑）

  • 不靠肉眼：改前改后各跑一遍 npm run goods:shot 与 today:ui，前者出图对比，后者保证断言未动。
  • 级差可量：脚本里取 getComputedStyle 的 fontSize，断言 Hero 数字 ≥ 1.4 × 正文 —— 只断言"有 class"会恒绿。
  • 死白可量：面板 scrollHeight 与 clientHeight 之差 / 面板高 > 50% 时，必须存在收束行（否则红）。
  • 颜色零新增：grep -c "#[0-9a-f]\{6\}" src 改前改后数字不变。
