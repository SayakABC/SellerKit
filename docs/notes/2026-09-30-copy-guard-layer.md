# 用户可见文案的守卫该落在哪一层：真机冒烟读 innerText > 源码正则

**结论**（2026-09-30 落地）：给"用户可见文案"做回归守卫时，

1. **首选真机冒烟读 `innerText`**（我们已有：`npm run plugins:island:smoke` 的**工具条文案体检**）——
   读的是"用户**实际看得见**的文本"，因此**折叠区（`v-if` 收起）天然不在里面**：
   一条断言同时守住两件事 ——「不出现内部术语」与「调试入口必须默认收起」。
2. **源码正则只钉结构性事实**（"诊断区存在且被 `v-if="showDiag"` 包着"、"徽标文案来自 `badgeFor`"），
   **不要拿它判文案**：注释、被折叠的模板、拼接字符串都会命中 ⇒ 误报会把真信号淹掉。

## 为什么（这次的实测路径）

- UX 计划原本要新写一个扫源码的 `tests/uxCopy`。评估后放弃：宿主文案散在模板、`:title`、
  `toast(...)` 实参、事件 dispatch 的字符串里，正则要么扫不全、要么把注释里的术语（本仓注释写得很多）
  当成违规。**"看起来红了"但红的全是噪声**，等于把校验器改瞎。
- 真机冒烟那条则相反：`document.querySelector('.ui-island-bar').innerText` 拿到的就是像素级呈现，
  没渲染出来的（折叠的「诊断」）自然拿不到。落地后 6 个岛全绿，且把「等待桥握手…」改回去会立刻变红。

## 顺带定下的两条纪律

1. **术语规则成文**（`AGENTS.md` §1.10「用户可见文案纪律」）：禁用族 = 能力域/表名/op 名 ·
   进程与协议名（宿主/桥/iframe/CSP/realm/token）· 权限审计内部词（越权/权限门）· 内部分级（L0/L2/外置·）·
   主键 ID · **悬空功能名**。改写方向：能力/来源/状态说人话 + 空态三段式（现状 + 原因 + 一个可点的下一步）。
2. **例外要写明**：插件中心的**权限明细**那一列保留技术细目（哪个域、哪些动作）—— 知情同意需要精确范围。
   例外写进规则文件，而不是留在作者脑子里；否则下一个人会"顺手统一"掉它。
