# 界面"好看"这件事：改的是**骨架**，不是控件

**结论**（2026-10-01，样式治理第二轮；第一轮见 `docs/notes/2026-10-01-ui-style-system-audit.md`）

1. **"难看"的根因是层次缺失，不是配色或控件不统一。** 第一轮已经把按钮/输入/标签收敛成同一套
   （控件层），但用户仍然说"还是很难看" —— 因为：
   画布 `#f6f7f9` 与面板 `#ffffff` 只差约 **2%**（看不出卡片边界）、全仓**零阴影尺度**、
   字号集中在 12–13px（标题只比正文大 5px）、统计数字写成一句流水（`产品 2 SKU 3 缺克重 0`）、
   空态是一行居中灰字飘在大片空白里。用户看到的是"一整块浅灰 + 一堆同重量文字"。
2. 这轮补的是**五种结构骨架**（`src/styles/index.css` 的 `@layer components`）：
   `.wb-page` / `.wb-head`（页头：标题 + 描述 + 动作）/ `.wb-metabar`（指标条：标签 + 数字）/
   `.wb-panel`（画布上的白卡，带投影）/ `.wb-empty`（空态四段：图标 / 标题 / 说明 / 动作）/
   `.wb-table`。
   同时把画布压到约 5% 反差、新增 `--wb-elev-1/2/3` 三档投影与 `--wb-border-strong`。
3. **视觉重构有一条硬约束，见下节** —— 它比"用哪个颜色"重要得多。

## ⚠️ 硬约束：改模板结构会让断言变红，而红的**不是样式**

`scripts/today-ui-smoke.mjs` / `goods-ui-smoke.mjs` / `picking-ui-smoke.mjs` /
`order-profit-ui-smoke.mjs` 在无头 Chrome 里跑**真实构建产物**，断言形如
`/产品 2/`、`件数 7`、`缺克重 0 行`、`1 个 SKU · 3 件`，判据是：

```
el.textContent.replace(/\s+/g, ' ').trim()
```

它 **不会在元素之间插空格**。取证 —— `npm run goods:ui` 的真实输出：

```
PASS 统计条：产品 2 / SKU 3 / 缺克重 1 / ... | 产品 2SKU 3缺克重 1未关联厂家 1已映射商品ID 4
```

`产品 ` 的尾空格位于文本节点内被保留；而 `2`（在 `<b>` 里）与下一个 `SKU`（下一个元素）
之间**一个字符都没有**。于是：

- ❌ **把"标签 + 数字"拆成两个兄弟元素**（`<span>产品</span><span>2</span>`）→ 拼成 `产品2` → 断言红。
- ❌ **依赖模板里的裸空格**：Vue 编译器默认 `whitespace: 'condense'`，**含换行的纯空白文本节点会被整段删除**
  （不含换行的只压成单个空格）。`{{ n }} <span>个 SKU</span>` 只要被 prettier 重排成两行，
  那个空格就没了。而 prettier 的 `htmlWhitespaceSensitivity: css` 又会把 `<span>产品 <b>X</b></span>`
  排版成 `>产品 <b>X</b></span\n>` 这种**刻意保空白**的形状 —— 两种行为混在一起，靠肉眼读源很难判断。
- ✅ **允许的改法**：换 class、加包裹元素（父级或兄弟）、改样式。**文本节点本身逐字不动。**

**推论（比本条规则更重要）**：模板里的可见文本是**既有验收契约的一部分**。
要改文案或改结构，正解是 ① 有意识地一并改断言，② 并把判据从"整段拼串"升级为"按元素断言"
（给文本元素加稳定的 `data-act`，断言钉在元素上）。若只是顺手把断言改成新拼串，
等于**用测试迁就实现**，把"用户还能不能看见那句话"的守卫悄悄删掉。
本轮只做视觉，故**一字未改**。

## 附 A：视觉复核怎么取证（可复用）

- 无头 Chrome 把 `--dump-dom` 换成 `--screenshot=<png> --window-size=1440,1000`，
  即可**复用既有冒烟的假桥与数据夹具**拿到真截图（不必另写一套 fixture）。
- 要冻结在某个中间状态：在该脚本的 `step('x');` 之后插一句 `return;`。
  断言结果写不出来无所谓，要的是那一帧画面。
- ⚠️ 参数替换要按 **`'--dump-dom',` 这一个 token** 匹配，不要按整串匹配 ——
  各脚本里它有时单行、有时在多行数组里，整串匹配会静默漏掉（本轮踩到）。
- 深色主题：注入 `setTimeout(() => document.documentElement.setAttribute('data-theme','dark'), 1200)`
  即可（主题是 `data-theme` 属性驱动，见 `src/core/services/theme.ts`）。
  本轮用它核了浅色/深色两套主题与四个页面。

## 附 B：`--wb-shadow` 是**颜色**，不是整套阴影

新增的三档投影刻意**不叫** `--wb-shadow-sm` —— 存量 `--wb-shadow` 是**颜色**
（岛内抽屉按 `box-shadow: ... var(--wb-shadow)` 自行拼装）。同名同前缀必被传错，
故另起 `--wb-elev-1/2/3`。

新增令牌必须同步进 `src/core/plugin/uiBridgeHost.ts` 的 `WB_THEME_TOKENS`：
`tests/uiIslandThemeTokens.spec.ts` 双向校验（清单 ⊇ 定义、且清单内无孤儿），漏一处即失败。
本轮新增 `--wb-border-strong` 与 `--wb-elev-1/2/3`，四处一起改。

## 附 C：本轮**没有**改的

- `ui-plugins/**` 下的任何岛（岛内自带样式，只通过注入令牌跟随宿主；本轮只增令牌、未改语义）。
- 文本框正文的 13px 尺度（桌面高密度工具，13px 是既有标准）。
- 任何**文案**（见上节"硬约束"）。
