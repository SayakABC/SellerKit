# 「功能串不起来」类诊断：必须跑真实库，代码只能告诉你"能做什么"

**场景**：用户问"当前项目的数据能不能支撑这条流程 / 这些功能为什么串不起来"。
**结论**：**光读代码会得出方向性错误的结论** —— 本轮 3 个假设全部被真实库实测推翻。
只读连库跑一组 count / distinct 就能避免，成本极低（半小时）。

```bash
python3 -c "
import sqlite3,os
p=os.path.expanduser('~/Library/Application Support/seller-kit/sellerkit.db')
c=sqlite3.connect(f'file:{p}?mode=ro',uri=True).cursor()   # mode=ro：只读，绝不改用户库
print(c.execute('SELECT color,COUNT(*) FROM oi_orders GROUP BY color ORDER BY 2 DESC').fetchall())"
```

## 四个实测教训（换项目也照这个思路验）

### ① 填充率 ≠ 可用 —— 要看**取值分布**，不是有没有值

`oi_orders.color` 填充率 **157/157 = 100%**，看起来"颜色数据齐全"。
按取值分布一看：**62 行（39%）是 `Picture color` / `Image Color`** —— 这是平台的"以图为准"占位值，
**根本不是颜色**。剩下的是中英文混杂（`black` 与 `黑色` 并存、`Red` 与 `红色` 并存）。

> **判据**：用户说"这个字段只能靠肉眼/只能人工判断"时，**先 `GROUP BY` 看取值** ——
> 十有八九是"字段有值，但值是占位/原文/别名"，而不是"字段为空"。两者的解法完全不同：
> 前者要**归一 + 定权威源**，后者要**补采集**。

### ② 主数据的工作量按**去重实体数**算，不是按行数

"商品ID ↔ 产品"的映射表只有 3 行，直觉是"要建几百条"。实测：

- 42 行订单里的商品ID **去重后只有 17 个**；现有 3 条映射已覆盖其中 **26 行（62%）**。

> **判据**：任何"要给 XX 建映射/建主数据"的判断，先
> `SELECT COUNT(DISTINCT <实体键>)`，别用行数吓自己。**一个商品ID/店铺/供应商 对应几十行订单是常态。**

### ③ 写时触发的同步**不回溯存量**

`electron/purchase-cost-sync.ts` 在每次拿货写操作后自动同步成本 —— 但当前库里
拿货单 3 张（全 `submitted`）、明细 12 行有价，`ae_cost_map` 却是 **0 行**：那几张单建在同步机制**上线之前**。

> **判据**：任何"以后自动同步"的新机制上线，都要单独问一句**"存量怎么补"**。
> 本轮的表现是"货拿了、钱花了，利润里却没成本"——数字凭空变好看，且**不报错**。
> （这条在 `purchase-cost-sync.ts` 的文件头注释里已经写过一次，是同一个坑的第二次现形。）

### ④ 同一张表的行可能有不同**来源形态** —— 按"键集"分组就能看出来

`oi_orders` 157 行的 `raw_fields` 有两种**完全不同的键集**：

| 键集 | 行数 | 来源 | 下游后果 |
| --- | --- | --- | --- |
| `{__migratedFrom, 采集帧}` | 115 | 老采集表迁移（v4） | **无产品ID、无图、未识别款** —— 拣货/取图/识别**全部静默失效** |
| `{店铺名,尺寸,订单号,下单时间,产品信息,产品数量,产品图片链接,产品ID}` | 42 | 新导入（芒果店长） | 正常 |

这 115 行全 `status='pending'`，会被拣货投影照收 → 157 行聚出 **75 组**，绝大多数是 `(未识别款)` 噪声。

> **判据**：诊断"某功能数据不对"时，先按 `raw_fields`（或等价 JSON 列）的**键集分组**数一遍。
> **"同表不同形"** 是迁移 + 新导入并存时的必现现象，而**按 JSON 字段解析的功能会对老形态静默失效**
> （取不到 → 按兜底值走 → 不报错）。

## 一句话

**代码告诉你"系统能做什么"，只有真实库告诉你"它现在实际有什么"。**
做差距审查时先花半小时跑只读 `count / distinct / group by`，
再动笔写方案 —— 否则会把"很容易的事"写成"大工程"，或反过来。
