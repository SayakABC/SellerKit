# 导入回执：导完之后「数据去哪了 / 下一步做什么」（2026-10-05）

**结论一句话**：统一导入的返回值从"一句人话"升级成**结构化回执**（`title` / `landed` / `next`），
今天页把它渲成一张常驻卡 —— 落点说清"存到哪儿、在哪看得到"，下一步是**真按钮**。
零新 IPC 通道、零新表、零能力域变更、岛无需发版。

## 为什么改（用户原话）

> 现在的流程还是不够直观，导入订单后，接下来不知道要做什么，并且数据也不知道去哪了

旧实现的 `message` 其实写得挺全（判据 + 导了多少行 + 拆行 + 主图 + 店铺），
但它**同时缺两样东西**：

1. **没有目的地** —— 只说"已导入 17 行"，没说进哪张表、去哪个页面能看见；
2. **没有动作** —— 三张卡并列摆着，用户得自己判断"导完订单该点哪个"。

## 改法

| 层 | 改动 |
| --- | --- |
| `src/lib/importDetect.ts` | `ImportDetection` 加 `variant`（具体子类名，如 `芒果店长待发货订单`；`item-info` 标识"认出但不该导"的那支） |
| `src/core/services/importSheet.ts` | `AutoImportResult` 加 `title` / `landed` / `next`，四类分支各自填全 |
| `src/modules/today/TodayView.vue` | `lastImport: string` → `receipt: AutoImportResult \| null`；渲成回执卡（状态+标题 / 判据明细 / 落点 / 下一步按钮，可关闭）；订单导入后点亮「待拣」卡 |

三条设计约束（都不是随手定的）：

- **卡片内部顺序 = 结论在前、证据垫底**。`landed` + `next` 排在最前，判据（`message`）压成最后一条带分隔线的灰字脚注。
  判据那段信息量最大但也最长，夹在标题与落点之间时，会把"数据去哪了 / 下一步点哪"**挤到下面去** ——
  而这两句才是用户要的（真截图里一眼就看出来了）。

- **落点只给"人话名 + 用户点得到的页面名"**，不给物理表名 —— `oi_orders` 是开发者视角，
  用户可见处出现表名是术语泄漏。`views` 里的「拣货」「算钱」与 `tests/uxEntryNames.spec.ts`
  的入口名守卫同口径（写不存在的地方会红）。
- **`next` 的 `moduleId` 必须是真模块**。写错 = 按钮点了没反应**且不报错**（`switchModule` 只派发事件）。
  冒烟里的白名单**从 `modules.config.json` 读**，不抄一份副本 —— 抄了则改配置后断言恒绿。
- **"提示变入口"只改可达性、不改语义**：`message` 里那句"可在「算钱」页一次「归到该店」"
  原来只是个说法；现在未归属店铺时回执第二格按钮就是它。原来那句话**保留在明细里**（没删信息）。

## 踩到的坑（都有实测）

### 1. 等待判据命中**上一条**回执 —— 后续断言全在读旧值

统一导入有两条 message **共享子串**：

- 商品信息表：`没认出这个文件是什么。逐张体检：…这类文件**不用再导入**了…`
- 认不出的文件：`没认出这个文件是什么。逐张体检：…`

冒烟等"junk 那条结论出现"用的是 `flat(el).indexOf('没认出') >= 0` ——
它**在上一条（商品信息表）还挂在界面上时就已经满足**，于是 waitFor 立刻返回，
紧接着的"认不出时不给下一步按钮"断言读着**旧回执**判成了红（那条红是真的在报"read 了错的对象"，
但它长得像"新功能没实现"）。

两层修法（都做了）：

- **根因**：`importExcel` 在**选定文件之后**先 `receipt.value = null` —— 识别/落库期间界面不该还挂着上一条结论
  （用户会把它当成这次的结论）。放"选定之后"而不是"函数开头"，是为了不因"用户取消选文件"而抹掉已有回执。
- **判据**：冒烟的完成信号从整段 message 换成**标题**（`[data-act="import-title"]`）—— 它是唯一的，不会被旧值满足。

> 通用教训：**"结论出现了"这类等待判据，必须钉在只有新结论才具有的特征上**。
> 同类 message 之间的公共子串（尤其模板化的开头语）是隐形陷阱，批量导入、重复导入时最容易撞。

### 2. 改文案 → 先升级断言（不是改文案去迁就实现）

回执从"一行字"拆成四段后，原来那种
`flat(card('import-result')).indexOf('订单报表') >= 0` 的整段 `textContent` 拼串判据就不能再用了：
`textContent` **不给相邻元素插分隔符**，拆元素会把相邻文本粘成 `去「货与成本」维护下一步` 这种串。

做法（顺序不能反）：

1. **先把判据钉到语义锚点上**（`import-title` / `import-detail` / `import-landed` / `import-next`），逐元素断言；
2. **再**动结构。容器 `data-act="import-result"` 与其中 `import-detail` 承载的**原 message 全文**一字未改，
   于是"这次导入完了没"这类既有判据继续成立。

### 3. 引导 ≠ 重复入口

导入后把「待拣」卡点亮（`is-fresh` 边框 + 一行 `刚导入的订单已算进来`），但**不给第二个按钮** ——
动作仍是卡里原来那个「生成待拣清单」。同理，回执卡里的「下一步」按钮与卡片按钮是**同一场景的两个层次**
（临时回执的导览 / 常驻卡片的执行），文案与目标一致，不构成"同一件事两个入口"。

### 4. **断言全绿 ≠ 界面没问题 —— 一定要看一眼真截图**

上面那些断言全部钉在 `data-act` 锚点里的几个词上，于是**两个文案 bug 一个都抓不到**，
是"把冒烟脚本的 `--dump-dom` 换成 `--screenshot`"拍出来才看见的：

- **自相矛盾**：`kind === null` 分支一律用「**没认出**这个文件是什么…」当 message，而「商品信息」表是
  **已经认出来了**的那支 ⇒ 回执卡标题写「商品信息」表、正文写"没认出"。
- **markdown 星号漏进界面**：检测层的体检记录里带着 `**不用再导入**`，界面上**星号按字面渲染**。
  这些字符串是**用户可见文案**，不是文档 —— 写文案时别把 markdown 标记带进去。

> 一般化：**锚点类断言只能保证"这几个词还在"，管不了"读起来对不对"**。
> 改动用户可见文案时，收工前**至少拍一张真图**看一遍（成本：复用假桥冒烟脚本、改两个 token）。
> 顺带还有一条：`--screenshot` 拍到的是**某一帧**，想冻结在中间状态就在 `step('x');` 后插 `return;`。
