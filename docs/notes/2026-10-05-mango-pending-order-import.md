# 芒果店长「待发货订单」导入：判据要具体到子类，主图列探测必须 strict

**结论（四条）**

1. **「芒果店长待发货订单」是订单报表的一个更具体的子类，不是新类型。** 它只比速卖通订单报表多两列：
   「店铺名」与「产品图片链接」（AE 是**按店铺导出**、既没有店铺列也没有图列）。所以它走的是同一条
   `orders` 导入链路，只是判据 `why` 要点名到它 —— 判据是用户在界面上**唯一**能核对"导到哪去了"的线索。
2. **主图列探测必须分两版：自动导入用 strict，界面选列用宽松版。** 宽松版 `detectImageColumn` 认不出
   图列时会**回落第一列**（给人一个可改的默认值）；拿它去拆多产品行，一张**没有图列的报表**
   （速卖通 47 列，第一列是「订单号」）会被当成"有图片列" ⇒ 拆出的行图片全空、并**逐行误标缺图**。
   新增 `detectImageColumnStrict`（不回落）给自动导入专用。
3. **「一行 → 落库字段」要有单一纯函数层**（`src/lib/orderImportRow.ts`）。两个静默口径：
   ① 店铺名必须落 `oi_orders.shop`（报表无该列才留空 → 由「算钱」页「归到该店」）；
   ② 主图 URL 必须 **trim** —— 单产品行的单元格带**尾随换行**（拆行只在 N>1 时切分），带上去下载必失败。
4. **带图导入的幂等键是 `(order_no, image_id)`，所以"下载失败不丢行"必须显式回落免图并计数。**
   若某行下载失败就整行跳过，界面只会少一行而不报错；回落免图（`imageId=null`）后它仍是待发货单。

**取证**

- 真实模板 12 列（`tests/fixtures/mango-pending-orders.xlsx`，用户导出 16 行原样）：
  `店铺名 / 尺寸 / 订单号 / 下单时间 / 产品信息 / 产品数量 / 产品图片链接 / 产品ID / 产品总金额 / 物流费用 / 订单金额 / 收货国家（中文）`；
  多值分隔符实测：图片=换行、产品ID=分号、尺寸=逗号；`产品信息` 是 `【N】…(产品属性:Size:XXXL,Color:1,…)(产品数量:1 piece)` 块。
- 拆行结果：16 行 → **17 行**（只有 1 个 `产品数量=2` 的单被拆开）；拆出的行图片/尺寸/商品ID **逐行对齐**，
  订单级字段（订单号/店铺名/订单金额）原样复制。用例见 `tests/mangoPendingImport.spec.ts`（17 例）。
- 金额：模板的「订单金额」是**无币种前缀**的裸数（`76.75`）→ `parseMoneyCell` 认（前缀为空、`cents=7675`）；
  「产品总金额 / 物流费用」留在 `raw_fields`、不进同一列（`electron/orderMoney.ts` 的列名族本来就不含它们）。
- 判据正则：`looksLikeMangoPendingSheet` = 订单号 ∧ 产品数量 ∧ 产品图片链接（`src/lib/importDetect.ts`）。
- **变异复核 4 组**（各自变红后已复原，`grep MUTANT` 无残留）：strict 回落到第一列 → 2 例红；
  芒果签名恒 `false` → 1 例红；图片 URL 不 trim → 2 例红；店铺恒空 → 1 例红。
- 真接线守卫：`npm run today:ui` 的 `import-mango` 步骤（假桥真点，断言店铺落 place、`orderDownloadImage`
  真被调用且 url 正确、`imageId` 非 null、结论含「主图 1 张」且不含「归到该店」）。

**不要重复踩的**

- 别把「店铺名」当作"报表没有店铺列"的默认回落（`detectShopColumn` 无命中就该返回空串）——
  店铺是自由文本，猜错一次就是把两家店的账并到一起。
- 带图导入会让导入变慢（每行一次下载，走 `order-download-image` 的 URL/内容指纹复用）。
  重复导入同一份文件不会重复落盘、也不会重复落行（image 命中 → 同 `(order_no, image_id)`）。
- AI 款式识别队列**没有**搬进宿主：那是"识别"不是"导入"，仍在「订单归类」岛（岛是可选加工手段，见
  `2026-09-30-plugin-vs-host-boundary.md`）。
