# P4「成本维护界面」落地：入口放哪、能删什么、口径从哪来（2026-10-09）

对应 CHANGELOG 续十七。路线图 P4（`docs/features/PRODUCT_LIBRARY.md` 进度表最后一格 ⬜）收口。

**结论**：新页签「**进价**」（「货与成本」，两形态都加）。只做**单款**维护（批量已在导入模板里），
写入与导入**共用同一份口径**，删除**只删 `manual`**。

## 一、界面放哪：算钱页 vs 「货与成本」

`ae_cost_map` 的**只读**成本表早就活在算钱页（`CostRatesSection.vue`），所以"就地改成可编辑"是最短的路。
**没有走那条**，判据三条：

1. **P4 的原始定位在产品库**（现「货与成本」），成本是主数据，这一页是主数据的家。
2. **同页动线**：上一轮刚在产品列表加了「进价」列（缺价的款显示「—」）—— 切个页签就能补；
   而算钱页看到"缺成本"之后要去哪补，原来在界面上没有任何答案。
3. **算钱页的定位是"看利润"**。把录入塞进去会让那页同时承担两个视角（诊断 + 维护）。

算钱页的成本表**保留只读**，加一句路标。⚠️ 顺带改正了那里一条**站不住的理由**：

> 旧注释：「成本表只读 —— 手点会让用户在两个地方看到两份成本」。
> 事实：`ae_cost_map` 就**一张表**，不存在"两份"。真正的约束是**入口唯一**（让用户猜哪个入口才是"真的"）。

## 二、删除：只删 `manual`

`purchase` 行是拿货对账**自动同步**的产物（`purchase-cost-sync.ts` 每次落账全量替换那一批）。
允许删它的后果是：用户删掉 → 下次落账原样写回来 → **用户以为"删不掉"，反复试**。

所以 `costMapDeleteManual` 的 SQL 带 `AND source = 'manual'`，界面上 `purchase` 行**不渲染删除按钮**
（渲染一个点了没用的按钮比不渲染更糟）。冒烟两头都钉：删除路径带 `source` 过滤 + 拿货行那条**没有**删除按钮。

**删掉之后会发生什么必须在界面上说出来**：该区间不再生效，读取侧回落到**更早的区间**
（没有更早的就回落到最早那条）。确认框里写了这句话，并且有一条冒烟断言钉住"**回落真的成立**"
（删掉 S1 的手工 12.34 → 当前价变成更早的拿货价 9.99）。不写这句话的话，用户看到的是"价悄悄变了"。

## 三、口径：`pickUnitCost` → 拆出 `pickCostInterval`

界面要显示"**当前生效的是哪条**、来源是手工还是拿货"。这个"挑哪条"的逻辑原先只存在于
`pickUnitCost` 内部（只返回价格），界面若自己按日期再挑一遍，就会漂：

> 成本页写着「当前价 12.34（手工）」，而算钱 / 拣货算的是 10.00（拿货对账）—— 不报错、不抛异常，
> 只是两个数字对不上，而且没人知道哪个是对的。

所以把挑法提成 `pickCostInterval(costs, styleCode, bizDate): CostInterval | null`，
`pickUnitCost` 改成 `pickCostInterval(...)?.unitPrice ?? null`。**排序 + 回落两条规则只有一份**。

## 四、写入口径：从 `product-cost-sync.ts` 提到 `manual-costs.ts`

上一轮（续十六）把导入口径写在 `product-cost-sync.ts`。本轮界面也要写同一批 `manual` 行，
两个调用方各自实现"值相同就不写"必然漂开，于是把函数提到 `electron/manual-costs.ts`
（文件头写明两个调用方），**`product-cost-sync.ts` 删除** —— 它移走核心逻辑后只剩一层转调，
那是没有实质的薄壳（本仓明确不留）。

## 五、⭐ 本轮踩的两个坑（都是本仓记过的老坑新犯）

1. **注入脚本的注释里不能有反引号**。`goods-ui-smoke.mjs` 的断言脚本是一个模板字面量，
   我在注释里写了 `` `__smokeEmptyProducts` `` ⇒ 模板串被**提前终止** ⇒ `node --check` 直接报
   `Unexpected identifier`（而这个脚本的 npm script 恰好带 `node --check`，所以是"跑之前就红"）。
   本仓笔记里已记过 5 次，这次是第 6 次。
2. **toggle 型展开被点了两次 → 收起**。删除前的步骤我又点了一次行首的展开箭头，而那一行**从上面起就是
   展开状态** ⇒ 第二次点击把它收起来 ⇒ 下一步 `document.querySelector('[data-cost-detail="S1"]')`
   返回 `null` ⇒ 报错信息只有 `Cannot read properties of null (reading 'click')`，指向的是**下一步**，
   与真因（上面那次多余点击）隔了一步。修法：删掉那次点击，并在注释里写明"不要再点"。

另有一条**假绿**的当次经历值得记：`goods:ui` 只失败了**第一遍**（宽视口），后两遍 ALL PASS ——
根因是 `load()` 里 `loadCosts` 与 `loadProducts` 分开 await：成本表先渲染出来、缺价清单的数据还在路上，
而冒烟的 settle 等的是成本表。修法不是"等信号"，而是让**成本表渲染出来本身就意味着两件事都完成**
（`Promise.all` + 表 `v-if="!loading"`）。这与 2026-10-08 那条"等信号 ≠ 判信号"是同一类。
