# 产品导入模板改列（去类目 + 图片/颜色/尺码/克重）——2026-10-09

对应 CHANGELOG 续十二。用户原话：「导入产品的 Excel 模板需要增加图片地址字段，去除类目字段，还需要增加 SKU 和克重」。
本文只记**决策与踩坑**，逐条验收见 CHANGELOG 与 `PROJECT_BASELINE`。

## 一、需求的真实形状是三轮问答问出来的

用户第一句要的是「图片地址 + 去类目 + SKU + 克重」四个字段，但**行粒度没说**。这轮最重要的教训：
**克重在库里是 SKU 级属性（`pl_variants.weight_g`），加它就等于改导入的行粒度** —— 一行一款则一个克重格对应不了多规格。最后落的是：

- 一行一个款；「颜色」一格一个；「尺码 / 克重」可多值**按顺序一一对应**（个数不等 → error）。
- 中途用户提出 JSON 方案（SKU 格填 `[{"color":"红",...}]`），评估后**放弃**：Excel 里手写 JSON（中文引号、转义）比三列顺序对应更容易错，且错误更难看懂。

## 二、「图片地址」列的最终形态：图给人看，路径给机器读

- Excel **没有**"图片作为单元格内容"的存储格式（Excel 365 的 `=IMAGE()` WPS/旧版不认）。嵌进 xlsx 的图是**浮动对象**，读不回来（按锚点猜行会在用户插行时静默错位）。
- 所以「图片」列是**双通道**：导出嵌真图（人看）+ 文本列填**本机缓存路径**（机器读，同机往返离线可用）；导入只认嵌入图按锚点行归位（防错位：非数据行 / 一行多图 / 读不到，逐条 warning）。文本地址**明确不认**（warning 说明）。
- 落盘复用 `pl_images`（SHA-256 去重）+ `pl_products.image_id`，零新表零新列。

## 三、⭐ 本轮最大的坑：两条路径、两套字段名，校验器只认了一套

导入是两遍模型：**解析**（`parseProductRows`，SKU 错误记进 `cellErrors`）→ 预览 → **提交**（界面回传行结果，同一些错误在行结果上叫 `skuErrors`）。`validateImportRows` 两遍都用，但只认 `cellErrors` ⇒ **提交时预览标了「跳过」的行带着空 SKU 照样落库**（IMP-3 实测进了 items）。

教训的一般化：**同一个校验器被两条路径共用时，"同一种错误"在两条路径上的字段名必须一起认** —— 否则预览的合格性和提交的合格性是两套口径，而冒烟只在预览那半断言（"第 4 行标成跳过"是绿的），提交那半没人看。变异复核时两条守卫（单测 + 冒烟 items 断言）都红，才算闭环。

顺带：单测要选**只有提交路径才有的形状**（只给 `skuErrors`、不给 `cellErrors`），否则解析路径的兜底会让用例恒绿 —— 又是"互为兜底的两条路径只断言结果会蒙对"那一类假守卫（老坑新犯）。

## 四、夹具语义要跟实现一起改

冒烟夹具原先把嵌入图**刻意**给不合格行（验"图不改变合格性"）。提交 bug 修好后，那一行被剔除 ⇒ 主图数归 0 ⇒ "结果页报主图数"断言反而红了。这不是实现错，是**夹具没跟上新语义**。改成两张图两种命运：第 2 行（合格 → 成主图）+ 第 4 行（不合格 → 图跟行走），一次覆盖两件事。

同类：导出克重断言写 `320,`（夹具初值），但冒烟前文的 save 步已把黑 M 改成 275 ⇒ 导出读的是**库的当下值**，期望值必须跟着流程走（`320,275`）——断言期望值要问"**此刻**库里的真实状态是什么"，不是"夹具最初写的什么"。

## 五、预览默认"只看有问题的行"是设计，不是丢行

预览表默认只渲染问题行（有问题行存在时）。冒烟要通读所有行，先点 `only-problems` 开关切回「全部」再断言（判定开关态用 `aria-pressed`）。曾把"只渲染出 1 行"误判成渲染 bug，量了几何才看清是 onlyProblems 在起作用 —— **先查状态分流，再怀疑渲染**。

## 六、其他工程点

- **exceljs 探针先行**：读回嵌入图前先写一次性脚本验证 `wb.getImage(id).buffer` 的真实形状（`ArrayBuffer` vs `Buffer`），别照类型定义写。
- **导出改主进程生成**（渲染层 SheetJS 写不了 `xl/drawings`）：渲染层算"每格写什么"（纯函数有单测），主进程只写格子 + 嵌图 —— 表头/行口径仍然只有一份。
- **冒烟脚本自身假绿**：新写的 xlsx 冒烟把 `check(asyncFn)` 挂在顶层没 await，进程在用例跑完前退出打出"✅ 全部通过"。修法 = 全部用例包进 `async main()` 逐个 await，收尾在 `finally` 里报真实成败。
- 本轮新增 `scripts/goods-shot.mjs`（`npm run goods:shot`）：把「货与成本」页按指定状态渲染出来落 PNG（复用 goods-ui-smoke 的假桥，按"模板串内无反引号"的仓规安全抽取）——布局类问题的判据是人眼，`--dump-dom` 回答不了"看着是不是坏的"。
