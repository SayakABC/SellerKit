# 「拿货 › 要拿什么」整页重做成卡片网格 + 「复制给厂家」（2026-10-10）

用户给出设计稿（「拿货工作台」卡片网格）并选定「**整页重做卡片网格**」。四块一起落：

1. **顶部厂家筛选标签**（数 = 待拿款色数；只给有货要拿的厂家占位；「未指定厂家」是独立一档
   `data-supplier="0"` ——它的货要能看到，但不该混进别家的筛选里；一个可筛的都没有时整行不渲染）。
2. **卡片网格**（`pk-grid`）：一张卡 = **一个款色** = 图（缺图画「缺图」占位）+ 厂家胶囊 +
   尺码角标条（`L×2` = 这一码**还要拿** 2 件、`L✓` = 已拿完；tooltip 保留「需求 / 已拿 / 还差」）
   + 四态标签（**已忽略 > 已拿完 > 缺哪一环 > 齐**，"已拿完"与"齐"分开说）+ 款名 + 卡面小计
   （`≈¥20.00` / 全无价 `—`）+ 单价（裸数字，后缀「元/件」挂在 `data-act` 外面）+ 行尾「忽略」。
3. **底部汇总条**（`pk-sum`，**吸底**）：一行一个厂家 = 「这家什么情况 + 复制发哪家 + 一键开单」；
   总账一行给「待拿 N 款色 · N 件 · 预估 X」。
4. **「复制给厂家」**：把**这一家**的待拿货画成一张 PNG 写进**系统图片剪贴板**（粘到微信直接发）。

## 判据（改这块之前先读）

- **网格是平铺的 ⇒ 排序必须全网格做**。卡序 = 还要拿 → 已拿完 → 已忽略（同档内维持
  段序 + 件数降序）。本轮真踩：排序写在**段内**（收集时每段各排一遍），被段序盖过 ——
  厂A 整段被忽略后，那张调暗的卡仍排在未指定厂家的待拿卡**前面**（`picking:ui` 一条断言当场红）。
  `Array.sort` 稳定，收集完再排一次即可。
- **汇总条必须吸底（sticky）而不是随列表滚**：卡片一多它会被顶到几十屏之外，而「生成拿货单」
  是这条链的下一步动作，**找不到就等于没有**。
- **「复制给厂家」是图不是文本**：厂家照图备货；纯文本粘进微信丢表格结构，截屏又会把页签、
  别家的货一起发出去。`src/lib/pickingSheet.ts` 的 `sheetModelOf`（走 `pendingOf`）+ `renderSheetPng`
  （canvas 2×）⇒ **屏上 / 发出去的 PNG / 导出 xlsx 是同一个数**（`money`/`amountText`/`noPriceNote`
  三个措辞函数三方共用）。
- **`write-clipboard-image` 是渲染层→主进程的图片通道**：主进程只做两件校验（dataUrl 前缀
  `data:image/` + 8MB 上限）再 `nativeImage.createFromDataURL` + `clipboard.writeImage`。
  ⚠️ **当轮真机实测即失败**：v44 已移除 `clipboard.writeImage`（这条写的 v33 时代 API），正确写法
  是 `clipboard.write([ClipboardItem + Blob])`，两条通道也已外提到 `electron/clipboard-handlers.ts`
  —— 详见 `docs/notes/2026-10-10-electron44-clipboard-writeimage.md`。
  ⚠️ 主进程/preload 改动要**重启宿主**才生效（HMR 不覆盖）。
- **两种宿主共用这一块**：独立「拣货」页与「今天 › 拿货」同一个 `PickingView`（embedded），
  忽略链接 / 开单按钮由 `rowAction` / `supplierAction` 决定渲染（独立页不渲染开单按钮 ——
  那是「拿货」页的动作）。

## 实测纪律

- ⚠️ **注入脚本（FAKE_BRIDGE / ASSERT_SCRIPT）注释里的反引号又踩一次**：`node --check` 报的是
  文件中部 `Unexpected identifier 'lib'`（离真因就是那句注释），排除方向容易被带偏。改完先
  `node --check`（`npm run picking:ui` 的 npm script 已带）；写注释时用 `lib/pickingSheet`
  这种不带反引号的写法。
- **写剪贴板的假桥只能验"发出去的是什么"**（真写剪贴板在主进程）：断言载荷是
  `data:image/png;base64,` 前缀还不够 —— 补一条**非空转**判据 `new Image()` 解码
  `naturalWidth > 0`（画布不可用/空壳 dataUrl 会当场红）；失败分支 `__clipFail` 反向夹具，
  断言 toast 如实报「复制失败」（不装作已复制 —— 否则用户粘出的是上一张图）。
- **一张卡的两个判据钉同一格**：尺码格的文本（`L×2`）与 tooltip（三个数）必须同一个
  `size-chip` 上取 —— 分开取或整卡拼串时"串位"不会红。
- **反向夹具 `__allTaken`**：已拿完的第四态要整条翻（卡调暗 `is-done` + 不再报金额 +
  该厂家标签消失 + 汇总行说「已拿齐」）—— 只翻一处就是两套口径。
- `*:ui` 读 `dist/` ⇒ 先 `npm run build`；做完变异必须 rebuild 再跑最终门禁。
