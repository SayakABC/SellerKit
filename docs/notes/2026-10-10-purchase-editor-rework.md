## 结论 1：布局类问题先截图取证 —— 「别扭」的真身是列被裁 + 按钮不可见

新增 `npm run purchase:shot`（`scripts/purchase-shot.mjs`）：从 `today-ui-smoke.mjs` 安全抽取假桥（唯一真源）
+ HTTP + headless Chrome **CDP** 截图（`Page.captureScreenshot`），`PROBE=1` 时附几何。
改前 PROBE 实测：抽屉 560px / 内容区 527px / 表格 `scrollWidth` 658px ⇒ **横向溢出 131px**；
「金额(元)」列头被裁半个字；行尾操作列 **x=1475 > 1440 视窗** —— 「取最近价 / 删」在屏幕上
**根本不存在**（点不到、也没有任何报错）。

⚠️ 这条问题**此前的断言面完全覆盖不到**：`--dump-dom` / 存在性断言回答不了"看着坏没坏"——
DOM 里 8 列都在、表头列集合断言全绿，而其中一列与操作列在屏幕上不可达。**布局的判据是人眼
+ 几何，不是 DOM 结构。**

## 结论 2：修法 = 使宽度成为可算的预算（620px 抽屉 + fixed 布局 + colgroup）

- 抽屉 560 → 620px ⇒ 内容区 = 620 − 1（左边框）− 32（body padding）= **587px**；
- 表格 `table-layout: fixed` + `<colgroup>`：图片 48 / **款色 = 不给宽度（吃剩余）** / 尺码 54 /
  建议 40 / 实拿 60 / 单价 80 / 金额 76 / 操作 60 ⇒ 固定列合计 418，款色得 169（内置 code 92 +
  color 58，`min-width` 允许窄屏继续压缩）。
- ⚠️ **`table-layout: fixed` 把"放不下"从『横溢出』变成『压窄 auto 列』**：溢出断言对"抽屉变窄"
  这类回归**不敏感**（变异实测：去 fixed 才红），它挡的是**去掉 fixed / 加宽固定列 / 加列**。
  这是有意的取舍——宁可窄屏压窄款色列，也不要整表横滚把右侧列推出视野。

## 结论 3：守卫必须「几何 + 可达性」两条（本轮为既有盲区补的）

- ①「明细表不横向溢出」：`wrap.scrollWidth <= wrap.clientWidth + 1`；
- ②「行尾两个按钮在视口内且可被点中」：`getBoundingClientRect` 四边都在 `window` 内
  **且** `document.elementFromPoint(中心)` 命中按钮或其子节点（按钮里是子节点（SVG 或文字）⇒
  用 `contains` 判 —— 反馈轮把 SVG 换成文字后这条判据**自动继续成立**）。
- **两条都做过变异确认**：去掉 `table-layout: fixed` ⇒ ①红（590/587）；加 `min-width: 700px`
  ⇒ ①②全红（诊断给出行尾按钮坐标 791 / 815 vs 视口 800）。⚠️ 第一次变异只命中 ①——
  溢出仅 3px 时按钮仍在视口内，**断言要吃够故障幅度**才两条都红。

## 结论 4：`data-act` 契约第六轮兑现 —— 改版可以零断言债

所有 `data-act` 名一个没动 + 表头 8 格文字逐字保留（含第 8 个空 `th`）⇒ 既有 **181 条**断言
**原样重挂**，本轮只 +2（新增的两条守卫）。冒烟里对编辑器的一切操作（`pue-fill-1` / `pue-delrow-1`
直接 `.click()`、表头 `join('|')` 全等）都无需改一字。

## 其它设计决定（都写进组件注释，此处只留判据）

- **行尾两个文字链接是表格宽度的最大贡献者**（80px 列里竖排挤成三行、行高被顶到 77px）⇒
  改 **SVG 图标按钮**（↻ 取最近价 / ✕ 删本行）：不赌字体字形渲染（`↻` 字符在无头渲染有豆腐块风险），
  `title` + `aria-label` 兜底语义与可发现性。
  ⚠️ **本决定同日被用户反馈推翻**（图标说不出含义）—— 已改回文字动作，见文末「同日反馈修正」。
- **两行并一行**：日期（原 `label` 两行）+ 提示句（原单独一行、含「共 N 行」）合成一行工具条；
  「共 N 行」移到页脚与合计并列（**包价单不加** —— 它没有"行"的概念，写「共 0 行」是错的）。
- **行内 padding 9 → 5px**（行高 77 → ≈58px）；行 hover 高亮**连同首格一起换色**（首格是 sticky
  列自带底色，不跟着换会在横滚时断层）。
- 款色格去掉「·」分隔符，改 `placeholder`（款编码 / 颜色）——空行的字段名从无语义的分隔符变成认得出的提示。

## 同日反馈修正（用户实报两处，都已改）

用户：「拿货单中的款色和尺码为什么要用输入框的样式？现在操作区的两个按钮完全不知道是什么意思。」

### 结论 5：身份数据去「输入框样」= 幽灵输入框（默认像文字 / 悬浮出框 / 聚焦还原）

- **判据是"这格是谁在说话"**：款编码 / 颜色 / 尺码是清单带过来的**身份数据**（人只偶尔修正），
  每格都画边框会让整行被读成"这里有三个框等我填"；实拿 / 单价才是"等你填"的字段。
- 实现 `.pue__ghost`：默认 `border-color / background-color: transparent`；`:hover` 出一条
  `--wb-border`（提示"可点"）；`:focus` 还原完整输入框（`--wb-focus` 边框 + 3px 焦点环 +
  `--wb-surface-2` 浅底）。
- ⚠️ **用 `:focus` 而不是 `:focus-visible`**：基座 `.wb-input` 用 `:focus-visible` 只为键盘焦点环；
  ghost 常态完全像纯文字，**鼠标点进去若不还原外观就没有"我在编辑"的反馈**。键盘用户走 Tab
  同样命中 `:focus`，无需两套。
- **改的是外观不是能力**：手工加行、现场改色仍要能输入 —— 没有任何编辑能力被撤。

### 结论 6：图标按钮改回文字动作 —— 应用惯例是 `.wb-link`

- 上文「其它设计决定」里"改 SVG 图标按钮"一条**已被本反馈推翻**：用户"完全不知道是什么意思"
  （图标语义不自明，`title` 要悬停才可见）。⇒ 改回**文字**：「取最近价」「删除」，用
  `.wb-link` / `.wb-link--danger`（与「拿了什么」列表的行尾动作同一套惯例）。
- 宽度预算重算：66px = 「取最近价」12px 文字（≈56px）+ 链接内边距 + 单元格 4px 内边距
  （60px 会把"取最近价"挤断成两行）。⚠️ **覆盖 td padding 的特异性坑**：`.pue__table td`
  （0-1-1）压过裸 `.pue__ops`（0-1-0）⇒ 必须写 `.pue__table .pue__ops`（0-2-0）。
- 结论 3 的两条几何 / 可达性守卫**自动重挂**：判据里用 `contains` 判"按钮或其子节点"，子节点
  是文字还是 SVG 都吃不倒 —— 这正是当初用 `contains` 而非 `===` 的回报。

### 结论 7：模板字符串转义陷阱本轮两连踩（诊断全对、断言恒红）

`today-ui-smoke.mjs` 的浏览器侧代码整段嵌在模板串里 ⇒ **正则与注释都是字符串内容**：

1. 新守卫里用正则比颜色（`/rgba\(0, 0, 0, 0\)|transparent/`）：`\(` 在模板串里被剥成 `(` ⇒
   正则实际去找字面量「rgba0, 0, 0, 0」⇒ **恒不命中**。症状极像"实现坏了"：诊断串里
   `code=rgba(0, 0, 0, 0)` 明明是对的。**修法：不用正则，改字符串相等**。
2. 为解释 ① 写的注释里又出现 `\(` ⇒ ESLint `no-useless-escape` **error**（注释在模板串里
   按字符串内容判转义）。**修法：注释里不写反斜杠。**
- 这是本仓「模板串内转义」族的又一次现形（同族既有事故：注入脚本注释/断言里的反引号 ——
  `2026-10-10-purchase-card-grid.md` · `2026-10-08-goods-ux-refactor-closing-batch.md`）。
  **在该脚本里写正则 / 注释前先问一句：这段文本自己带着转义吗？**
