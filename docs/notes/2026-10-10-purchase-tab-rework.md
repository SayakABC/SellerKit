# 「拿货」页重设计：元素太多先换聚合层，而不是删信息（2026-10-10）

用户原话：「拿货 tab 界面一条一条的实在太多了，元素很多，嵌套也很多，你重新设计一下页面，使界面
简洁直观，操作便捷，始终要记得初衷」。初衷 = 这条链：**要拿什么（图角标 + 价）→ 按此生成拿货单 →
拿了什么 → 录付了多少钱 → 对账**。

**结论**：病根不在"元素多"，在**行粒度太细 + 数字和动作离开了它们描述的对象**。四条判据：

1. **换聚合层，不是删信息**。清单原按 款 × 色 × 码 一行（黑 L 一行、黑 M 又一行）⇒ 同一款色的
   图、款名、进价逐行重复，10 列的表大半是重复。行粒度折叠到 **款色**（行键 `S1 · 黑`），
   尺码并排成 chips（`L×2` = 这一码**还要拿** 2 件、`L✓` = 已拿完；tooltip 保留
   「需求 3 · 已拿 1 · 还差 2」三个数）⇒ 表收成 6 列。**展示粒度与出货粒度可以不同**：
   发给厂家的 xlsx 仍按码把角标烧进图（与 `badgeOf` 同源，不是一个数两套算法）。
2. **数字就地给，不抽到顶栏**。"指标条 + 分段徽章"是同一批数字的第三份拷贝；撤掉后：清单条给
   「待拿 N 款色 · N 件 · 预估 ¥」（与段尾按钮同一个 `pendingRollup`）、「拿了什么」面板头给
   「N 张 · N 张草稿待提交 · 已提交 ¥」。**数字住在它所描述的对象旁边**，不用上下对照。
3. **动作钉在起作用域上**。一张拿货单只能挂一个厂家，数据里已按厂家分好段 ⇒ 开单按钮钉**段尾**
   （`pk-create-order` + `data-supplier`）；页级"先选厂家 + 按此生成拿货单（N）"整个撤掉 ——
   那一步对用户是白问的。剩下的厂家下拉只服务「新建空白单」，且没选厂家时两个新建都禁用。
4. **把"下一步"自动做掉**。开单只是中点，"填单价"才是目的 ⇒ 生成草稿后自动切「拿了什么」并
   **直接打开这张单的编辑器**（合计 0.00 等填）；toast 说「已生成拿货单 #N（草稿）—— 填好单价再提交」。

## 三条实测纪律

- **改 toast 文案要 grep 按文案取的断言**：toast 从「…去「拿货单」填单价」改成「…填好单价再提交」后，
  `toastHas('填单价')` 不再成立 —— `today:ui` 当场红一条。文案是断言输入的一部分。
- **假桥必须"记住"新建的单**：`createFromPick` 之后立刻 `purchaseOrderGet(新 id)` 开编辑器 ——
  夹具不持久化就当场报「拿货单不存在」（补 `CREATED_ORDERS` + `allOrders()` 才成立）。
- **同一格的两个判据钉在同一个元素**：chip 的文本 `L×2` 与 tooltip 都在同一个 `size-chip` 上取 ——
  分开取（或整行拼串）时"列串位"不会红。
