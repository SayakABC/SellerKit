# 「发货台」命名 + 每日口径（导入日过滤）+ 回执结论卡 + 归类动作计数（2026-10-11）

> 缘起：用户对「今天」这条主线的四问（导完记录不知道去哪 / 核对完订单不知道在哪 /
> 是不是只该看今天导入的 / 是否改名「今日拣货台」）。方案与执行流水见
> `docs/plans/DAILY_SHIPPING_FLOW_PLAN.md` §6 S9；这里只留"下次开工还得记得"的结论。

## 0. 一句话

**名称 = 发货台**（只改显示名、id 不动）· **口径 = 1–3 步按「今天导入」、4–5 步按「未结清」** ·
回执**拆两层**（大字结论 + 折叠判据）· 归类页补**「待核对 X · 已核对 Y」**与**空态三出口**。

## 1. 改名：显示名 ≠ 模块 id

- 只改 `today/meta.ts` 的 `name`（+ `TodayView` 页头 `<h1>`）；**模块 id 仍是 `today`**。
  改 id 会断 `knownModules` / 深链 / 市场 id，而"给用户看的那个名字"只有 `name` 一处。
- 连带要扫的是**注释里的指路**：「今天 › 拿货」这类写法在 4 处注释 + 2 处测试注释里，
  `tests/uxEntryNames.spec.ts` 的悬空入口名守卫会拦写错的指路（但它**扫前会 stripComments**，
  所以只改文档不同步改注释，守卫是看不见的 —— 得手工 `grep -E` 一遍）。

## 2. 每日口径：按 `created_at`（导入日）而不是 `order_time`（下单日）

- 工作流是"每天早上导**前一天 → 导出时点**的全部订单"，中途追加的也算同一天要拿的货。
  ⇒ 筛的键是**导入时间** `date(created_at)`（`created_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))`），
  **不是** `order_time`：昨天下的单今天导，就该落在今天这批里。
- 落地四处同改（本仓 IPC 契约的标准姿势）：`electron/order-db.ts`（`shippingRows` + `listOrdersPage`）
  → `electron/order-handlers.ts`（`sanitizeImportDate` 形状兜底，只放行 `yyyy-mm-dd`）
  → `electron/preload.ts` → `src/types.ts` + `src/core/services/ipc.ts`。
- ⚠️ **契约是四处、不是三处**：只改 `IpcApi` 接口、漏改 `ipc.ts` 顶层的 `export function orderShippingRows(payload?: {...})`
  包装签名 ⇒ `vue-tsc` 报"属性不存在"。本轮实踩一次。
- 消费方口径分工：**1–3 步（导入 / 归类 / 算钱）按导入日筛；4–5 步（拿货 / 对账）不动** ——
  它们走"未结清 / 未发货近 30 天"，天然可跨天结转。这就是用户拍板的"跨天结转"。

## 3. 同一份视图、两个入口两种口径

- 「算钱」`OrderCostView` 加了**可选** `importDate` prop：内嵌在发货台（`CostPanel`）时传**今天**；
  独立模块入口不传 = **全库**（= 改造前行为，不动）。
- 页面上必须**写明作用域**：加了 `data-act="oc-scope"` 的「今天导入」药丸；总览的订单卡同样加
  `data-act="orders-scope"`。理由：**同一页里两个数不一样时，用户没法判断谁对** —— 标签就是这个数字的作用域。
  ⚠️ 只在**有数字时**出现（空态那句自己已交代范围，再挂一个标签是重复）。
- ⚠️ 「今天」在**结算对账的时间窗分段控件**里是**日期语义**（`{ id: 'day', label: '今天' }`），
  不是模块名 —— 全仓搜「今天」改名时**别一起改**。同理 `electron/*.ts` 里的「今天」都是日期语义。

## 4. 回执拆两层（`headline` / `message` / `warnings`）

用户原话是「反馈信息模糊、文字太多、完全看不懂」，而原来 `message` 一坨里塞了**结论 + 判据**：

| 层 | 字段 | 界面 | 判据 |
| --- | --- | --- | --- |
| 结论 | `headline` | 17px 大字，独立一行 | 扫一眼就知道"成了没有、成了多少" |
| 判据 | `message` | **默认折叠**在 `<details>`（「怎么看出来的」） | 排查用；不该占日常阅读路径 |
| 异常 | `warnings[]` | **平铺不折叠** | 用户**要采取行动**的事（跳过几行 / 主图没下来）；空数组 ⇒ 一个字都不写（不写"无异常"，那种话不携带信息） |

- 「下一步」的 `ImportNextStep` 加了可选 `tab`（与 `moduleId` 二选一）：**目标在本页页签就写 `tab`**
  （就地切页签，`go()`），真跳别的模块才写 `moduleId`（`openModule()`）。写错 = 点了没反应且**界面看不出异常**，
  所以冒烟里 `checkNextTargets()` 会把按钮 id 拿去与**现读的** `KNOWN_TABS`（正则从 `flowCtx.ts` 抓）∪
  `KNOWN_MODULES`（读 `modules.config.json`）比对 —— 清单**抄副本**的话将来改配置这断言会恒绿。
- 主次按场景分叉，**两支都要测**：店铺**未归属**（报表没店铺列）⇒ 次操作「去『算钱』归店铺」(`cost`)；
  **已归属** ⇒ 次操作「去看要拿什么」(`purchase`)。主操作两场都是「去核对这些行」(`classify`) ——
  这条是修**自相矛盾**：流程卡上"第 2 步才是当前步"，而回执原先把人直接送到第 4 步拿货。

## 5. 归类页：动作计数 + 空态三出口

- 页头「**待核对 X · 已核对 Y**」（`data-act="cl-counts"`）。它不是被撤掉的"指标条"复活，
  而是**这一页的动作计数** —— 这页的动作是"逐行核对 → 那行离开列表"，做完一轮用户**看不出自己做了多少**，
  列表一空只剩一句"都核对完了"，无从判断"真核完了"还是"这批本来就没有"。
- ⚠️ 两个数**必须同一个筛**（都按导入日），否则两边之和会大于这批的行数，用户一眼看出对不上。
  `pendingCounts()` 因此是三次 `orderList` 的 `Promise.all`（`corrected:false` / `corrected:true` / 不带 ⇒ 用来数 unclassified）。
- 空态按**原因**分三支（提示不是入口 —— 说明里的下一步必须**点得到**）：
  · 今天还没导 ⇒ 「去导入订单」(`cl-goto-import`)；
  · 搜不到 ⇒ **不给按钮**（清空搜索框就在旁边，塞个按钮反而多一步）；
  · 这批核对完了 ⇒ 「去算钱」(`cl-goto-cost`) + 「去看要拿什么」(`cl-goto-purchase`)。
- 空态标题是「**今天还没有导入订单**」而不是「还没有订单数据」：只数今天这批时，后者是**假话**
  （库里可能有前几天的单，用户会以为数据丢了 —— 正是本轮要治的病）。

## 6. ⚠️ 通用教训（这轮最值钱的一条）：假桥要连**结构**一起复刻

`scripts/today-ui-smoke.mjs` 的假桥 `orderList`，原先在 `corrected` **未传**时只回"待核对"行；
而真实 `listOrdersPage` 的语义是 **`corrected === undefined` ⇒ 不过滤（全表）**。

后果：我为新功能加的「核对过的行不该出现在待核对表里」这条断言 **恒绿** ——
假桥根本不可能在待核对分支里返回那些行，"列表漏传 `corrected: false`"这个回归永远抓不到。

修法：让假桥照抄真实语义（`undefined` ⇒ 全部；`true`/`false` 才按列筛）。
之后 `listPending` 掉 `corrected: false` 的变异体才真的把这条断言打红。

**推论（可复用到任何假桥）**：夹具只复刻"内容"不够，**被依赖的结构（参数语义、缺省行为、
分页边界、sheet 顺序…）也要一起复刻** —— 否则依赖该结构的错误实现必然恒绿。

## 7. 两个操作层面的坑

- ⚠️ **注入脚本注释里的反引号**：`today-ui-smoke.mjs` 是两个大模板串（`FAKE_BRIDGE` / `ASSERT_SCRIPT`），
  注释里写 `` `createdAt` `` 会把模板串**提前闭合**，而 `node --check` 报的是"文件末尾 brace 不配"，
  很难往这里想。本轮又踩 **4 次**（累计第 3、4 次）。**小批改、每批 `node --check`**，别攒一批再跑。
- ⚠️ 本仓 `grep` 是 macOS BSD 版：`grep "a\|b"` **静默返回"无匹配"**（看起来像"文件里真没有"）。
  一律用 `grep -E` 或 Grep 工具。本轮又据此误判过一次"文件里没有"。
