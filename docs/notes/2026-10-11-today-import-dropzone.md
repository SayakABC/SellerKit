# 「今天 › 导入订单」做成投放区（可点可拖）+ 回执卡精修（2026-10-11）

> 缘起：用户要求"优化设计今天--导入订单页的样式和交互"。上一轮（`2026-10-11-today-pages-design.md`）
> 只做了"删说明段 / 空态改两行预告"的减法，**没解决最核心的交互缺失**：导 Excel 最常见的动作是
> "从资源管理器把文件拖过来"，而这一页全页只有一个按钮，拖进来没有任何反应。
> 变更史见 `CHANGELOG.md` 2026-10-11 段；这里只留"下次开工还得记得"的结论。

## 1. 结论：一个页面只能有**一条**点击路径，但可以有**多个投放方式**

交付形态（`src/modules/today/tabs/ImportPanel.vue`）：

```
[ 投放区 （虚线框，悬浮/拖入变主色实线 + 浅底）    ]   ← data-act="import-drop"
       ↑ 上传图标（悬浮变主色）
   把订单 Excel 拖到这里 / 松手就导入 / 正在识别并入库…
   [ 选择 Excel 文件 ]                              ← data-act="import"（既有断言点它）
   〔订单报表〕〔待发货订单〕〔结算明细〕〔报价单〕   ← 四类可识别文件（原先埋在空态的括号里）
[ 库里现有 42 行订单 | 导入 40 | 采集 2 | 最近下单 2026-10-11 ]  ← data-act="import-stock"
[ 回执卡 ]                                        ← data-act="import-result"，**只在上次导入后出现**
```

⚠️ 上面这份形态是 2026-10-11 **二次收口后**的样子：原先投放区还带一行副标题、下方还挂着一张
"虚线占位卡"（`data-act="import-none"`）—— 两者都已删，理由见下面第 6 节。

- **点击只挂一处**（区块本身），按钮**不另挂 handler** —— 按钮的 click 冒泡上来就够。
  ⚠️ 两个 handler 并存会让一次点击导入两次，而导入**不是幂等**的（同一份报表导两遍 = 订单行翻倍）。
  从结构上只留一条路径，而不是靠"记得写 `stopPropagation`"。
  既有断言点的是 `[data-act="import"]`（按钮）：`element.click()` 冒泡到区块 → 命中同一个 handler。
- **拖放**走 `@dragenter/dragover/dragleave/drop`；`dragenter/dragleave` 在子元素间会反复触发
  ⇒ 用**计数器**判定，"进出子元素"不算离开（否则指针划过图标时高亮会闪）。
- 拖放的字节来源是 `File.arrayBuffer()`（**渲染层**），与对话框选文件的 `ArrayBuffer` **同形** ⇒
  容器里只需要一条 `runImport(src)`：识别 → 落库 → 回执 → `bump`。拖放换的只是"字节从哪来"。

## 2. ⚠️ 重入守卫是必要的，但它会**静默吞掉**并发的拖放

`runImport` 开头 `if (importing.value) return;`。理由：导入非幂等，而投放区"整块可点"、连点两下很容易。
代价：**导入进行中拖进来的文件会被无声忽略**（界面此时显示"正在识别并入库…" + `cursor: progress`，
所以不算"假动作"，但确实什么都没发生）。

**这条守卫在冒烟里制造过一次假红**（值得记，因为它长得像"功能没实现"）：

- 序列：点区块（拉起对话框）→ `waitFor(selectExcel 计数 +1)` → `waitImportIdle()` → 派发 drop。
- `waitFor` 的第一个探针是**同步**跑的，而假桥的 `selectExcel` 也是同步记录 ⇒ 第一条 `waitFor`
  在第一跳就满足；此刻 `importing` **还没置位**（`runImport` 要等 `selectExcelFile()` 的
  promise 落地才走到那一行）⇒ `waitImportIdle` **当场返回**（按钮此刻仍可点）。
- 于是 drop 与上一轮导入**并发**：`runImport` 的守卫把 drop 吞掉 ⇒ `orderInsert+0`，
  回执还停在上一条（junk）的结论上 —— 现象是"拖了没反应"，很容易被读成"投放区没接上"。
- **完成信号不能只看"按钮可点"**：本页用「回执换成认不出的结论 **且** 按钮恢复可点」当整轮结束。
  通用教训：**"某 IPC 被调用"≠"这一轮业务结束"**，等的是业务结论，不是调用记录。

## 3. 合成 drop 事件：用 `new Event` + `defineProperty`，别用 `new DragEvent`

```js
var dt = new DataTransfer(); dt.items.add(new File([bytes.buffer], 'x.xlsx'));
var ev = new Event('drop', { bubbles: true, cancelable: true });
Object.defineProperty(ev, 'dataTransfer', { value: dt });   // ✅ 各版本 Chrome 都稳
zone.dispatchEvent(ev);
```

`new DragEvent('drop', { dataTransfer: dt })` 对 `dataTransfer` 的支持在各版本不一致，
而**这条链上失败会被读成"投放区没实现"**（排查方向直接跑偏）。隔离验证过：`dt.files.length=1`、
handler 拿得到 `File`、`arrayBuffer()` 正常（1.5 KB ~ 16 KB 的 xlsx 都行）。

夹具出口：桥脚本是 IIFE，内部变量外面取不到 ⇒ 桥里补一句
`window.__smokeXlsxB64 = { orders, junk, weights, mango }` 供驱动脚本合成"拖进来的文件"。

## 4. 视觉上真正起作用的三件事（可复用）

1. **虚线框 = "可投放"的通用语义**；悬浮/拖入时**同时**换边框样式（dashed→solid）与颜色 ——
   只改背景色在深色主题下读不出来（与既有 `.td-tab.is-on` 同一条教训）。
2. **长括号里的枚举要拧成标签**：`（订单报表 / 待发货订单 / 结算明细 / 报价单）` 读起来像一句话，
   用户很难确认"我手上这份在不在里面"；四枚 chip 才扫得动。
3. **回执补 0.2s `translateY+opacity` 入场**，`prefers-reduced-motion` 下关掉。
   ~~空态与回执同位置、同尺寸（虚线占位卡 ↔ 实线回执卡）~~ ← **已于同日二次收口撤销**，
   见第 6 节：占位卡本身是一段说明文字，而"状态切换不跳到新地方"这件事，靠回执自己的入场动画就够了。

## 6. 二次收口：**说明文字是在替界面认错**（同日，用户反馈）

> 用户原话："'导入后这里会留下一张回执'这里的区域去掉，尽量少有提示文字，要从交互设计中让用户会用。"

删了三处：

| 删掉的 | 它原本想说的事 | 现在由谁来说 |
| --- | --- | --- |
| 空态占位卡（`data-act="import-none"`） | "导入后会出一张回执" | **回执自己**（导一次就见到，且位置就在投放区正下方） |
| 投放区副标题 "点这块任意位置选文件，也可以直接把文件拖进来" | ① 可点 ② 可拖 | ① 主按钮 + 整块 `cursor: pointer` ② **虚线框 + 上传图标**，拖到上面变实线 + 标题换"松手就导入" |
| 主按钮 "选择 Excel 文件导入" → "选择 Excel 文件" | （"导入"二字） | 这一页就是导入页，不必再说一遍 |

⭐ **可复用的判据：一句话值不值得留，看它有没有"对应的界面事实"。**
- 有事实兜底（虚线框=可投放、按钮=可点、"正在识别并入库…"是**进行中状态**）⇒ 撤掉文字，
  用户第一次拖上去就懂了，而且以后每次都不用再读一遍。
- 没有事实兜底（"导入后这里会留下一张回执"**在任何状态都不对应界面上的任何东西**）⇒ 它只是
  一张自己解释自己的便签，占位置、每次都要读、读完还不一定信。

⚠️ **连带的断言必须一起改，而且要换成"真会坏的东西"**：原判据是"空态文案里有没有 `Excel` / `回执`"
（`flat(guide).indexOf('回执')`）—— 这条断言的作用是**把一段说明文锁进测试**，文案删了就红。
换成：**回执撤掉后页面不留残壳、投放区还在、主按钮没被禁用**。理由：空态少一句话不影响任何人，
**入口没了才是致命的**（"关回执顺手把入口也禁了"这种 bug 原来根本测不出来）。

⚠️ 同一轮补了一条**非空转**的交互守卫（因为文字撤掉后，拖入反馈成了**唯一**的引导）：
拖 `dragenter` → 断言**计算样式** `border-style: dashed → solid` 且标题变成"松手就导入"，
`dragleave` 后**复原**。为什么要读计算样式而不读 `is-over` 这个 class：class 挂上了但样式被覆盖
（选择器写错）时用户照样看不见，只查 class 会恒绿。实测 `idle=dashed over=solid back=dashed`。
