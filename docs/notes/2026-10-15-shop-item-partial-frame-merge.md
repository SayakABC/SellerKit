# 采集帧「全字段覆盖」把另一层级采到的字段静默清空 —— 两半字段的两个写入者必须「只覆盖非空」

2026-10-15 · 修复 + DB 冒烟守卫

## 结论

`pl_shop_items` 的行由**两个采集层级**写入，各带**一半字段**：

| 帧来源 | 带的字段 | 不带 |
| --- | --- | --- |
| 列表轻采（本页 / 本店全部 / 店铺主页） | itemId / title / imageUrl / priceText / category / status / url | skus（`[]`） |
| 详情重采（「采 SKU」） | itemId / skus | 其余全部 |

而 `upsertShopItems` 旧实现 = **全字段覆盖** ⇒ 后跑的那次把另一次采到的字段**静默清空**，
两个方向都可达：

- 「采 SKU」成功后：标题 / 图 / 价 / 状态 / URL 被清空（详情帧里没有它们）；
- 全店重采后：SKU 矩阵被清空（列表帧 `skus: []`）。

回执照报 inserted/updated 成功；界面上表现为"那个字段没采到"，实际是**被覆盖没了**。
（同族前例：店铺编辑"漏传字段 = 静默清空" —— 同一实体多个写入者 + 全量提交。）

## 修法（只覆盖非空）

`upsertShopItems` 对已存在行先查旧行，**空值不覆盖**：

- 空值语义 = 「**这次没采到**」，不是「平台上这个字段没了」（后者不存在这种事件）；
- 非空新值**照常覆盖** —— 是"空值不覆盖"，不是"一律不覆盖"；
- SKU 按"**有没有行**"判（`skus.length ? 新 : 旧`），不是按字符串非空。

## 守卫（DB 冒烟 3 例，前两例在旧代码上逐条打红）

`npm run shop-item:smoke`：

1. 详情帧（只有 SKU）不清空列表帧的标题 / 图 / 价，且 SKU 真写进去；
2. 列表重采（帧里 SKU 为空）不清空 SKU 矩阵，且标题非空照常覆盖；
3. 详情帧带**新** SKU ⇒ 覆盖旧矩阵 —— 防"有值就跳过"的坏修法（该例在旧代码上也是绿的，
   它守的不是旧缺陷而是**新实现**不许退化成"一律不覆盖"）。

夹具用**生产形状**的两种帧（`frame({name:'层级店'}, [{itemId, skus:[{props:'Color:Black;Size:L', price:'US $1.20'}]}])`），
不是手工拼"合理形状"。

## 为什么之前没人发现

- 「采 SKU」在此前从未成功采过（真库 8 行 `sku_json` 全 `[]`）⇒ 方向①没有机会触发；
- 方向②（全店重采清 SKU）要"先采过 SKU、再重采整页"才现形，用例与流程都没走到；
- 两个方向都**不报错**（回执是成功），只能从"字段变空"反推。
