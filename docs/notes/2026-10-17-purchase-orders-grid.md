# 「拿货 › 拿了什么」重做成拿货单宫格，并修掉同形态的静默压扁（2026-10-17）

用户口径：「将发货台-拿货页面重新设计，修改成宫格样式」。
「拿货」页签两半里，「要拿什么」2026-10-10 就是卡片网格了；本轮改的是**「拿了什么」的拿货单列表**
（六列表格 → 一张卡 = 一张单）。判「这页哪里不是宫格」的办法：逐段看哪个容器还是 `wb-table`。

  2026-10-10 编辑器行尾两条（↻ / ✕ "完全不知道是什么意思"）的教训直接继承。

## ⭐ 立身之本：修掉"静默压扁"（与 `pk-sum` 2026-10-10 同一根因）

**取证**（探针量几何，不是看图）：`--dump-dom` 无头 Chrome 的默认视口是 **756×469**
（侧栏 208）⇒ 拿货面板可用宽度只剩 ~466。改宫格前先量了一遍，两个数当场不对：

1. `.wb-panel` 的 `overflow:hidden` 把**弹性列里的自动最小尺寸**（min-height:auto）归零
   ⇒ `.pu-view`（定高 `height:100%` 的弹性列）内容一超高就把面板压成一条 **37px 的缝**：
   卡面四段内容全裁在缝里（DOM 还在、`elementFromPoint` 点不到）。按钮实测坐标
   `(274,518)` —— 在 469 高的视口外。**旧的表格为什么没暴露**：表格是块级盒，
   被压扁的只是body 滚动口，表本身保持自然高度、在 37px 缝里可滚；宫格的容器自己就是
   `flex:1` 的弹性项（`min-height:0`），整块连内容一起被压。
2. 442px 的可用内容宽下 `minmax(224px,1fr)` **只能排一列** ⇒ 宫格塌成竖排，形态没了。

**修法**（两行，都在 `PurchasePanel.vue` scoped）：
- `.pu-view > .wb-panel { flex-shrink: 0 }` —— 面板不许缩，装不下溢出 `.pu-view` 去滚
  （`pu-view` 自己就是 `overflow:auto` 的滚动口）。拿货单宫格与已忽略折叠面板都吃这条。
- 最小列宽 200：442 内容宽下 `200×2+12=412 ≤ 442` ⇒ 窄窗仍并排两列。
  **宫格的"并排"是形态本身** —— 窄窗塌成一列就等于退回表格之前的竖排，这不是"自适应"。

## 判据（改这块之前先读）

- **表格换宫格 ⇒ 旧形态判据全部翻面**。新增的宫格布局守卫一条内含三个判据
  （`today:ui` 的 `purchase` 段）：
  ① 前两张卡**同一行、左右并列**（`display` 被改成 block / flex-column 时红 ——
  纯 DOM 存在性断言抓不到"卡片还在、只是变成一列"）；
  ② 每张卡 `scrollHeight == clientHeight`（被弹性列压扁时红）；
  ③ 行内动作滚到眼前后 `getBoundingClientRect` 在视口内且 `elementFromPoint` 命中自身
  （被别的元素盖住时红）。
- ⚠️ 守卫里滚的是**整张卡**不是单个按钮：窄窗（215px 卡）下四个文字动作折成两行，
  只滚第一个按钮会让行尾的「删除」刚好压在折线下 —— 那一红的是"折行"不是"不可达"。
- **变异验证**（各只红目标那条）：拿掉 `flex-shrink:0` ⇒ `clipped=true` + 两个按钮
  `out-of-view`；`display:grid` 改 `block` ⇒ `side=false`。两条都实跑确认，不是推演。
