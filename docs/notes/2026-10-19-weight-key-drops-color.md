# 克重取数去掉「颜色」这个前置条件（2026-10-19）

## 症状

订单进得来、款也认得，但运费算不出，界面只写「缺克重」。人去产品库把克重填了，**还是缺**。

## 两条各自独立的原因（都在真库上量过）

| 断点 | 数据事实 | 后果 |
|---|---|---|
| 颜色是两个世界 | 订单上的色是**平台色名**：`7`、`Khaki`、`Photo color`、`printing 04`；产品库里是用户自己的色名：`黑色`/`白色`/`红色` | `skuWeightKey(款, 色, 码)` 逐字节比 ⇒ 一条也命中不了 |
| 尺码是两种写法 | 产品 SKU 写 `3XL/4XL/5XL`，同一批订单写 `XXXL` | 就算颜色对得上也命中不了 |

真库取证（51 单 / 19 款 / 365 变体）：

- 精确命中（款+色+码）只有 **4/51**；
- 「款+码」层：**83/83** 个「款×码」的**各色克重完全一致**，0 例各色不同重；
- 尺码：4 条 `XXXL` 的订单在产品侧一条都对不上（产品只有 `3XL`）。

## 定性：不是"色名没配"，是"颜色不该进这个键"

上一轮设想的方案是「让用户把平台色配一次我的色名（`(productId, 平台色) → variant`）」。
真库一看不可行：平台色名里有一半是**数字**（`1`…`15`），连猜都没有依据；让人逐色配一遍，
等于把"多色逐色配映射"这件刚被证伪的事换个壳重做一遍。

而克重本身在实测里**与颜色无关**（83/83 各色同重）⇒ 正确做法是让颜色**退出克重的判定条件**，
而不是给两套色名建字典。

## 改法（纯层，无表结构、无落库值变化）

`src/lib/orderCost.ts`：

1. `canonSizeKey(size)` —— **只用于建查表键**：全角→半角、`XXL`/`xxl`→`2XL`、`XXXL`→`3XL`。
   **不碰** `S/M/L/XL/XS`（`XS` 与 `S` 是不同码），不猜 `均码`/`70B`，认不出原样返回。
2. `skuWeightKey` 的码段改走 `canonSizeKey`（建表与查表两端共用，故天然对称）。
3. 新增 `skuSizeWeightKey(款, 码)` = 颜色留空的同一形态键。
4. `resolveWeightG` 两级：`款+色+码` → **`款+码`** → `null`。
5. 新增 `buildSkuWeightIndex(variants, codeOf)` —— 从产品 SKU 行建查表，**折叠键只在"各色确实同重"时产出**：
   该款该码的**在售**变体全部填了克重、且值完全一致。任一没填 / 任一不同重 → 不产出。

`src/core/services/skuWeights.ts` 退化成「取数 + 调纯函数」，规则只有一处。

## 三条"宁可少算"的纪律

- **少算优于错算**：折叠键不存在时继续报「缺克重」（人看得见、会去补），绝不拿某个颜色的重量顶上 ——
  顶错了是发错货。
- **无色行不建精确键**：颜色为空的变体建出来的键就是「同款同码」键，会让"各色不同重"绕过判定。
- **归档变体不参与折叠判定**（不发货，不该挡住），但它的精确键照样生效。

## 真库效果

| | 旧 | 新 |
|---|---|---|
| 51 单里有克重 | 4 | **12** |
| 折叠键 | — | 72 个 |

剩余 39 单：17 单没认款（没有产品，属"人工一次"那一步）、8 单尺码 `S/M` 产品侧根本没有这两个码、
其余是产品 SKU 克重没填（126/365 变体 `weight_g=0`）。**都在"补数据"侧，不在代码侧。**

## 守卫

- `tests/orderCost.spec.ts` +7：尺码归一（`XS≠S`、`XXXL==3XL`）、折叠键不可冒名精确键、
  两级查询优先级、折叠边界（全填同重 / 有没填 / 有不同重 / 归档 / 无色行 / 无款编码）。
- 变异五条各只红目标断言：去尺码归一 → 尺码用例红；去第二级 → 两级用例红；
  不要求全填 → 「有没填」红；不同重也折叠 → 「不同重」红；无色行建键 → 「无色行」红。
- 门禁：`tsc` / `vue-tsc` / `verify` / `verify:docs` / `build` / `vitest` /
  `today:ui` / `order-profit:ui` / `shipping-rate:ui`。

## 仍然不解决

- **订单上的颜色仍旧显示平台色名**（`7` / `Khaki`）。这是"事实"而非 bug；要显示成 `黑色` 需要人给一次对应，
  属 UX 能力，本轮不做。它**不再阻塞运费**，因为克重已不看颜色。
- `S/M` 这类"产品侧没有这个码"的情况要靠建款时补齐尺码，代码无从推断。
