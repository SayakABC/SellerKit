## ⭐ 通用铁律（跨轮复用）

- ⭐⭐ **产品原则（用户 2026-10-20 明确）：「数据准确」与「人工介入最少」并列，不是二选一**。开工前先问
  「有没有不用人做的办法」，再决定要不要加按钮/入口：
  · 能由**已有事实推导**的（映射、色图、克重、尺码归一），一律自动落，不要变成"请人工确认"；
  · 自动化的**触发点要紧贴语义变更**（映射确认、店铺归一、订单落库），而不是"用户点一下"；
  · 自动修完**必须说出来**（"刚按已有映射补了 N 行"）—— 静默改库会让人以为数据本来就是这样，比不修更糟；
  · 只允许自动写**确定性结果**（同一输入必得同一输出），且只碰"未定/占位"状态，绝不自动覆盖人的结论；
  · 新加一个"待办按钮"之前先想：它能否变成加载时的幂等自愈（`dryRun` 报数 + 真跑只在不改变语义时进行）。
- ⭐⭐ Vue `v-model` 挂 `<input type="number">` 会把输入 **coerce 成 number**（TS 声明 `string` 会说谎）；对其调字符串方法（`.trim()`）= **渲染期崩溃 ⇒ Vue 卸载整个组件**（"用着用着弹层自己消失"），不走 `window.onerror` 只有 `console.error`。防御 `String(x ?? '')`；冒烟守卫断"元素还在 + 值重算"（2026-10-18 拿货编辑器敲单价踩过，变异验证于 `today:ui` 敲单价条）
- ⭐ "元素静默消失"定位次序：IDLE-CHECK → 拦 keydown/click → 拦 `removeChild` 抓卸载 → 查假桥调用排除保存路径 → 入口函数埋栈排除主动关 → **最后覆盖 `console.error`**（渲染崩溃只去那里）；合成事件（`el.value=`+`dispatchEvent('input')`）与真实敲键同路径，能复现
- 假桥/夹具连「结构」一起复刻（参数语义、缺省行为、分页边界、sheet 顺序）；桥少一个分支 ⇒ 断言恒绿
- ⭐⭐ 假桥 data **返回活引用**（真 IPC 是结构化克隆）⇒ 写入后"同引用赋回"被 hasChanged 吃掉，响应式静默失效（宿主看着是新的、computed 永远旧缓存）；假桥返回数组一律 `.slice()`（2026-10-17 忽略原因三处证据打架，实跑定位）
- ⭐⭐ 桩给所有输入同一输出 = 把被验的量写死（最隐蔽的空转）。自检：喂两个**应结果不同**的输入
- ⭐⭐ **借别处的类名 ≠ 借到样式**：`<div class="gd-toolbar">` 抄过来，那套 CSS 在**别的组件的 scoped 块**里 ⇒ 类名在、样式不在（按钮被挤到下一行、贴左边）。DOM 断言只问"元素在不在"，一律绿；只有**截图/几何**看得出来。新页面要复用版式前先确认那份 CSS 是不是全局（`src/styles/index.css`）
- ⭐⭐ **手写的枚举白名单（if 长链 / 数组）漏一项不报错**：`loadPrefs` 里"哪些 tab 值算数"是手写 if 链，`shipping` 加了两轮都漏着 ⇒ 用户上次停那一页、下次进被弹回第一页，零报错。清单要从**单一来源**派生（数组 → `as const` → 类型也由它派生），白名单读它
- ⭐ 新页面的**表格列宽**别指望 auto 布局：内容只有三五个字时三列会被平均摊开（联系方式与说明之间空半屏）。要定宽用 `table-layout: fixed` + `colgroup`（列宽写在 `col` 上；fixed 布局下 `td.xxx` 的宽度声明静默不生效）
- ⭐⭐ 「从自己的输出学自己的输入」= 恒空转：学习/对照类逻辑的"原文"必须取**外部事实源**（采集快照），不能取本函数链路刚写过的字段（`saveCorrection` 先写 `oi_orders.color` 再学 ⇒ 键与目标同值，永远记不下）。同理"这次改了什么"要拿改前快照，不是改后读回
- ⭐⭐ 对照/字典的**粒度选在产品级**（不是平台级会串、不是商品级费工）：判据是"哪个维度上语义真的相同"。同款同色名是业务事实（配一次覆盖全款多商品），同平台同色名只是巧合（不同款可不同叫法）。实现上数据层 `WHERE product_id` + 纯函数再判一次是**冗余保护**（只撤一层全绿，两层都撤才红 —— 别把"单层变异不红"误判为断言无效）
- ⭐ 取数粒度 ≥ 展示粒度；"不存在就回落第一个"只能是兜底；SQL 挑"某层用过的那条"用 `EXISTS` 不用 `JOIN`
- ⭐⭐ 夹具复刻「生产形状」：生产恒空的字段别填（= 关掉用例）；同一逻辑 id 两表会撞主键 ⇒ 夹具走生产同一落库函数取 id
- ⭐⭐ 退路/兜底入口别挂条件渲染容器里：问「最被需要的那一刻容器还在吗」；夹具要有零数据样本
- 可达性断言前先关残留模态（covered-by 栈看 `wb-mask`）；模态多的模块给 ✕ 补 `data-act`
- ⭐⭐ **嵌套模态**（弹层里再开弹层，如今日 SKU 矩阵的"看大图"）：遮罩的包含块会被祖先的 `transform`/`filter` 换掉 ⇒ `inset:0` 静默缩进那个容器。判据用**几何**不用截图：`遮罩 rect == 视口`（变异：给祖先加 `transform: translateZ(0)` ⇒ 量到 `906×219`）。点遮罩/`Esc` 都只能关**自己**（两层都用 `@click.self` 时最容易关错一层）；常驻 window 的 `Esc` 监听要带"这层开着"的守卫
- 用户可见文案里**不要写 Markdown 标记**（`**粗体**` 会原样显示在界面上）；提示语要粗体用 `<b>`
- ⭐⭐ 跨模块跳转回程会静默失效（`activateCore` 早退守卫）⇒ 切回前等目标 DOM 落地、判据双向

- ⭐⭐ **收纳/折叠的判据不能只看 `aria-expanded`/图标**：只转箭头、内容照旧占高度的实现能骗过一切查属性的断言 ⇒ 断言元素**从 DOM 消失**（并双向：再点要回来，"关了打不开"同样绿）；另加一条源码级断言钉"收起参与的是渲染条件"
- ⭐⭐ **冒烟脚本里写死别处的文件路径 = 定时炸弹，而且炸相取决于抛错落在生命周期的哪一段**：`mail:body:smoke` 写死读 `ui-plugins/shop-accounts/index.html`（该岛 2026-10-14 已回收为内建模块），那步在 `app.whenReady()` **之前** ⇒ Electron 对 load 期异常只打一行 `App threw an error during load` **且不退出进程**，症状是"**零输出、一直卡着**"，本轮被误判成"同机并发挤住"整整一轮。三条纪律：① 读仓库文件的动作放进 `whenReady` 的 `try`（catch 打堆栈 + `app.exit(2)`，永不表现为挂住）；② 跨域引用改成**按事实扫描**（"谁的源码用到它就读谁的文件"），扫不到就**显式打印"不适用"**，别抄一份副本冒充真实（副本会让"对方删了那条指令"恒绿）；③ 回收岛 / 删表 / 改列名之后，除跑门禁再 `grep` 一遍 `scripts/` 里对被删路径与旧列名的引用


## 归类链路 / 货与成本

- 归类顺序「映射→指纹→模型」；`features` 只由 VLM 写 ⇒ 人工核对恒空；跨域锚点 = `code`；订单挂款挂在图片上；回流只写不覆盖 / 颜色只填不猜 / 失败不外抛
- 颜色两个存处：`oi_orders.color` = 订单行属性（= **平台色名**，2026-10-20 起由 `parseOrderPropsColor` 从报表「产品信息」的 `(产品属性:Color:5,...)` 补出，v5 只回填空值）；真正载体 = `oi_style_colors(款,色)`
- 归色五级（`autoAssignByMap`）：映射色 → 图片已有真实色（不动）→ 订单图反查采集色 → **报表规格串色** → 已有平台色名 → `未分类`；规格串排在图**之后**（图有采集快照作证 ⇒ 以前能定的行不变）。一单多色 ⇒ 定不出来（取第一个=错色）
- ⭐⭐ **关联表算"已关联"必须 JOIN 存活主表**（2026-10-20 悬空映射）：`pl_shop_sku` 指向已删产品不会消失，`resolveOrderSku` 当未命中，而队列/批量解析按映射表算已关联 ⇒ 问题商品**连待办都不进**（用户看到 N 单认不出、却没有一处能点）。凡"某集合算不算数"，判据要与消费方同一口径
- ⭐⭐ **副本字段绝不能进匹配键**（2026-10-20 平台退出映射身份）：`pl_shop_sku.platform` 是写映射那刻从店铺抄的副本，却在 `(platform,shop_id,item_id,spec)` 里 ⇒ 「店铺登记」改一次平台（`toNameKey` 不折叠大小写，`AE→ae` 也算）整店映射一条都不命中；重配因四列都不撞而**新增行**、旧行留成幽灵关联。身份取**能被事实唯一派生**的那几列（`shop_id` 全局唯一 ⇒ 平台可派生），副本只作记录/兜底展示。识别信号：某列的值**只可能来自另一个表的同一行**（`shop_url` 也是这一类）
- ⭐ 同一份"身份"散落在多处 SQL 时，**要么一次改齐、要么留一个键函数**：本轮四处（认款 / 队列 mappedKeys / 批量 / 写入判重）靠 `bindingKey` 收口；键函数**换名并删参数**比改语义安全 —— 旧签名还在，下一个调用者照样把副本传进去
- ⭐ **去掉匹配条件必须同时看索引**：旧索引前缀是刚删掉的那列（`platform`）⇒ 查询放弃它退化成扫表；补 `(shop_id,item_id,status)` 后才是既对又快的
