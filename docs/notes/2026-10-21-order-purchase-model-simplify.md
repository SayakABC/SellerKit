# 订单-采购模型简化方案（对齐现有基线）

> 决策日：2026-10-21。目标：把利润/对账的数据源收敛到「订单表 + 订单商品关联表 + 包裹表」，
> 退役 `ae_cost_map`（成本区间表），让数字只有一处来源、一处维护。

## 一、最终数据模型（三张自洽表）

### 1. 订单表（一单一行，`order_no` 幂等）

| 字段 | 说明 |
| --- | --- |
| 店铺 / 订单号 / 下单时间 / 金额 / 收货国 / 状态 | 现有 `oi_orders` 已具备 |
| **总克重**（新增） | = Σ 关联表行克重；导入/归类时计算并钉死 |
| **总物流费**（新增） | 按「总克重 → 无忧物流运价」查一次，钉死（包裹级，见下） |

### 2. 订单-商品关联表（一单多行）

| 字段 | 说明 |
| --- | --- |
| 订单ID / 商品ID / 图片 / 尺码 / 颜色 / 数量 / 关联产品ID / 店铺ID / 状态 | 现有 + 需补 |
| **克重**（新增，行级） | 从产品 SKU 查；**在归类核对「确认无误」时**钉死（关联产品ID+颜色确定后才查得到 SKU） |
| **实际进价**（新增，行级） | ⚠️ **不在导入时**，而是拿货单填价落账后回写（见 §二 时序） |

> **同款合并是「汇总层」，不是「存储层」**：关联表**保留 SKU 级粒度**（每行 = 一个 SKU 规格），
> 拿货/展示时按「关联产品ID+颜色+尺码」聚合合并显示。这样拆包才能「按单个商品拆 + 拆分合并行数量」——
> 物理行是 SKU 级，拆包只是给 SKU 行分配数量到不同包裹。

### 3. 包裹表（新增，支持一单多包）

| 字段 | 说明 |
| --- | --- |
| id | 包裹主键 |
| order_id | 归属订单 |
| 包裹号 / 物流单号 | 外部追踪号 |
| **克重** | 本包裹克重（默认 = 所含 SKU 行克重之和） |
| **物流费** | 本包裹运费（按包裹克重查运价） |
| 包含订单行 | 多对多：`parcel_lines(parcel_id, order_item_id, qty)` |

> **拆包允许拆分一个 SKU 行的数量**（用户已拍板）：`parcel_lines` 带 `qty`，一行 SKU 数量 N
> 可拆到多个包裹（各包裹分到部分数量）。一单多包时订单表 `总物流费` = Σ 包裹物流费；单包 = 该包裹物流费。

## 二、时序（核心结论）

```
导入订单 ──► 归类核对（确认无误时，一次性钉死）──► 拿货页面 ──► 拿货单(填实际进价) ──► 拿货落账
   │                    │                                              │
   │ 只落原始订单        │ 颜色/产品ID/尺码 确定后：                      │ 回写: 关联表.实际进价
   │ （不钉克重/运费）    │ ①查 SKU 克重→钉关联表行                       │ (替代旧 ae_cost_map 落点)
   │                    │ ②Σ克重→查运价→钉订单表总克重/总物流费           │
   └────────────────────┴──────────────────────────────────────────────┘
```

- **克重/运费都在「归类核对确认无误」时钉死**（用户已拍板）：此时颜色/产品ID/尺码/收货国全齐，
  克重才查得到 SKU、运费才算得出。**导入时只落原始数据**，不钉克重/运费。
- **实际进价**：拿货单填价后**回写**订单关联表，不是导入时（导入时拿货单还没填）。
- 这是「实际进价」从「款级区间表」迁移到「订单行级快照」的落点变化。

## 三、与现有实现的差异

| 现状 | 目标 | 动作 |
| --- | --- | --- |
| `oi_orders` 一行 = 订单×图片 | 订单表一行 = 一单；商品拆关联表 | 拆表（大改，见风险） |
| 进价落 `ae_cost_map`（款级区间） | 进价落关联表（订单行级快照） | `purchase-cost-sync` 改写 |
| 运费实时查 `sr_rate_snapshots` | 运费钉订单表/包裹表 | 利润引擎取数改读快照字段 |
| 克重实时查 `pl_shop_sku` | 克重钉关联表 | 导入/归类时查一次落库 |

## 四、退役表清单（待消费方改造完成后）

| 表 | 消费方 | 退役前提 |
| --- | --- | --- |
| `ae_cost_map` | 利润引擎成本、`purchase-cost-sync`、`manual-costs` | 成本改读关联表「实际进价」；`manual-costs` 落点改为「产品信息进价」 |
| `ae_settle_lines` | 利润引擎精确轨、件数真值 | ⚠️ **暂缓**：对账口径 A（供应商应付）不依赖它，但平台结算轨仍需确认 |

**保留**：`sr_rate_snapshots`（供导入/归类算运费）、`pl_shop_sku`（克重/SKU）、`suppliers`、`purchase_orders`/`purchase_items`（拿货单仍是实际进价产生地）。

## 五、产品域定稿（2026-10-21 补充确认）

### 产品域三表对照（方案 vs 现有）

| 方案表 | 现有表 | 定稿动作 |
| --- | --- | --- |
| 产品信息表 | `pl_products`（id/code/name/supplier_id/category/status/note/image_id） | **+ `进价` 列**（当前最新价，维护入口） |
| 产品SKU表 | `pl_variants`（product_id/code/color/size/**weight_g**/status） | **+ `image_id`（SKU 图片）** |
| 店铺商品-产品关联 | `pl_shop_sku`（item_id/product_id/shop_id/spec/variant_id） | 已满足，无需改 |

### 产品域两个新增字段（用户已拍板）

1. **`pl_products` 加 `进价`（成本单价，分）**：
   - 产品表存「**当前**进价」（维护入口，产品页展示 + 新订单默认进价）。
   - 订单关联表存「**导入/拿货时**快照」。两者并存不冲突：一个答「现在多少钱」，一个答「那单当时多少钱」。
   - 退役 `ae_cost_map` 后，`manual-costs`（手工进价）的落点从「区间表」改为「产品表当前进价」；
     `purchase-cost-sync`（拿货对账同步）的落点改为「订单关联表实际进价」。

2. **`pl_variants` 加 `image_id`（SKU 图片，引用 `pl_images`）**：
   - **用途是「认色」**，不是装饰：采集回来的颜色不可信（`Picture color` 占位、平台色名≠自家色名），
     需人工对照图片逐色校正。每色一图 = 认色的工作界面素材。
   - 落点走窄接口（`variantImageAttach/detach`，同 `pl_products.image_id` 的 `imageAttach/detach` 模式），
     不进 `variantUpsert` 全量提交。

## 六、包裹维护界面落点

拿货单编辑在 `src/modules/today/tabs/PurchaseOrderEditor.vue`（「今天 › 拿货」页签）。
包裹维护建议落在**订单详情/归类核对页**，而非拿货单：

- 拿货单是「供应商维度」，与包裹（物流维度）正交，不该混在拿货单里。
- 建议：在**归类核对页**（`ClassifyPanel.vue`）或订单详情侧，加「包裹拆分」入口：
  勾选订单内若干行 → 归为一个包裹 → 填包裹号/物流费。

## 七、待办 / 风险

1. **拆表是大工程**：`oi_orders` 下游（`shippingRows`/`pickingRows`/`settleLines` 对齐/颜色回填/利润引擎）全部按「订单行=最小单位」写死，拆表需同步改写。
2. **`ae_settle_lines` 去留未定**：平台结算轨（净收入/件数真值）若要用，不能删。
3. **克重钉死时点**：SKU 克重后续修改不会回改已导入订单（快照语义，符合预期）。
4. 拆表与「进价/运费快照」是**两个独立工程**，建议分阶段，不混在一起做。

## 七·补、审查发现（2026-10-21 复审）

1. **克重/运费钉死时点已定**：统一在「归类核对确认无误」时（不是导入时）——已并入 §二 时序。
2. **同款合并 vs 拆包已解耦**：合并是汇总层、拆包是物理层。关联表保留 SKU 级粒度，`parcel_lines` 带 `qty` 支持拆分合并行数量。
3. **进价回写范围待定死**：拿货单按「款色尺码」汇总，回写订单行时须明确「只写该拿货单覆盖的行、且不覆盖已写的旧行」——避免后拿的价污染历史订单。
4. **`pl_variants.image_id` 的认色工作流**：认色 = 归类核对页「选款色」动作，SKU 图片用于辅助展示该款各色，**不另建认色页面**（避免重复建设）。

## 八、分阶段执行计划（草案）

> 按「快照前置」与「拆表」拆成两个独立工程，互不阻塞；每阶段门禁全绿再进下一阶段。

### 阶段 A：快照前置（不改表结构，先加字段钉快照）

1. **`pl_products` + `进价`**、**`pl_variants` + `image_id`**（两条 `ALTER`，走 `ensureProductColumns`/`ensureVariantColumns` 补列）。
2. **订单表 + `总克重`/`总物流费`**、**关联表 + `克重`/`实际进价`**（快照写在「归类核对确认无误」与「拿货落账」两处）。
3. **利润引擎 `orderCost.ts`** 改读快照字段（克重/运费/成本），不再实时查 `sr_rate_snapshots`/`pl_shop_sku`/`ae_cost_map`。
4. **`manual-costs` 落点改产品表**、**`purchase-cost-sync` 落点改关联表**（进价回写范围按 §七·补 3 定死）。
5. 验证利润数字与改造前一致（门禁：`<order-profit>:ui` + `vitest run`）。

### 阶段 B：拆表 + 包裹（大工程，独立立项）

1. 订单表拆「订单 + 订单商品关联」两表，`order_no` 幂等。
2. 建 `parcels` + `parcel_lines(parcel_id, order_item_id, qty)`（一单多包，支持拆分数量）。
3. 改写全部下游：`shippingRows`/`pickingRows`/`settleLines` 对齐/颜色回填/利润引擎。
4. 归类核对页加「包裹拆分」入口（按单个商品拆、可拆数量）。

### 阶段 C：退役表

1. `ae_cost_map` 消费方全部迁走后删表。
2. `ae_settle_lines` 待平台结算轨决策后再定去留。

## 九、C2 定稿：明细行两个成本字段（2026-10-21）

> 本节收敛 §五：早前定过「进价 + 实际进价」两个快照，实现侧只落了后者（A5 的 `cost_cents`），
> 预估一直实时查 `ae_cost_map`。删表前把两字段补齐。执行细则见
> `docs/plans/ORDER_PURCHASE_MODEL_SIMPLIFY_PLAN.md` §5「C2 定稿」。

| 字段 | 语义 | 写入时点 |
| --- | --- | --- |
| `oi_order_items.cost_cents` | 进价（预估，当时生效价） | 归类核对「确认无误」 |
| `oi_order_items.actual_cost_cents` | 实际进价（拿货实付） | 拿货落账回写，只补空 |
| `pl_products.cost_cents` | 当前进价 | 成本面板 / 产品导入 / 产品抽屉 |

- 利润取数：**实际 > 预估 > 缺**；0 一律视为缺失。
- 存量：现有 `cost_cents`（实际价）先搬 `actual_cost_cents`，再把旧价目表按下单日期回填 `cost_cents`。
- 来源由"哪个字段有值"表达，**不另加 `cost_source` 标记**。
- 判据更正：只要求成本侧 `costmap` 归零；`weightSource='lookup'` 是克重来源，不在 C2 判据内。
