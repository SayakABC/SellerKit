# 「已导入 N 行」是个数字，不是地方：第 1 步的产物必须当场列出来

- 日期：2026-10-22
- 场景：发货台 › 导入订单
- 触发：用户实报「导入订单后显示『已导入 16 行订单』，但不知道订单在哪」。

## 结论（下次别再犯）

1. **"存到哪个页面"不等于"数据在哪"。** 回执卡原本写着「存到「订单」—— 在「归类核对」页签、「拿货」页签、「统计」页能看到」，
   这回答的是**页面名**；用户听完仍然不知道**自己刚导的那 16 行长什么样**。凡是"我导入了 N 条"的动作，
   该页必须能列出这 N 条 —— 否则用户只能靠"去别的页面里翻"来确认自己没白干。
2. **同一个数字不要在两处并列。** 原页面既有容器 `summary.orders.total`（那条「今天导入 N 行订单」现状条），
   又有列表自己的行数。两者来自**同一次 IPC 的同参数**，但刷新时差足以被读成"数字不对"。
   ⇒ 数字收敛到**一处**（列表自己那份），现状条并进表头。页签徽标另算（不同屏、同参数）。
3. **新块要考虑首屏可见性，而不是"DOM 里有就算做完"。** 实测 1152×800：投放区（~230px）+ 回执卡
   （~190px）已占满首屏，明细表连同表头被压在最底、行一个都看不见 —— 等于白加。
   ⇒ 导入**写了库**之后 `scrollIntoView({ block: 'nearest' })` 把它带进视野（`nearest` = 本来可见就不动；
   尊重 `prefers-reduced-motion`）。**没写库不滚**：那时没有新行，滚过去只有旧数据。
4. **金额是整单级，不能按行合计。** `shippingRows` 的 `amountCents` 取自 `oi_orders.amount_cents`，
   一单拆多行时每行都是同一个整单金额 ⇒ 合计等于翻倍。列表只显示、合计不显示（表头 `title` 写明口径）。
5. **空态要按"为什么没有"分叉。** 「今天还没有导入」与「没有匹配 xxx」指向完全不同的下一步
   （去导文件 vs 改关键字）。合成一句会让第二种人以为自己导失败了。

## 取证

- 取数（与容器逐字同参，`electron/order-db.ts:2758` 按 `date(o.created_at)` 筛导入日）：

  ```ts
  ipc.orderShippingRows({ limit: 2000, importDate: localDayKey() })
  ```

- 接线：容器 `bump()` → `token` +1 → 本页 `watch(() => token.value)` 重取。
  这样"选文件"与"拖进投放区"两条路都自动生效，**不需要在 `runImport` 里再写一次刷列表**（那正是会漏拖放那条路的写法）。
- 骨架：`src/modules/today/tabs/ImportPanel.vue`（`data-act="import-rows"` / `-count` / `-search` / `-refresh` / `-empty` / `-more`）。
- 守卫：`scripts/today-ui-smoke.mjs` 的 `import-drop` 段新增 6 条，其中**反向夹具**是关键 ——
  `IMPORTED_OLD`（三天前导入）必须在列表里**不出现**；漏传 `importDate` 时它才出现，而"能滚动的表多几行"
  人眼几乎发现不了。
- 截图取证：1440×900 与 1152×800 各一张（临时脚本已删；做法同 `scripts/classify-shot.mjs`）。

## 踩到的两个坑（注入脚本里）

`today-ui-smoke.mjs` 的假桥是**模板字符串**（`const FAKE_BRIDGE = \`…\``），所以：

1. 注释里**不能出现反引号**（文件头已写明）—— 本轮又踩了一次（写 `` `importDate` `` 直接语法错）。
2. **反斜杠也会被吞**：`/\d+/` 注入后变成 `/d+/`，守卫当场变成"永远匹配不到"（还不会报错）。
   取数字改用 `replace(/[^0-9]/g, '')`，别在注入脚本里写带 `\` 的正则。
