# 常用色一排 + 拖色合并：给"两色并一色"一条真正的路（2026-10-24 第三轮）

用户口径：「是否可以把常用颜色放在上面，通过拖动颜色方式来合并？当前将并入的颜色名称修改后或删除后，
下面已存在的 SKU 信息就没了。」

## 结论（五条）

1. **「改了名 / 删了色，SKU 就没了」不是丢格**。探针把整段流程走了一遍（并入 → 改第 1 个色名 → 改最后一个 →
   删最后一个），每一步的「格数 / ✓ 数 / 克重输入框数」都原样保持（`checked: 4 → 4 → 4 → 2`，
   最后一步少的就是被删那一行的 2 格）。改色名在数据层只是改标签，`cells` 一个都不动。
2. **真正缺的是"把两行并成一行"这条路**。用户能想到的做法只能是"把一行改名成另一行的名字"，
   而保存校验会拦下（`颜色「黑」出现了两行 —— 先合成一行再保存`）。被拦下之后如果关掉抽屉
   （放弃改动），此前"并入矩阵"的一切都没落库 ⇒ 合起来就读成"改了名就没了"。
   ⇒ 这轮补的是**合并**，不是"修一个丢数据的 bug"。
3. **拖色合并**：把色 chip 拖到另一个 chip 上松手 = 前者的格搬进后者、前者消失
   （`mergeMatrixColor`）。阈值 6px：小于它算点击（点输入框 / ✕ / 缩略图要照旧）。
4. **常用色一排排在「颜色」上面**：10 个服装高频色，点一下加一色；已经在矩阵里的**打勾变灰**，
   再点**不会加第二行**（只把焦点递到那一行的输入框）—— 于是这一排同时回答"还差哪些色没加"。
5. **合并的落库语义**（这是它安全的原因）：搬的是**同一个格对象**，`variantId` 跟着走 ⇒
   保存时那些 SKU 是"原地改色名"，不是"删旧建新"（编码与状态都在）。同码冲突保留**目标行**那一格，
   但克重取有值的一方；源侧那条 SKU 会随保存删掉 —— 回执把这件事说出来
   （`… 5 个同码格以「藏青」为准（保存后少 5 个 SKU）`）。

## 坑（这轮真踩到的）

1. **空格里没有克重输入框**：空组合只有一个虚线按钮（`v-else`），`.mx-weight` 只存在于"在卖"的格上。
   冒烟里按下标取 `querySelectorAll('.mx-weight')[1]` 会拿到 `undefined`（报错还是
   `Cannot read properties of undefined (reading 'tagName')` —— 看着像选择器坏了）。一律改用
   `[data-cell-row][data-cell-size]` 定位。
2. **冒烟注入脚本是模板串，注释里一个反引号就把整段截断**：那条注释里顺手写了
   「用 `[data-cell-row][data-cell-size]` 定位」，反引号直接把注入脚本截断，Node 报
   `ReferenceError: data is not defined`。这一条已在工程铁律里，但**写"定位方式"这类注释时
   最容易顺手带上反引号**。
3. **不用 HTML5 拖放**：色 chip 里有 `<input>`，`draggable` 会和"拖选文字"抢事件；
   **也不用 pointer capture**：合成事件（冒烟/截图脚本）里 `setPointerCapture` 会抛
   `InvalidStateError`，且捕获会把 move 全锁在源元素上。合并目标就在同一个容器里 ⇒
   监听挂容器 + `elementFromPoint` 命中 `[data-mx-row]` 足够。
4. **回执文案不许换行**：`.mx-bar` 是 `flex-wrap: wrap`，回执一长就把图例挤到第二行 ⇒
   下面矩阵整体下移十几像素，看着像界面错位。修法不是缩字号，而是**回执出现时顶掉图例**
   （两者都是次要说明）+ 单行截断（全文进 `title`）。
5. **常用色的每个词都必须在色卡词表里**（单测钉住）：否则调色板会出现一排"没有色块的文字"，
   比不画色块更让人以为是坏了。

## 不做的事

- **不做"改名撞到已有色名 ⇒ 自动合并"**：敲字过程中会瞬间路过别人的名字，自动合并等于
  按一次键就能毁掉一行数据。撞名仍拦下，但文案改成指路（"把一行拖到另一行上合并成一色"）。
- **合并不可撤销（保存前可放弃）**：抽屉里的改动本来就靠"放弃改动并关闭"整体回退，不为此单开一步 undo。
- **不给调色板做"取色器"**：色名是外部事实（平台色名 / 采集色名），颜色值只是识别辅助。
