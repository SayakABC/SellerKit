# 产品编辑抽屉改成「整窗高两栏」：字段与 SKU 各占一栏，SKU 的手势按"一句话说清的事"来设计

**日期**：2026-10-24 · **用户口径**：「重新设计编辑产品页面，当前页面太杂乱，SKU 的编辑也很不方便」。

**与旧笔记的关系**：不取代任何一条。[`2026-10-17-sku-spec-rack-and-weight.md`](2026-10-17-sku-spec-rack-and-weight.md)
的"规格区 / 组合区分家"仍是当前实现（本次只把颜色列表在 `fill-height` 模式下放宽到 168px，
并把列头 / 行名从只读文字改成开关）；[`2026-10-23-product-sku-single-source.md`](2026-10-23-product-sku-single-source.md)
的"矩阵唯一维护面在产品抽屉"不变。

## 结论（先看这段）

1. **改的是版式与手势，不动数据模型**。抽屉从「560px 单列滚到底」改成**整窗高两栏**：
   左栏 320px（主图 / 基本信息 / 价格与状态 / 备注，分节用一条细横线分隔，不套框），
   右栏吃满剩余宽高（吸顶工具条 + 规格 + 矩阵 + 编码 / 老数据）。抽屉宽 `min(1040px, 94vw)`
   —— 仍然让列表露出可见的一条，抽屉"改的时候对照列表"的初衷没变。
2. **两栏各自滚动**。这是"太杂乱"的根：单列时字段与 SKU 在同一条滚轴上下叠加，
   改 SKU 要把字段滚走、看字段要把 SKU 滚走；而且矩阵被挤在 560px 宽、`40vh` 高里
   （行头 168 + 每列 96 ⇒ 一屏只看得到三列）。两个方向的空间都不够，界面再整洁也没用。
3. **矩阵高度不再用 `40vh` 封顶**，改成 `flex: 1 1 auto` + `min-height: 180px`（`fill-height` prop）。
   `40vh` 是"弹层别被顶出去"的兜底，在产品抽屉这个整窗高容器里它只是把表格压成一条。
   ⚠️ 采集快照弹层与建款向导**仍是** `40vh`（那两个场景没变，不要顺手删掉兜底）。
4. **SKU 的批量手势**（新增，全部有守卫）：
   - **列头 = 整列开关、行名 = 整行开关**。这两处在矩阵里本来就是"这一列 / 这一行"的代表，
     又刚好是**只读标签**（改名在规格区），可以安全承担这个动作。语义是"**应该是**"而不是
     "反过来" ⇒ 幂等（已经全开时点一下 = 整列/整行取消），连点两下回到原状。
     `setMatrixRowCells / setMatrixColumnCells`（`src/lib/skuMatrix.ts`）。
   - **按住拖过几格 = 连续勾选 / 取消**。`pointerdown` 刻意**不直接改**：那样一次普通点击会被算
     两次（down 改一次、click 翻回来）。所以 down 只记目标状态，等真的掠过**另一格**才动手，
     并把起点补上；`pointerup` 后用一个 0ms 的 `suppressClick` 挡掉"拖完那一下"的 click。
   - **克重格按 Enter ⇒ 同一列的下一格**（不是下一行、也不绕回第一格 —— 绕回去会让人以为
     自己没离开过，接着把值打到已填好的格上）。定位靠 `data-cell-row` / `data-cell-size`。
5. **文案去重**。同一句"空格 = 不存在"原先在矩阵图例、矩阵页脚、抽屉末尾各说一遍；现在
   图例说手势、页脚说格的读法、抽屉只留"同款内色+码唯一，改名原地改"。头部那整段
   「边改边存」说明压成一枚 11px 徽标（全文进 `title`）—— 那段解释本身也是"看着乱"的来源。

## 不能破的四条（改这块前先读）

1. **`data-act` 名字是冒烟的位置钩子**，不是装饰：`ed-color` / `ed-weight` / `ed-row` /
   `ed-row-thumb` / `ed-sku-save` / `ed-import-*` / `ed-guard-hint` 全被 `scripts/goods-ui-smoke.mjs`
   逐条使用（含**克重输入框的顺序** `['320','150','','180']`）。重排版式可以，改名字要同步改冒烟。
2. **保存模型不变**：表单字段 `@blur`/`@change` → `autoSave`（含"至多一条在飞" `flying`）；
   SKU 矩阵**仍显式保存**（一次可能改几十格，逐格写库会变成几十次写 + 几十次重拉）；
   关闭前 `closeGuard` 只拦"真的会丢"的两类（未保存的矩阵 / 新增模式的草稿）。
3. **矩阵的既有不变量一条不动**：空格 = 组合不存在（批量开关只改存在性，不造 SKU）、
   行身份 = 色名、`variantId` 原地改名、`price` 原样带回、0 克重显示成空（占位「待填」）。
4. **整行/整列关 = 真的删这些 SKU**（保存时才落库，保存前 `pendingSkuPlan` 列出要删的组合）。
   把整行关掉再打开 = **新组合**（克重丢失）—— 这是既有语义，不是本轮引入的回归。

## 遗留（知情不做）

- 矩阵只有两三行时，`.mx-wrap` 会被 flex 撑满，表格下方留一块空白（电子表格的常态，不影响操作）。
  要消掉它得让容器"按内容定高 + 上限"，而那个上限拿不到"剩余空间"，只能写死视口比例 —— 不划算。
- 左栏在 800px 高的窗口里略有一点纵向滚动（备注贴底）—— 分节间距已收到 10px，再压会失去分组感。
