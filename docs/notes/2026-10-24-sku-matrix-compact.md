# SKU 矩阵：规格区收成三行 chips，颜色靠色块认（2026-10-24 第二轮）

用户口径：「选择并入矩阵后，SKU 样式是乱的，有很多重叠，页面中的颜色也不够直观，操作不够便捷」+「文字也太多了」。
承接同日 [产品编辑抽屉改成整窗高两栏](2026-10-24-product-editor-two-pane.md)（那轮解决"版面太杂乱"，这轮解决矩阵自身）。

## 结论（五条）

1. **「乱 / 重叠」在 DOM 里并不存在** —— 没有元素真叠在一起。真因是**高度预算**被规格区吃干：
   196px 宽的色卡（7 色实测 **330px** 高）把矩阵压到约 180px ⇒ 一屏只看得到 **3 行**组合；
   同时单元格内容只有 96px 宽、左右各 4px 缝 ⇒ 每一格都像要挤出来。看起来是"重叠"，量出来是"没地方"。
2. **规格区改成三行「标签 + 内容」**（`颜色` / `尺码` / `克重`，`SkuMatrixEditor.vue:16,82,141`），
   内容是 chip 而不是卡片：`spec 330 → 150`，矩阵 `~180 → 420`，一屏可见 **13 行**（8 色 5 码）。
   ⚠️ 三行的顺序是**数据维度顺序**，不是视觉排序 —— 用户脑里的顺序是"什么色、什么码、多重"。
3. **颜色直观靠"只读色块"，不靠把色名搬进匹配**：色名 chip 前挂 26px 色块，行首再给 3px accent
   （`.mx-c-row` 的 `inset box-shadow`，颜色取 `findSwatch(色名)`）。色块**只显示**：不参与落库、不参与匹配、
   点不动 —— 铁律「身份用 id，标签只展示」在这里的具体形态是"色名仍是唯一标签，色块是它的放大镜"。
4. **常用动作就地给**（`SIZE_PRESETS` / `addPreset` / `focusSizeAt`）：`常用 ▾` 一次补齐 S–XXL（**幂等，只补缺**）、
   选完自动收起（开着会一直盖住矩阵）、新增色/码后自动聚焦到刚生成的那个输入框、
   `＋ 尺码` 遇到已有空 chip 就**聚焦**它而不是再插一列（否则连点两下会多出一列空码）。
5. **文字收敛到只剩空态与提示**：规格区总说明、页脚说明、导入说明、进价说明全部删掉或压成一句，
   解释搬进 `title`（悬停才出现）。判据是"第一眼看过去只剩控件"。

## 坑（这一轮真踩到的）

1. **几何断言连绿三次，全是"量错了对象"**：`td.scrollWidth > td.clientWidth` 恒假；
   量 `.mx-cell__on` 包装层（它宽恒等于 td 内容宽）即使把输入框改成 96px 也照样绿；
   `table.scrollWidth` 恒等于容器宽（auto 布局会把列压扁而不是溢出）。
   ⇒ 只有量**子控件的 `getBoundingClientRect()`** 对 td 的 rect 才有效；
   而且必须带 `wInputs.length >= 2 && wTogs.length >= 2` 这种"样本数"守卫，否则选择器写歪时零元素 = 零比较 = 恒绿。
   这一条与本仓既有铁律「几何取证要量到真的会变窄的那个元素」同源（见 [工程铁律](2026-10-20-engineering-hard-laws.md)）。
2. **`table-layout: fixed` 配上 `width: max-content` 是失效的** —— 表格宽度由内容决定时，固定布局不参与计算。
   所以"一屏能放几个码"实际由**单元格内容的宽**决定（`.mx-weight` 的 `max-width: 52px` 就是这个作用），
   想调这个数只能调内容宽，改 `table-layout` 没有任何效果。
3. **`从「常用」里补齐` 直接把悬空入口名守卫打红**：`tests/uxEntryNames.spec.ts` 的
   `NAV_PATTERN = /(?:去|在|到|先|从|回)「…」|「…」(?:页|模块|页签)/`，意思是"让用户去某个入口"。
   「常用」是本组件自己画的下拉按钮，不是入口 ⇒ 文案改成 `用「常用」一次补齐`（动词换成"用"）。
   **不要**为此加 `ALLOWED_NON_ENTRY`：豁免表是给"页面上看得见的控件名"留的，而这里只要换个动词就不需要豁免，
   少一条豁免就少一处将来会失效的假设。
4. **窄容器下的残留**：建款向导（640px）里 chip 变宽（约 125–135px），规格区只放得下约 2 行色，
   实测 `spec=116 / table=92`。本轮目标只是产品抽屉，故知情接受，用 `@media (max-height: 720px)` 收
   `.mx-colors` 的 `max-height` 兜底；真要治它得让 chip 在窄容器下折成"色块一行 + 名称一行"。

## 不做的事（免得下一轮重新论证）

- **不给色名自动归类到色系**：`findSwatch` 认不出就返回 `null`，刻意不回落中性灰 ——
  给一个"所有认不出的色都长一样"的灰块，比没有色块更误导（用户会以为它们是同一个色）。
- **色块不做输入**：不做取色器、不做色卡选择器。色名是外部事实（平台色名 / 采集色名），
  在这里改颜色语义会与订单侧对不上。
- **不做拖拽重排行列**：行序/列序即 SKU 生成顺序，重排会改 `pl_variants` 的既有组合顺序，
  而这一轮明确"数据模型零改动"。
