# 记账 P1 界面：三条"判定写在哪一层"的结论，与两个被门禁抓出来的真错

## 结论（改记账页 / 改跨模块跳转前先看这五条）

1. **指标条只认月份，不随筛选变 —— 这是判定，不是漏写。**
   筛完只剩两行而合计仍显示整月，用户第一眼会怀疑"数不对"。所以指标条自己带月份标签
   （`2026-10 · 整月`），表尾再写一句「合计见上方「… · 整月」」说明两者不是一回事
   （`src/modules/ledger/LedgerView.vue:24`、`:280`）。
   反过来做（合计跟着筛选走）的问题是：用户想知道"这个月到底赚没赚"时，必须先把筛选全部清空 ——
   而筛选条件会被持久化，下次进来看到的还是上次那个局部数。

2. **切到「公共」时必须默认勾上全部可参与店铺。**
   首版把参与集合留空，用户看到的是「0 家参与」+ 预览区「请至少勾选一家参与分摊的店铺」——
   等于每记一笔公共支出都要先把店点一遍。修法是 `watch(scope)` 里 seed
   （`src/modules/ledger/EntryEditor.vue:586`）。
   ⚠️ seed 只在"集合为空"时做：编辑历史条目时不能覆盖它读回来的参与集合。

3. **跨模块跳转的 action 必须落到"真能改它的那一屏"，不是"相关的那一屏"。**
   「还没有店铺」的出口原来写 `switchModule('shop-accounts', 'registry')`，而 `registry` 是**店名归一**
   （认历史文本，不能建店），加店按钮在 `accounts`（「店铺」页签）。
   两处一起错：跳转目标错了、文案还指着一个 2026-10-22 已改名的页签（「店铺登记」）。
   抓到它的是 `tests/uxEntryNames.spec.ts`（悬空名守卫），不是冒烟 —— 冒烟只点自己页面上的东西，
   不会跟着按钮跳过去看落点。**文案与跳转目标要同批改**（`EntryEditor.vue:175`、`:684`）。

4. **"必填"的摩擦只能靠减少操作次数解决，不能加兜底选项。**
   相关人必填（P0 裁定）带来"随手选一个"的风险（方案 RK-11），界面的对策是：
   下拉里**就地新建**（只填名称 + 类型）+ 按收支**分别记住上次选的人**；
   **不提供**「其他 / 默认人」这种兜底 —— 那会让台账被污染得比空值更难发现。

5. **锁定要在保存前就说清楚，别等后端拒。**
   已结算条目：金额 / 方向 / 范围 / 店铺 / 相关人全部 `disabled`，作废按钮禁用并写明结算单号；
   营收占比基准的历史条目锁范围与参与集合（**2026-10-26 P2 调整：金额可改，按当初分摊金额的比例重算** ——
   原「锁金额」会让"录错金额只能作废重记"）。后端仍会拒（P0 已实装），但让用户点一次保存才看到红字
   是"设计偷懒"。锁定判据集中成三个 computed（`settledLocked` / `revenueBasis` / `allocLocked`），
   不要在模板里散写条件。

## 两个真错（都是这一轮门禁抓出来的）

| 错 | 怎么发现的 | 失败时的样子 |
|---|---|---|
| 切到「公共」参与店铺为空 | `ledger:ui` 冒烟 `create-shared-equal` 步 | 界面上是「0 家参与」+ 红字「请至少勾选一家」；不是崩溃，用户会以为这是正常要求 |
| 空店态出口跳错页签、文案已过期 | `npx vitest run tests/uxEntryNames.spec.ts` | 提示「去「基础数据 › 店铺登记」添加」：该名 2026-10-22 已改成「店名归一」，且建店在「店铺」页签 |

第二条是**老坑新实例**：改页签名字时，全仓用户可见文案都得跟着改，而这条守卫只覆盖 `src/**` 里
"去/在/到「X」"式的引号名 —— 它抓到了，说明规则在生效。**别把这类红当成"豁免表漏了一项"**：
先确认那个入口还存不存在（本例是入口改名 + 落点也错，只能改代码）。

## 假桥冒烟的夹具要求（`scripts/ledger-ui-smoke.mjs`）

- **三种店铺参与态必须同时存在**：在用·已开业（可参与）/ 已停用（排除：inactive）/ 当月尚未开业
  （排除：not-open-yet）。只放"能参与的店"时，"未开业被排除"这条实现的缺席**测不出来**。
- **stub 必须真改夹具**：保存 / 作废 / 合并相关人 / 科目增改都写回同一份数组，并让 `entryList` /
  `ledgerSummary` 从这份数据现算。否则"列表变了"可能只是乐观 UI，接口其实没落。
- **六类条目都要有**：专属支出、专属收入、公共手工分摊、已结算、已作废、营收基准。
  每种都对应一条锁定或展示规则；缺一种就有一条断言在空跑。
- 计数只作参考：本轮宽视口 55 条、窄视口 57 条（多的两条是横向溢出与弹层宽度守卫）。
