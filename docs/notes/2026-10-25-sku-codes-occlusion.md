# 编码区"被上面的组合遮挡"：`min-height: 0` 让矩阵缩到 0，内容却照自己的高度画出来

**日期**：2026-10-25 · **用户口径**：「打开 SKU 编码编辑时被上面的组合遮挡了，请修复」。

**与旧笔记的关系**：承接
[`2026-10-24-product-editor-two-pane`](2026-10-24-product-editor-two-pane.md)（抽屉两栏 + `fill-height` 的由来）、
[`2026-10-24-pointer-handles-and-occlusion`](2026-10-24-pointer-handles-and-occlusion.md)（同一条思路：
DOM 尺寸看不出来的事，要量"谁画到了哪里"）。这一轮只动右栏的高度分配与编码区的视野保障，
不动矩阵数据、不动保存路径。

## 一、先按"重叠"验，三个高度都没叠

用户说"遮挡"，第一反应是两个矩形相交。用假桥 + 无头 Chrome 在三种窗口高度下量了
`.mx`（组合区）与 `.ed-codes`（编码区）的位置：

| 视口（innerHeight） | 组合区底边 | 编码区顶边 | 第一行编码框命中测试 |
| --- | --- | --- | --- |
| 1440×900（813） | 582 | 590 | `INPUT.ed-codes__input` |
| 1200×700（613） | 382 | 390 | `INPUT.ed-codes__input` |
| 1000×620（533） | 302 | 310 | `INPUT.ed-codes__input` |

三条都不相交，命中测试也全是输入框自己 —— 因此**不是常规尺寸下的布局重叠**。

## 二、真因：`.mx--fill { min-height: 0 }` 允许它缩到 0，而内部内容不会跟着缩

`.mx` 是 flex 列，里面有三种子项：

- `.mx-spec`（规格区，`flex: none`，**按内容撑高** ~150px）；
- `.mx-bar`（「组合」标题行，~24px）；
- `.mx-wrap--fill`（表格容器，`flex: 1 1 auto` + `min-height: 140px`）。

父级 `.mx--fill` 写的是 `min-height: 0`（本意：让矩阵能被压缩、表格内部自己滚，别把整列顶高）。
但 `min-height: 0` 允许它**压到远小于自己内容的高度**：规格区与 140px 的表格容器仍按各自的高度
画出来，**溢出到 `.mx` 盒子之外**，而 `.ed-codes` 是按"压缩后的 `.mx` 高度"排版的下一个兄弟 ——
于是编码区被组合区**盖住**。叠不叠取决于"右栏可用高度 < 矩阵最小内容高度"，
小窗口 / 多色多码时才出现，所以默认 1440×900 的冒烟永远是绿的。

复现（把 `.ed-main` 的 `max-height` 压到 300px 模拟矮窗口），旧版实测：

```
detTop=177  detH=156  mainTop=47  mainBottom=347   scrollHeight=379
```

`detTop=177` 比"规格区 + 表格下限"应有的位置**小了一百多像素** —— 编码区被拉进了组合区里面；
`scrollHeight` 也只有 379（真实内容需要 557），因为它按被压扁的盒子算。

## 三、另一个成因（体感）：右栏是滚动容器，而 macOS 的滚动条默认不显示

编码区在 `.ed-main` 的**最后**，矩阵先把剩余高度全吃掉（`flex: 1 1 auto`）。展开后编码区落在
窗口下沿之外时，`.ed-main` 其实能滚，但滚动条是 overlay 的、静止时不画 —— 用户看到的就是
"点开了，可什么都没多出来"。这条不需要"重叠"也能成立，因此单独修。

## 四、四处改动

1. **`.mx--fill` 的 `min-height: 0` → `min-content`**（`SkuMatrixEditor.vue`）。
   矩阵最低缩到"规格区 + 140px 表格"；再不够就让右栏整体滚动。
   **不许叠在一起** —— 收缩能力的边界应当由内容决定，而不是"能缩多少缩多少"。
2. **`.ed-codes { flex: none }`**（`ProductEditorDrawer.vue`）。空间不足时不再被压成一条缝：
   展开是为了编辑，压扁等于没给这个入口。
3. **展开即入视野**：`onCodesToggle` → `revealInMain(el)`。
   `toggle` 派发时 details 已经展开完，同步量一次就够（再补一帧兜底异步内容）；
   顶部让开吸顶工具条（`.ed-main__bar`），并且**只有整块能塞进可视区时**才去追底边 ——
   比可视区还高时对齐顶边才对，否则会把标题滚走。
4. **`scroll-padding-top: 46px` + `scroll-margin-block: 46px`**：聚焦到编码框时浏览器自己滚，
   也不会停在吸顶工具条底下（那一瞬间看起来同样是"被上面的东西盖住"）。

## 五、守卫

`goods:ui` 的 `sku-code-rule` 步新增两条：

- 「展开的编码区在吸顶工具条下沿之后、第一行编码框没被上面的组合区盖住（命中测试是它自己）」——
  三种常规视口下都绿，守的是**重叠回来**（谁再把 `min-height` 改成 0、或给编码区加负 margin）。
- 「右栏空间不足时，展开编码区会把它自己滚进视野」—— 把 `.ed-main` 压到 300px 再重新展开，
  判据是 `scrollTop > 0`。这条是这次的**真守卫**：没有第 3 条改动时它恒红（实测 `scrollTop=0`），
  改完是 251。

变异核对：只回退 `min-height: min-content` ⇒ 第一条开始红（`detTop` 从 590 掉回压缩位置）；
只回退 `onCodesToggle` ⇒ 第二条红。

## 六、留给后来者

- `min-height: 0` 那条经验本身没错，但它的前提是**子项自己会裁切/滚动**。子项内部若有
  "按内容撑高"的块（这里是规格区、以及带 `min-height` 的表格容器），无限收缩就等于**让它画画**
  —— 画到谁身上取决于兄弟顺序。
- 判"有没有被遮挡"不能只判矩形不相交：元素自己盒子被压扁时，矩形不相交照样成立，
  它画出来的内容早就压到别人身上了。要么量**命中测试**，要么量"位置是否与 `scrollHeight` 一致"。
