## 1. 「拿货 › 要拿什么」整页重做成**卡片网格** + 「复制给厂家」

**结论**：用户给出设计稿（「拿货工作台」卡片网格）并选定「**整页重做卡片网格**」。四块一起落：

1. **顶部厂家筛选标签**（数 = 待拿款色数；只给有货要拿的厂家占位；「未指定厂家」是独立一档 `data-supplier="0"` ——它的货要能看到，但不该混进别家的筛选里；一个可筛的都没有时整行不渲染）。
2. **卡片网格**（`pk-grid`）：一张卡 = **一个款色** = 图（缺图画「缺图」占位）+ 厂家胶囊 + 尺码角标条（`L×2` = 这一码**还要拿** 2 件、`L✓` = 已拿完；tooltip 保留「需求 / 已拿 / 还差」）+ 四态标签（**已忽略 > 已拿完 > 缺哪一环 > 齐**，"已拿完"与"齐"分开说）+ 款名 + 卡面小计（`≈¥20.00` / 全无价 `—`）+ 单价（裸数字，后缀「元/件」挂在 `data-act` 外面）+ 行尾「忽略」。
3. **底部汇总条**（`pk-sum`，**吸底**）：一行一个厂家 = 「这家什么情况 + 复制发哪家 + 一键开单」；总账一行给「待拿 N 款色 · N 件 · 预估 X」。
4. **「复制给厂家」**：把**这一家**的待拿货画成一张 PNG 写进**系统图片剪贴板**（粘到微信直接发）。

**取证**：`pk-grid`（卡片网格）、`pk-sum`（吸底汇总条）、`data-supplier="0"`（未指定厂家独立一档）；尺码角标 `L×2` / `L✓`。

**源**：`2026-10-10-purchase-card-grid`（2026-10-10）

## 2. 网格是平铺的 ⇒ **排序必须全网格做**

**结论**：卡序 = 还要拿 → 已拿完 → 已忽略（同档内维持段序 + 件数降序）。本轮真踩：排序写在**段内**（收集时每段各排一遍），被段序盖过 —— 厂A 整段被忽略后，那张调暗的卡仍排在未指定厂家的待拿卡**前面**（`picking:ui` 一条断言当场红）。`Array.sort` 稳定，收集完再排一次即可。

**取证**：`picking:ui` 一条断言当场红（厂A 被忽略的卡仍排在未指定厂家的待拿卡之前）；修法为收集完再排一次（`Array.sort` 稳定）。

**源**：`2026-10-10-purchase-card-grid`（2026-10-10）

## 4. 「复制给厂家」是**图**不是文本；`write-clipboard-image` 的通道与它的 API 陷阱

**结论**：「复制给厂家」是图不是文本：厂家照图备货；纯文本粘进微信丢表格结构，截屏又会把页签、别家的货一起发出去。`src/lib/pickingSheet.ts` 的 `sheetModelOf`（走 `pendingOf`）+ `renderSheetPng`（canvas 2×）⇒ **屏上 / 发出去的 PNG / 导出 xlsx 是同一个数**（`money`/`amountText`/`noPriceNote` 三个措辞函数三方共用）。

**`write-clipboard-image` 是渲染层→主进程的图片通道**：主进程只做两件校验（dataUrl 前缀 `data:image/` + 8MB 上限）再 `nativeImage.createFromDataURL` + `clipboard.writeImage`。⚠️ **当轮真机实测即失败**：v44 已移除 `clipboard.writeImage`（这条写的 v33 时代 API），正确写法是 `clipboard.write([ClipboardItem + Blob])`，两条通道也已外提到 `electron/clipboard-handlers.ts`。⚠️ 主进程/preload 改动要**重启宿主**才生效（HMR 不覆盖）。

**取证**：主进程校验 dataUrl 前缀 `data:image/` + 8MB 上限；`nativeImage.createFromDataURL` + `clipboard.writeImage` 在 v44 已移除，正确写法 `clipboard.write([ClipboardItem + Blob])`，通道外提到 `electron/clipboard-handlers.ts`；详见 `docs/notes/2026-10-30-electron-and-platform.md`。

**源**：`2026-10-10-purchase-card-grid`（2026-10-10）

## 6. 实测纪律（剪贴板假桥 / 同格取证 / 反向夹具 / `dist`）

**结论**：
- **写剪贴板的假桥只能验"发出去的是什么"**（真写剪贴板在主进程）：断言载荷是 `data:image/png;base64,` 前缀还不够 —— 补一条**非空转**判据 `new Image()` 解码 `naturalWidth > 0`（画布不可用/空壳 dataUrl 会当场红）；失败分支 `__clipFail` 反向夹具，断言 toast 如实报「复制失败」（不装作已复制 —— 否则用户粘出的是上一张图）。
- **一张卡的两个判据钉同一格**：尺码格的文本（`L×2`）与 tooltip（三个数）必须同一个 `size-chip` 上取 —— 分开取或整卡拼串时"串位"不会红。
- **反向夹具 `__allTaken`**：已拿完的第四态要整条翻（卡调暗 `is-done` + 不再报金额 + 该厂家标签消失 + 汇总行说「已拿齐」）—— 只翻一处就是两套口径。
- `*:ui` 读 `dist/` ⇒ 先 `npm run build`；做完变异必须 rebuild 再跑最终门禁。

**取证**：`new Image()` 解码 `naturalWidth > 0`；失败分支 `__clipFail`；反向夹具 `__allTaken`（卡调暗 `is-done`、汇总行「已拿齐」）。

**源**：`2026-10-10-purchase-card-grid`（2026-10-10）

## 12. 守卫必须「几何 + 可达性」两条

## 14. 其它设计决定（都写进组件注释）

**结论**：
- **行尾两个文字链接是表格宽度的最大贡献者**（80px 列里竖排挤成三行、行高被顶到 77px）⇒ 改 **SVG 图标按钮**（↻ 取最近价 / ✕ 删本行）：不赌字体字形渲染（`↻` 字符在无头渲染有豆腐块风险），`title` + `aria-label` 兜底语义与可发现性。（⚠️ **本决定同日被用户反馈推翻**，见 §15。）
- **两行并一行**：日期（原 `label` 两行）+ 提示句（原单独一行、含「共 N 行」）合成一行工具条；「共 N 行」移到页脚与合计并列（**包价单不加** —— 它没有"行"的概念，写「共 0 行」是错的）。

## 15. 【历史记录】图标按钮改回**文字动作** —— 应用惯例是 `.wb-link`

**结论**：【历史记录】上文"改 SVG 图标按钮"一条**已被本反馈推翻**：用户"完全不知道是什么意思"（图标语义不自明，`title` 要悬停才可见）。用户原话：「拿货单中的款色和尺码为什么要用输入框的样式？现在操作区的两个按钮完全不知道是什么意思。」⇒ 改回**文字**：「取最近价」「删除」，用 `.wb-link` / `.wb-link--danger`（与「拿了什么」列表的行尾动作同一套惯例）。

## 16. 身份数据去「输入框样」= 幽灵输入框（默认像文字 / 悬浮出框 / 聚焦还原）

**结论**：**判据是"这格是谁在说话"**：款编码 / 颜色 / 尺码是清单带过来的**身份数据**（人只偶尔修正），每格都画边框会让整行被读成"这里有三个框等我填"；实拿 / 单价才是"等你填"的字段。实现 `.pue__ghost`：默认 `border-color / background-color: transparent`；`:hover` 出一条 `--wb-border`（提示"可点"）；`:focus` 还原完整输入框（`--wb-focus` 边框 + 3px 焦点环 + `--wb-surface-2` 浅底）。**改的是外观不是能力**：手工加行、现场改色仍要能输入 —— 没有任何编辑能力被撤。

**取证**：`.pue__ghost` 三段状态；`--wb-focus` 边框 + 3px 焦点环 + `--wb-surface-2` 浅底。

**源**：`2026-10-10-purchase-editor-rework`（2026-10-10）

## 18. 模板字符串转义陷阱（本轮多连踩，含"注释反引号"与"正则被剥")

**结论**：`today-ui-smoke.mjs` 的浏览器侧代码整段嵌在模板串里 ⇒ **正则与注释都是字符串内容**：
1. 新守卫里用正则比颜色（`/rgba\(0, 0, 0, 0\)|transparent/`）：`\(` 在模板串里被剥成 `(` ⇒ 正则实际去找字面量「rgba0, 0, 0, 0」⇒ **恒不命中**。症状极像"实现坏了"：诊断串里 `code=rgba(0, 0, 0, 0)` 明明是对的。**修法：不用正则，改字符串相等**。
2. 为解释 ① 写的注释里又出现 `\(` ⇒ ESLint `no-useless-escape` **error**（注释在模板串里按字符串内容判转义）。**修法：注释里不写反斜杠。**

这是本仓「模板串内转义」族的又一次现形（同族既有事故：注入脚本注释/断言里的反引号）。**在该脚本里写正则 / 注释前先问一句：这段文本自己带着转义吗？**

**取证**：`/rgba\(0, 0, 0, 0\)|transparent/` 被剥成找字面量「rgba0, 0, 0, 0」；ESLint `no-useless-escape` error。同族另一例（`picking:ui` 那轮）：`FAKE_BRIDGE` / `ASSERT_SCRIPT` 注释里的反引号又踩一次，`node --check` 报的是文件中部 `Unexpected identifier 'lib'`（离真因就是那句注释），排除方向容易被带偏 —— 改完先 `node --check`（`npm run picking:ui` 的 npm script 已带）；写注释时用 `lib/pickingSheet` 这种不带反引号的写法。

## 20. 「模式」(mode) **保留**：它有两条互不相同的真实下游行为

**结论**：用户问「拿货单列表展示图片、款色、尺码、建议、实拿、单价、金额。**模式是什么？备注的意义是什么？** 如果没有可以去掉，界面尽量简洁，不要过度设计」。逐条溯源后裁决：**模式（mode）保留**（有两条真实下游链路）。`mode`（`detail` 明细 / `package` 包价）：
- `detail`：金额 = Σ(实拿 × 单价)，行**参与**拿货缺口扣减与成本同步；
- `package`：只记总额，**只参与厂家对账**（`reconciliation` 读 `total_cents`），不扣缺口、不进成本。

⇒ 之前它是编辑器里的一个表单格，但 `purchase-order-update` **不接受 mode**（创建时定死）——给一个"改不动的下拉框"是**假动作**。改成页头**只读标签**（`pue-mode-tag`，措辞与列表逐字一致），界面更简、语义不减。

**取证**：`detail` 金额 = Σ(实拿 × 单价)；`package` 只参与 `reconciliation`（读 `total_cents`）；`purchase-order-update` 不接受 mode ⇒ 改 `pue-mode-tag` 只读标签。

**源**：`2026-10-10-purchase-note-removal`（2026-10-10）

## 22. 删列的纪律 = 「新增列两处都要动」的**镜像**

**结论**：`AGENTS.md` §1.4 的纪律「新增列必须同时写进 `CREATE TABLE`（SCHEMA）与迁移」**删列一模一样**：`IF NOT EXISTS` 对已存在表一个字都不改 ⇒ **只删 SCHEMA 或只写迁移都会让新旧库形状分叉**。
- `purchase.main` **v1** 迁移（`electron/purchase-db.ts` `dropOrderNote`）：`PRAGMA table_info` 查到 `note` 就 `ALTER TABLE ... DROP COLUMN`（SQLite 3.35+）；查不到（新库、表还不存在）直接跳过 —— **迁移跑在 `dbMigrate(SCHEMA)` 之前**（house convention），每一步都必须处理"表还不存在"。
- `ensurePurchaseSchema()` 的顺序：`migrate('purchase.main', steps)` **先** → `dbMigrate(SCHEMA)`（已无 note）的新库路径一次建到当前形状。
- **老库删列后必须实测建单路径**（本轮冒烟场景 F 第四条）：列删了但 INSERT 还写它 ⇒ 老库上任何建单必抛（同 `oi_styles.name` 的删法事故）；"数据一条不丢"与"能建新单"是两件事，都要断言。

**取证**：`ALTER TABLE ... DROP COLUMN`（SQLite 3.35+）；`purchase.main` = v1；场景 F 第四条实测建单路径。

**源**：`2026-10-10-purchase-note-removal`（2026-10-10）
