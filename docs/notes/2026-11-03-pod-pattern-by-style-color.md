# 认图案的身份是「款色」，不是「图」（图案并入订花纸）

> 取代关系：**不取代** [净需件口径](2026-11-01-pod-need-single-source.md)（那是"报多少张"怎么算）。
> 本文只讲"哪一行属于哪个花纸图案"这件事的身份与入口。入口合并的用户口径见
> `CHANGELOG.md` 的同日条目（原文照录）。

## 结论

1. **匹配顺序 = 款色 → 图片指纹 → 变体键**，唯一实现在 `src/lib/podNeed.ts` 的 `podPatternResolver`。
   第一级是 `pod_style_color_patterns`（`style_color_id` 主键 → `pattern_id`），键取
   `oi_style_colors.id`（= `oi_order_items.style_color_id`）—— 它跨店铺、换商品图、改色名都稳定。
   指纹是**图**的身份：一张图被两个颜色共用时，按图认会把两个色认成同一朵花（用户报错的那种），
   所以它只能兜底。
2. **款有几个图案是算出来的，不存第二份**。一个款的图案集合 = 它的颜色认到的不同 `pattern_id` 个数。
   三个颜色共用一朵花 ⇒ 一条记录；两种花 ⇒ 两条。另存"款 → 图案列表"必然与款色表漂移。
3. **图与款色同一次调用、同一个事务**（`podImageLink({ patternId, images, styleColorIds })`）。
   分两次写的话，中间失败会留下"图认上了、款没记住"，而界面照样显示认好了。
4. **入口只有一处**：`基础数据 › 产品管理 › 图案` 已撤（`PatternPanel.vue` 删除），
   认图案 / 要订什么 / 花纸库存在「发货台 › 订花纸」一页里。
5. **合并（N→1）要搬四样**：识别图、颜色槽位、款色、花纸批次。少了款色这一样，
   合并后"同款下次自动带出"就断了，而识别图搬得好好的 —— 从界面看不出来。

## 三条会静默出错的判据

| 做法 | 症状（都不报错） |
| --- | --- |
| 只按图认、不写款色 | 同款换了 SKU 图就认不出；页面照样写「已认好」。用户第二天再来一遍 |
| 把"款 → 图案"另存一张表 | 与 `pod_style_color_patterns` 两处漂移；哪一处先写取决于点击顺序 |
| 用色名 / 款号当键 | 改名即失联（本品类已有三次实证，见工程铁律第 1 条） |

## 键盘流：并页重写最容易静默丢掉的一层（本轮实发）

- **现象**：并进订花纸时，新写的 `PodOrderPanel.vue`（2136 行）全文没有 `keydown` / `tabindex`，
  而方案 T3-7 的验收判据是「连续绑 24 个槽位不出鼠标」。旧 `BindingPanel.vue`（已归档）有整层 `keydown`。
  **重写页面时交互层会无声消失** —— 没有编译错、没有测试红，只有用的人发现"键盘全废"。
- **怎么钉**：`today:ui` 五条 —— 提示在页面上 / `Space` 选中 / `Esc` 清 / `↓` 换色后选中的是**第 2 格** /
  数字键按 `2` 得到 P002。第四条是关键：「按了空格有反应」用坏实现（永远认第一格）也能绿，
  只有"作用在第几格"能证明游标真的在走。三次变异复核（禁用 ↑↓ / 数字键恒取第一个 / 删占位项）都变红。
- **⚠️ `KeepAlive` + `window.addEventListener('keydown')` 会串页签**：本页在 `TodayView` 的 `<KeepAlive>` 里，
  切走**不卸载**。必须 `onActivated` 挂 / `onDeactivated` 摘；本仓还在 `onMounted` 也挂一次（同一函数引用
  会被事件系统去重）—— 将来谁把 `<KeepAlive>` 摘了，键盘流也不会静默失效。
- **两道让路**：焦点在 `INPUT/TEXTAREA/SELECT/contentEditable` 时全放行；焦点既不在左栏也不在 `body` 时
  不抢键（否则"点右栏的复制"再按 ↓ 会变成给颜色换款）。

## 「看不清图」和「文案太多」：两个都是判据问题，不是审美问题

- **缩略图 `object-fit: cover` 会把判据裁掉**：颜色 chip 的图框是 82×56（宽扁），方图 cover
  后上下各切掉约三成 —— 一朵花的花瓣正好在切口上。而这页唯一的判断动作就是「这两个色是不是
  同一朵花」。**图片的裁剪方式要按"看图的人要拿它判断什么"来定**，不是按"填满格子好看"。
  改 `contain`（整朵都在，小一点但完整）。
- **放大必须给"不缩放"模式**：`max-width:100%` 的弹层只是"装得下"，不是"看得清"。
  给一个 1:1 切换（放开 max-width/max-height + 容器滚动）才是真放大；
  **别用 CSS `zoom` / `transform: scale` 放大位图** —— 那是插值，越放越糊，等于没放大。
- **放大不能顺手改单**：角标必须是 chip 的**兄弟节点**（`<button>` 里不能嵌 `<button>`，
  嵌了以后空格会同时触发"选中"和"放大"，读屏也读不出来），且只压缩略图右上角 24×24。
  断言钉的是「放大后 `is-sel` 一张都没变」——"能弹出图"用坏实现（顺便 toggle 一下）也绿。
- **说明文案收进「?」时，断言要两头钉**：① 常驻区**干净**（`.po-lead` / `kbd-hint` 都不在
  面板内）② 问号里**东西没少**（口径 + 每个键 + 放大说明）。只断言"问号能弹出"是空的也能绿。
- **弹层开着时"全页只认 Esc"这条要一起改**：新增一个弹层忘了加进 `onKeydown` 的弹层分支，
  Esc 会**穿过弹层**去清空选择 —— 人以为关掉了、其实还在，之后每次按键都被吞，
  表现为"键盘失灵"。四个弹层（大图 / 新建 / 合并 / 说明）现在在同一处判。
- **又一次同形态的假红**：`Z` 之后只等「IPC 被调用」就去点关闭 —— 请求发出时弹层还没渲染，
  `querySelector` 拿到 `null`，没关成，后面的数字键全被吞。**等状态，不等"调用发生过"**
  （同一句话本日已经踩到第三次）。

## 本轮另外三个坑

1. **`select` 的 `v-model` 初值没有对应 `option` ⇒ 显示与状态不一致**：合并弹层"保留哪个"初值 0，
   options 是 1/2，浏览器**显示** P001、`v-model` 仍是 0 ⇒「合并」按钮灰着。界面说"选好了"、按钮说"没选"。
   修法是加占位 `option`（`value=0` disabled），**不是**默认选第一个 —— 合并方向必须用户明确指定。
2. **断言抢跑的两种形态**（都不是实现坏，但都表现为 15s 超时）：
   ① 回执写在 `await refresh()` **之前** ⇒ 一看到回执就点按钮时它还 `disabled`（`disabled` 元素的 `click`
   不派发事件）；② `podImageLink` 已调、行内表单还没收 ⇒ 此刻按 `M` 被当成"弹层中"只认 `Esc`。
   判据：**等状态（按钮可用 / 表单消失），不要等"上一次调用发生过"**。
3. **`rowNav` 偶发**（未提交的新功能）：`void nextTick(...)` 会把微任务带进下一条用例 ——
   全量首跑 1 红、单跑 16/16 绿、复跑 1440 全绿。见到"复跑就绿"的，先记下来，别把"再跑一次"当修复。

  灰那一色**故意没有指纹**，所以「认上」的载荷里 `images: []`、`styleColorIds: [103]`
  （断言钉在这里：漏送款色时页面不报错，只有这条能红）。
- 数据层冒烟：`npm run pod:smoke` 的 **[11] 款色 → 图案** 6 条（只给款色也能认 / 改指报
  `movedStyleColors` 且库里仍一行 / 按款色撤销幂等 / 都不给要报错 / 合并搬款色 / 撤销搬回）。

  的「一次 ensure 建齐」数（本轮由**七表改八表** —— 它当时就把这次改动报红了）。
- 真库实跑口径未变：`npm run pod:worklist -- --expect 560,50`（款色层是**新增的**一级，
  老槽位/图片绑定照旧能认，覆盖率不会因为这一级先掉下去）。
