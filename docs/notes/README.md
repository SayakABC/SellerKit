# 结论笔记（docs/notes）

**给谁看**：下一个接手的人或 AI 工具。本项目会被多个工具交替打开（WorkBuddy / Qoder / Hermes…），
它们的会话记忆各自留在本机私有目录里，**互相看不见、`git clone` 也带不走** —— 所以凡是"下次开工还得记得"的
结论，必须落进本目录。

**放什么**：跨会话仍成立、且**别人也要知道**的结论 —— 门禁怎么跑、哪个坑踩过、哪条约定不能破。

**不放什么**：变更史（去 [`CHANGELOG.md`](../../CHANGELOG.md)）、设计方案与审查（去 `docs/plans` / `docs/reviews`）、
按天的流水（那是工具私有草稿，随它去）。

## 命名与格式

- 文件名 `YYYY-MM-DD-<小写短横线 slug>.md` —— `npm run verify:docs` 会校验，不合规直接失败。
- 正文先写**结论**，再写**取证**（可复现的命令 / `文件:行`）。**没有取证的结论不要写进来**。
- 一条笔记一个主题，不要追加成流水账；内容变了就新开一条并注明取代关系。

## 与工具私有记忆的关系

|              | `docs/notes/` | 工具私有目录（`.workbuddy/memory/` 等） |
| ------------ | ------------- | --------------------------------------- |
| 入库         | ✅ 随 git 走  | ❌ 换机器即失效                         |
| 其他工具可见 | ✅            | ❌                                      |
| 性质         | **权威结论**  | 草稿 / 日流水（可以重复、可以更碎）     |

同一条结论两边都有时，**以 `docs/notes/` 为准**。私有目录可以继续写，但**只有本目录里的才算数**。
