> 设计：UI Designer ｜ 日期 2026-11-04 ｜ 可视稿：[`docs/mockups/ANALYTICS_2026-11-04.html`](../mockups/ANALYTICS_2026-11-04.html)
> 对象：`src/modules/order-cost`（模块 id 保留，显示名「统计」→「经营分析」）
> 依据：本机只读数据盘点（5 单 / 0 结算 / 307 条账本 / 21 款 481 变体）+ `src/styles/index.css` 令牌审计 + `docs/plans/UI_DESIGN_PROPOSAL_2026-11-03.md` 五条原则
> 状态：**方案稿，未改任何代码**

---

## 0. 一句话结论

**这一页最大的设计问题不是"放什么图"，而是"数据还不够时页面长什么样"。**

现有数据下，任何一张漂亮的利润报表都只能显示 5 单、成本覆盖 0%、结算 0 条 —— 用户看到的是"一屏精致的空"。
所以本方案把**可信度做成一等公民**：每个数字自带口径、分母与覆盖率，缺数据处记 `—` 并给出口；
页面按"当前能算的"自动重排，算不了的能力**收成一行**而不是摆 4 张空卡。

视觉上沿用 2026-11-03 已定的纪律：**一个颜色都不加**，只靠级差、留白与一处发声。

## 1. 落地价值评估

### 1.1 评分模型（为什么不是"能做的都做"）

单看"能不能算"会得出错误排序 —— 广告 ROI 也算得出来（只是没数据）。
故分两个分：

```
潜力分 = 0.4 × 可行动性 A + 0.3 × 决策频率 F + 0.3 × 结论可信 C   （补齐数据后值多少）
落地分 = 潜力分 × K(数据就绪 R)      K: R5→1.0  R4→0.9  R3→0.7  R2→0.4  R1→0.15
```

`K` 是**乘数不是加分**：没有数据的能力，再有用也落不了地，不给它"平均分"。

### 1.2 打分结果（按落地分排序）

| # | 能力 | A | F | C | 潜力 | R | **落地** | 判定 |
|---|---|---|---|---|---|---|---|---|
| 1 | **数据体检 / 可信度层** | 5 | 5 | 5 | 4.7 | 5 | **4.7** | P1 首屏 |
| 2 | **店铺资金卡（账本口径）** | 5 | 4 | 4 | 4.4 | 5 | **4.4** | P1 首屏 |
| 3 | **商品档案缺口（成本/克重/认款）** | 5 | 3 | 5 | 4.4 | 5 | **4.4** | P1 首屏 |
| 4 | 待发 / 超时（单条级） | 5 | 5 | 5 | 4.7 | 4 | **4.2** | P1 只做计数+跳转（详情归发货台） |
| 5 | 采集与认款健康 | 4 | 3 | 4 | 3.7 | 5 | **3.7** | P1 并入商品页签 |
| 6 | 款级毛利排行 | 5 | 3 | 3 | 3.8 | 2 | 1.5 | P2（成本覆盖 ≥90% 才开） |
| 7 | GMV / 趋势 / 环比 | 3 | 4 | 4 | 3.6 | 2 | 1.4 | P2（需 `order_date` + 回填） |
| 8 | 店铺排行（收入/毛利） | 4 | 3 | 3 | 3.4 | 2 | 1.4 | P2 |
| 9 | 价格带 / 盈亏平衡价 | 4 | 2 | 3 | 3.1 | 2 | 1.2 | P2 尾 |
| 10 | 结算净收入 / 平台费 / 退款率 | 4 | 3 | 5 | 4.0 | 1 | 0.6 | **P3，但一导入就值 4.0** |
| 11 | 待放款 / 现金流 | 4 | 3 | 4 | 3.7 | 1 | 0.6 | P3 |
| 12 | 采购缺口 / 供应商欠款 | 3 | 3 | 4 | 3.3 | 1 | 0.5 | P4 |
| 13 | 利润桥（瀑布） | 2 | 2 | 4 | 2.6 | 1 | 0.4 | P4，且必须两轨并排 |
| 14 | 广告 ROI / 曝光 / 转化 | 5 | 4 | 5 | 4.7 | 1 | 0.7 | **不属本项目**：另起数据接入 |

> 第 14 行是关键提醒：它潜力分 4.7（和第一名一样高），但落地分 0.7。
> **把它画进这一页 = 画一个永远空的图**。要做先接 AE 数据纵横/广告后台导出，是独立项目。

### 1.3 四档落地结论

**A 档 · P1（现在就能上线，本机有真实数据）**
1. 数据体检（9 项覆盖率 + 受影响收入 + 补数据顺序）
2. 店铺资金卡（13 店 × 12 个月账本：流入/流出/结余/公摊/科目结构）
3. 商品档案缺口（成本 17/21、克重 365/481、认款 64/71）
4. 待发/超时计数（只出数与跳转，不在统计页做发货）
5. 采集健康（链接数、认款率、采集陈旧）

**B 档 · P2（补 `order_date` + 订单回填 ≥30 单后有决策价值）**
GMV/订单/AOV 趋势与环比、店铺排行、款级毛利、价格带。

**C 档 · P3（结算导入后从 0.6 跳到 4.0）**
净收入、八类平台费、退款率、待放款、精准轨毛利。

**D 档 · 不做（无数据源或做了会误导）**
| 不做 | 原因 |
|---|---|
| 曝光/点击/转化/广告 ROI | 无数据源；接了也是另一个项目 |
| 竞品比价 | 无数据源 + 抓取合规风险 |
| 库存现存量 | 现在只有"需求 − 已拿货"缺口，不是库存，叫库存会误导补货 |
| 复购率 / LTV / 人群 | 无买家标识，且 5 单样本毫无意义 |
| 单一"总利润"大卡 | 三本账不可相加（见 §3.1） |
| 环形图/饼图做科目结构 | 13 个科目，饼图不可读；用排序条形 |
| 12 个 KPI 平铺 | 超过 6 个就没有焦点（2026-11-03 原则 1） |

### 1.4 速卖通口径的四个坑（页面必须写死，否则算出来也是错的）

1. **保证金不是费用**。5 万保证金是资金占用，记进"费用"会把某月净利做成巨亏。
2. **提现不是收入**。账本收入科目里几乎全是"店铺提现"，那是资金搬运。
3. **平台费 ≈ 9.14%**（代码注释里的实测值，277 行剔除全额退款）。没有结算数据时只能"近似"，页面必须显示"按 9.14% 近似"而不是装作精确。
4. **运费由克重 × 国家决定**。克重缺 116/481 ⇒ 这部分订单的运费只能是估，毛利必须标"含估算运费"。

结论：账本只出**资金结余**（现金口径），不出利润；利润要么等结算，要么标"预测"。

## 2. 用户与场景

### 2.1 三个真实决策（页面存在的理由）

| 决策 | 频率 | 现在能不能答 | 靠哪块 |
|---|---|---|---|
| 今天必须发哪几单、会不会超时 | 每天 | **能**（有 `deal_deadline`） | 待发/超时计数 → 跳发货台 |
| 这个月钱够不够、哪家店在流血 | 每周/每月 | **能**（账本 12 个月） | 店铺资金卡 |
| 哪款在赚钱 / 该不该提价 | 每月 | **不能**（成本 0/5 单） | 先补成本与克重 → P2 才出结论 |

第一版就按这个顺序排：**能答的排前面，不能答的收成一行并说清缺什么**。

### 2.2 用户习惯（8 条，逐条对应设计）

| 习惯 | 设计回应 |
|---|---|
| 按店铺思考（13 家店，多店并行） | 全局店铺筛选 + 店铺页签一行一店 + 排行表常驻 |
| 先看钱、再看量 | 4 张"钱"卡在上，"量"条在下 |
| 环比是刚需（跟上周/上月比） | 环比固定在数字下方（较上期 +1.9pt），不做成单独一列 |
| 不信汇总，要能钻到明细 | 每个数字可点 → 筛明细 / 跳对应页 |
| 要导出，自己再算一遍 | 表头右侧「导出 CSV」，带筛选条件与口径列 |
| 习惯右侧抽屉看详情 | 体检、口径说明都用 `.wb-drawer` / 浮层，不跳页 |
| 说人话，不用财务术语 | 成交额(GMV)、待放款(应收)、拿货成本(COGS)、资金结余(不等于利润) |
| 讨厌空页 | 空态必须写"缺什么 + 去哪补"，且给按钮 |

## 3. 设计原则（出现分歧时用它裁决）

1. **先可信，再好看** —— 数字旁边必须有口径与分母；没有分母的数字不上屏。
2. **缺就写 `—`，不写 0** —— 0 是一个结论，缺失是另一个事实。
3. **三本账只并排不相加** —— 预测 / 结算 / 现金各自成块，同屏不出现跨口径合计。
4. **一处发声** —— 同屏只有异常清单用警示色；覆盖率不足用灰条+文字，不用红。
5. **稀疏不连线** —— 数据点不足时只画孤点，不画趋势线（连线本身就是"有趋势"的暗示）。
6. **能力降级而非空卡** —— 算不了的模块收成一行"3 项暂不可用 · 缺结算"，点击进体检。

## 4. 信息架构

### 4.1 导航落位

- **保留模块 id `order-cost`**（路由 / 存储命名空间 / `importSheet.ts` 三处深链 / `TodayView` 跳转 / 冒烟锚点全靠它）。
- 只改显示名：`meta.name: '统计' → '经营分析'`；`src/modules/today` 的「算钱」文案、`importSheet.ts` 说明、`PROJECT_BASELINE.md` 命名空间表同批改。
- 侧栏位置不变（`order: 4`），图标沿用 `chart`。

### 4.2 一屏四页签

```
┌ 页头：经营分析 / 一句说明            [导出 CSV] [刷新] ┐
├ 筛选条（sticky）：时间段 | 店铺 | 来源 | 口径 | 成熟度徽标 ┤
├ 页签：经营总览 · 店铺经营(13) · 商品表现(21) · 资金与履约 ┤
│                                                          │
│  经营总览   总量 4 卡 + 量/风险条 + 趋势 + 排行 | 异常      │
│  店铺经营   一行一店（9 列 4 组）+ 行展开（趋势/科目/Top）  │
│  商品表现   款/SKU 表 + 价格带（平衡价竖线）               │
│  资金与履约 三本账 3 卡 + 利润桥 + 履约 + 结算             │
└ 口径脚注条（一条虚线框，写清三个公式 + "缺数据记 —"）      ┘
```

**为什么用下划线页签而不是 `.wb-seg`**：`.wb-seg` 的语义是"同一份数据的互斥视图"（待认/已认）。
这 4 个页签查的是**四张不同的事实表**（订单 / 店铺 / 商品 / 结算+账本+采购），用 seg 会让人以为是同一批数据换个看法。

### 4.3 能力降级布局（本方案的核心结构决策）

总览首屏按"当期可用能力"渲染，模块顺序固定为 `结论 → 量 → 趋势 → 排行/异常`，但：

| 当… | 则… |
|---|---|
| 订单 < 30 单或成本覆盖 < 60% | 顶部出现一条"现在只能回答 3 个问题"说明条，毛利两卡显示 `—` 并给出补数据出口 |
| 结算 0 条 | 「结算净收入」卡显示 `—` + "结算 0 条 · 导入后出数"；资金页签的结算面板显示空态（不是空表） |
| 全部缺（新装） | 只留体检 + 空态，页签置灰并给"先导一单试试"入口 |

⚠️ **不采用**"把空模块整块删掉"：用户会以为功能没做。收成一行 + 出口，是"有但暂时算不了"的正确表达。

## 6. 组件规范

### 6.1 口径徽标 `.wb-cal`（新增到 `@layer components`）

三本账的身份牌，**描边不填色**（颜色留给异常）。

| 变体 | 边框 | 用途 |
|---|---|---|
| `预测` | 1px 实线 `--wb-border-strong` | 订单口径 |
| `结算` | 1px 实线 | 平台口径 |
| `现金` | 1px **虚线** | 账本口径（"这不是损益"） |

规格：高 16、`padding: 0 5px`、字号 10.5、圆角 4。**不放进岛令牌清单**（纯 CSS 组件类，不涉及 `var()` 跨进程注入）。

### 6.2 KPI 卡 `.an-kpi`

```
┌─────────────────────────────┐
│ 成交额  [预测]              │ ← 11.5 muted + 口径徽标
│ ¥386,420                    │ ← 20/600 tabular（Hero 26/600）
│ ▬▬▬▬▬ 覆盖 100% · 1,240 单  │ ← 44×3 覆盖率条 + 10.5 muted
└─────────────────────────────┘
```

- **整卡是一个 `<button>`**（点开口径卡），`aria-haspopup="dialog"`。
- 状态四态见 §7；`—` 用 `--wb-text-muted` + 500 字重（**不要**变红）。
- 覆盖率条：`width = round(cov × 44)px`；`< 90%` 用 `--wb-warning` 填充，`≥ 90%` 用 `--wb-accent`。
- Hero：**每屏只有一个**，由口径开关决定谁是主角（切到结算口径时，「结算净收入」升 26px，「成交额」降 20px）。

### 6.3 口径卡 `.wb-pop`（本方案最有价值的一个零件）

点任意数字 → 浮层回答"这数怎么来的"：

```
毛利 [预测]
公式   收入 − 商品成本 − 运费 − 税 − 平台费（近似）
取数   oi_orders × pl_products × sr_rate_snapshots
样本   5 单 / 6 行 · 覆盖率 0%
更新   2026-11-02 23:14
⚠ 成本 5/5 单缺失 → 该值不成立，显示为 —。补成本后自动重算。
```

规则：
- `role="dialog"` + `aria-modal="false"`；Esc 关闭；关闭后焦点回到触发卡。
- 点浮层外关闭；浮层内可 Tab 到"看明细"。
- **"已知缺陷"一栏是必填的**，没有缺陷也要写"无" —— 这一栏是可信度的证据。

### 6.4 趋势图

- 1.6px 折线（`--wb-primary`），无面积填充（深色下 6% 白底会变成一块灰砖）。
- 网格：仅 3 条水平虚线（`--wb-border`，`2 4`）+ 基线；无纵向网格。
- x 轴标签每 5 天一个，**首末改 `text-anchor` 防贴边裁切**。
- **缺口处理**：整体连续时用虚线连接（`3 4`，45% 透明）；**数据稀疏（< 7 天有值）时只画孤点、不连线**，点用 muted 色。
- 悬浮：十字线不画，只出 tooltip（日期 / 值 / 环比）。
- 空态：图区中央一块虚线框"趋势暂不可用 —— 5 天里有数据，日趋势要连续 7 天以上，目前只能看总量"。

### 6.5 排行表 / 店铺表

- 列组用 `border-left: 1px var(--wb-border)` 分隔 + 组间额外 4px padding（**不用双行表头**：sticky 双行表头在横滚时对不齐）。
- 列宽用 `<colgroup>` 固定数字列（96–112），店铺列 `auto` —— 否则数字列被拉宽，金额离标签很远。
- 店铺行点击展开：下方插 `<tr class="detail-row"><td colspan=9>`，内含三块（近 30 天柱 / 科目结构条 / Top 款列表），`padding: 12 14 14`，底色 `--wb-surface-2`。
- 行展开**只允许一行同时展开**（再点收起）。

### 6.6 异常清单

- 每行：6px 严重度点（高 → `--wb-warning` + 3px 光晕；中 → `--wb-border-strong`）+ 主文案 12.5 + 后果句 10.5 + 右侧「去看」按钮。
- **不用数字序号**：`1 1 2 2 3` 会被读成"第几条"，而它表达的是严重度。
- 同根因合并（沿用 2026-11-03 的裁定）：一条给数量、一条给后果、一个出口。
- 最多 5 条，第 6 条起收进「全部 9 条 ›」。

### 6.7 数据体检抽屉

四段：① 成熟度轨道 L0–L4（实心 = 已就绪 / 斜纹 = 部分 / 空 = 未接入）② 覆盖率表（9 行：名称 / 条 / `62% · 1128/1820`）③ 补数据顺序链（编号 + 解锁什么）④ 最近更新时间。
底部两个动作：导出缺口清单 / 去补数据。

### 6.8 利润桥（瀑布）

- 仅在**同一口径内**画：预测轨与结算轨用同一面板切换，**不并排在同一坐标里**。
- 合计柱 `--wb-accent` 55%，扣减柱 `--wb-warning` 40%；柱顶数值 `¥386.4k` / `−16.2k`（万元以下保留一位小数）。
- 段间连接虚线只连"上一段结束高度"到"下一段起点"（瀑布语义）。
- **数据不足时画空态，不画断桥**（断桥比没桥更误导）。

## 7. 四态矩阵（这是本方案与普通报表页最大的差别）

| 模块 | 有数据 | 样本不足 | 无数据源 | 出错 |
|---|---|---|---|---|
| KPI 卡 | 数字 + 覆盖率条 | 数字照显 + 灰标「样本 5 · 仅供参考」+ **不进排行、不出结论** | `—` + "结算 0 条 · 导入后出数" + 入口 | `—` + "读取失败 · 重试" |
| 趋势 | 折线 | 孤点 + 中央说明框 | 空态 + 导单入口 | 空态 + 重试 |
| 排行表 | 排序 + 行展开 | 只列有单的店 + "其余 10 家本期无单" | 同左 | 空态 |
| 异常 | 5 条 + 全部 | 只留"补数据"类 | "暂无可判断项" | "无法生成" |
| 结算面板 | 5 行表 | — | 空态 + 导入按钮 | 空态 |
| 利润桥 | 7 段瀑布 | — | 空态 + "缺 3 环" | 空态 |

**阈值（可配置，写在一处）**：订单 ≥ 30 单才出毛利率结论；成本覆盖 ≥ 90% 才出款级毛利；结算 ≥ 50 单才出退款率结论（分母必须是**已结算订单**）。

## 8. 交互与键盘

| 操作 | 行为 |
|---|---|
| 时间/店铺/来源/口径切换 | 300ms 防抖，请求序号丢弃旧响应；页签切换**不重复取数**（按筛选条件内存缓存） |
| 点 KPI 卡 | 开口径卡（不跳页）；卡内「看明细」→ 筛明细 |
| 点异常项 | 直接筛出问题行，或跳对应补数据页（每项只有一个动作） |
| 点表格行 | 展开详情（店铺页）或进明细（款页） |
| `Esc` | 关浮层 / 抽屉；关闭后焦点归还 |
| `↑ ↓` | 表格移动当前行（复用 `useRowNav`，**不改变勾选**） |
| `Enter` | 行进详情 |
| `← →` | 页签漫游（roving tabindex） |
| `⌘ R` | 重新取数（与页头刷新同义，不做浏览器刷新） |
| 导出 | 表头右侧，导出当前筛选 + 当前口径列 |

动效：`150ms` 背景/边框、抽屉 `220ms`；`prefers-reduced-motion` 下全部关掉。

## 9. 无障碍

| 项 | 做法 |
|---|---|
| 对比度 | 全部走既有令牌（`--wb-text-muted` 5.2:1、`--wb-warning` 5.0:1，均 ≥ AA） |
| 不靠颜色编码 | 超时同时有「超时」文字；覆盖率同时有百分比；异常有严重度点 + 文案 |
| 图表替代 | `role="img"` + `aria-label`（"近 30 天成交额，5 天有数据"）+ 面板脚「看明细」文字通路 |
| 键盘 | 全流程可 Tab；KPI 卡是 button 不是 div；浮层 Esc 可关 |
| 焦点 | `:focus-visible` 2px 主色描边 + 2px offset（沿用 `.wb-btn` 约定） |
| 文字缩放 | 200% 下不出现横向滚动（数字列固定宽，店铺列 elastic） |

### 10.2 验收断言（必须可量，不能只断言"有这个 class"）

| 判据 | 断言 |
|---|---|
| 级差 | `getComputedStyle(hero).fontSize ≥ 1.4 × body` |
| 卡片等高 | 4 张卡 `offsetHeight` 全部 = 92 ± 1 |
| 覆盖率条 | `条宽 = round(cov × 44) ± 1` |
| **缺数据不是 0** | 空库下 KPI 文本匹配 `/—/` 且**不匹配** `/^¥?0(\.0+)?$/` |
| 三账不相加 | 页面内不存在同时包含「预测」与「结算」金额的合计节点 |
| 稀疏不连线 | 5 天数据时 SVG 内 `path[stroke-dasharray]` 数量 = 0（只有 circle） |
| 口径卡 | 点 KPI 后浮层出现，且含「公式 / 取数 / 样本 / 更新」四行 |

**变异点（改坏必须变红）**：① `—` 改成 `0`；② 覆盖率缺失时返回 100；③ 稀疏分支的 `!sparse` 去掉（连线回来了）；④ 结算与预测金额相加。

### 10.3 两个前置数据底座（方案成立的前提）

1. `oi_orders.order_date TEXT` + 索引 —— 否则日期范围筛选会静默漏掉 `08/30/2026` 这类美式格式。
2. `bk_categories.pnl_role` —— 否则"保证金/提现"会被算进净利。

> 这两条不改，页面的**日期筛选**与**净利**都不可信；其余视觉部分可以先做。

## 14. 本方案刻意不做的事
