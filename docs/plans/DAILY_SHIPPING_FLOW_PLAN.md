## 1. 实测：库里的真实状态

### 1.1 订单（157 行）的构成 —— 一半是"半残"的

- **115 行** 老采集数据迁移（`raw_fields = {__migratedFrom:'ae_orders', 采集帧}`）：无产品ID · 无图 · 未识别款 · 金额有值。
- **42 行** 芒果店长「待发货订单」导入（`raw_fields = 8 个中文列`）：有产品ID · 有图(42/42) · 未识别款 · **金额为 0**（待确认）。
- 识别队列 `oi_queue` **32 条全 `pending`** —— 识别从来没跑过。
- 订单店铺全来自「七店」（`sk_shops` 里共 6 家）。

⚠️ **两个待确认项（只读，未动库）**：① 芒果 42 行金额为 0（若走岛内导入链路可能跳过金额提取）；② 115 行采集帧能否重新展开成标准列。

### 1.2 颜色（"只能靠图"）—— 精确形态

`oi_orders.color` **填充率 157/157 = 100%**，但取值分布暴露真问题：`Picture color` 47 行、`Image Color`/`image color` 15 行（**共 62 行 = 39% 是"看图"占位**）；`black` 14 / `黑色` 12（同色异写）；`Beige` 19；其余中英文混杂。尺码规范（L/XXL/XL/M/XXXL/S/5XL）157/157 有值 —— 这块是好的。

**结论**：① 62 行"看图"占位 → 不看图无法知色；② 中英文混杂 + 同色异名 → 即使有值也可能指同一色。

### 1.3 商品ID 映射 —— 只需配 17 个

`pl_shop_sku` 仅 **3 行**（全 `spec='*'`、`product_id=1`）；芒果 42 行的 19 位速卖通商品ID 与映射表同套；**命中 26/42 = 62%**；去重后**17 个**商品ID。**配 17 次映射即可让全部 42 行拿到确定的"商品 → 产品"归属** —— 本次最省力、收益最高。

## 3. 三个点名问题（用实测回答）

### 3.1 商品ID 与厂家产品的关系 —— 怎么处理"比较方便"？

**两套归属链并行是全部问题的根源**：A. 商品ID 映射（`订单产品ID → pl_shop_sku → pl_products`，确定、不需识别、但拣货链不用它）；B. 视觉识别（订单图 → 视觉引擎 → `oi_styles.code → pl_products`，靠图猜、会错；识别队列 32 条全 pending = 等于没跑）。

**方便的形态：把映射从「产品级」升到「变体级」**（`商品ID + 规格 → 产品变体`），然后**拣货链优先查映射、识别降为兜底**。量小（仅 17 个 ID）、顺带解决颜色、识别出错面大幅缩小。

### 3.2 颜色只能靠图片肉眼区分 —— 出路

根因不是"没有颜色字段"，而是颜色没有"权威来源"（字段存的是平台原文 `Picture color` = "以图片为准"）。

**主路（够用）**：**让商品ID 成为颜色的权威源** —— 同一个商品ID 的颜色定一次，之后该商品所有订单自动带色（人工只做 17 次配对，而非每单看图）。**辅路（可选）**：建颜色枚举 + 按商品批量设色（`src/lib/colorSwatch.ts:18` 已有 16 色表可作枚举来源，顺手收敛 `black`/`黑色` 同色异写）。是否走辅路由你定（§7 G3）。

### 3.3 按进价算预估金额 —— 能算，且口径已被数据定死

| 来源 | 表/字段 | 粒度 | 实测 |
| --- | --- | --- | --- |
| **实际拿货价** | `purchase_items.price_cents` | 款 × 色 × 码 | ✅ 12 行有价 / 15 个款色码 |
| 成本映射 | `ae_cost_map.unit_price_cents` | 款 × 生效区间 | ⛔ **0 行** |

⇒ **口径不用你选**：`ae_cost_map` 是空的，**只能用 `purchase_items` 的拿货价**（按款色码取最近一次）。

**两个配套动作**：① **存量成本回填**：对已有 3 张拿货单跑一次 `syncPurchaseCosts` → 成本表有值；② **缺价要标出来**：新品/首次拿货无价 → 拣货单明确标「无进价」，**不按 0 蒙**。预估金额 = Σ(件数 × 单价)，与「算钱」页同源（`src/lib/orderCost.ts:429` `pickUnitCost`）。

## 8. 验收判据与门禁

**跑通判据**：选一天，从「今天」页导入 → 「拣货」页出清单（无未识别款噪声、每行有图有金额）→ 生成拿货单 → 提交后订单变已发货 → 「对账」页看到这家厂家的欠款 —— **全程不离开一个主线，且"同一条订单"在拣货页看到的金额/厂家，与成本页、对账页是同一个数**。

**门禁**（沿用基线，不改）：

- `npx tsc -p tsconfig.electron.json` / `npx vue-tsc --noEmit` / `npm run verify` / `npm run verify:docs` / `npx vitest run`
- 界面改动 → `npm run build` 后跑 `npm run <页>:ui` 假桥冒烟（`today:ui` 现有 **238** 项〔2026-10-12〕、`picking:ui` **84** 项〔2026-10-10〕）
- **导出的 xlsx 本身要单独验**：`npm run picking:xlsx:smoke`（读回产物：媒体扩展名、`[Content_Types].xml`、分表、空值、合计）
- **共享实现被覆盖 ≠ 调用点被覆盖**：`npm run purchase:xlsx:smoke`
- 新增断言一律**变异复核**，收工 `grep -rn MUTANT src/ scripts/ tests/`
- ⚠️ 门禁命令**逐条单独看退出码**，别串管道（`npm run build | tail` 会吞失败退出码）
- ⚠️ **"失败"必须证明退出码非 0**：`exit(1)` 之后再 `exit(0)` 会恒绿 ⇒ **同一段流程只调一次 `process.exit`**
- ⚠️ **状态/层级类改动，冒烟全绿也要拍图看一眼**（「当前步唯一」bug、S3「一件价都没查到却写 `预估 ¥0.00`」都是拍图拍的）
