## §0 结论速览

静态报告的结论是"工程层成熟、缺的全在包装层"。**真机走查推翻了这一点**：默认窗口尺寸下有 **4 个硬 bug**，其中两个让核心动线**物理上不可用**：

| # | 级别 | 一句话 | 用户看到什么 |
|---|---|---|---|
| **B1** | 🐞 bug | 左栏「已关联商品」**缓存永不刷新**（`ProductPane.vue` `loadLinks` 拉过一次——哪怕空数组——就不再拉） | 认款成功后右栏写「已关联 1」，左栏同一屏写「0 个店铺商品」，刷新按钮/重新展开都无效，只有重启应用才恢复 |
| **B2** | 🐞 bug | 「显示更多」**假动作**（判据 `groups > shown` 恒真） | 点了之后计数与行数纹丝不动，用户以为"坏了" |
| **B3** | 🐞 bug | 窄窗口（<1180px，**实测全新安装默认就落在这里**）左栏空态**溢出容器且被工具栏遮挡，点不到** | 新手首屏左栏只剩一个图标，"导入 Excel / 新增产品"按钮存在但点不着 |
| **B4** | 🐞 bug | **默认 1200×800 宽形态**下，右栏队列的「对比」按钮**被覆盖且超出视口右界——完全点不到**；「操作」表头被裁 | S3 刚建好的"对比"动线在默认窗口不可达 |
| **D1** | ⛔ 死锁 | 未归一提示**零可点元素**；全新安装**侧边栏没有「店铺账号管家」** | 提示让用户"先到店铺账号管家登记"，但这个入口在默认包里不存在，提示本身也不可点 |

**修正静态报告**：①"不需要重构、只包一层皮"要改为"**先修 4 个 bug，再包皮**"；②静态报告认为窄视口"两栏都在"即守卫成立（继承 `GOODS_WORKBENCH_PLAN.md` S4），真机证明**"都在"≠"可点"**——现有 110 条 `goods:ui` 断言全是按元素**存在**断言的，没有一条断言**可达**（`elementFromPoint` 命中）。

## §1 真机实证清单（每条带复现路径与根因）

### B1 · 两栏口径分裂（缓存 bug）

- **复现**：全新款（无映射）→ 展开左栏行（显示「已关联商品 0 个」）→ 右栏认款成功（弹层关闭、右栏指标变「已关联 1」）→ 重新展开左栏行，**仍写 0** → 点「刷新」、收起再展开，**仍写 0** → `Page.reload` 后同一位置正确显示「已关联商品 1 个」。
- **数据侧核实**：认款已正确落库（`pl_products` 新增一行、`pl_shop_sku.product_id` 指向它；WAL 模式）——**不是数据问题，纯前端缓存**。
- **根因**：`src/modules/goods/components/ProductPane.vue` 的 `loadLinks`（≈`:626`）：首次展开时拉取并置位，此后**任何重展开都不再重拉**；认款链路（`useSkuPool`）也不知道要通知左栏。
- **为什么严重**：用户刚做完一件"大事"（认款），立刻看到两个互相矛盾的数字——对不会电脑的人，这不叫 bug，叫"这软件靠不住"。

### B2 · 「显示更多」假动作

- **复现**：「已建立映射」页签点「显示更多」→ 计数与行数不变；切回队列页签复测，同样不变。
- **根因**：`useSkuPool.ts` 的 `shown` 分页判据 `groups > shown` 在"已认好的不再列"口径下**恒真**——判据说还有更多，列表实现却已把可列的列完了。
- **为什么严重**：这是本仓已有结论"**假动作**"的现行犯：按钮存在、可点、点了没任何反应，也不解释。

### B3 · 窄形态（<1180px）空态溢出 + 遮挡

- **复现**：视口覆盖为 900×800（同会话内）：左栏分到高度 ≈303px，空态按钮落在 y≈474，容器底 ≈441 → **按钮溢出容器**；命中检测显示**被上方工具栏遮挡**，`click()` 无效。
- **佐证**：全新 userData 启动（窗口 871px 宽，见截图 `03-fresh.png` 留档于走查现场）——左栏空态**只剩一个图标**，"还没有产品"的文字与按钮都不可见。
- **根因**：堆叠布局给左栏的固定/弹性高度没有给空态内容让位；空态内容超出时 `overflow` 把它裁掉，且后续栏的工具栏叠在其上。
- **为什么严重**：**全新安装的默认窗口就落在这个断点以下**——"新手第一屏按钮点不到"不是边缘场景，是第一印象。

### B4 · 宽形态 1200×800 队列溢出（默认窗口）

- **复现**：默认窗口（`electron/main.ts` 创建尺寸 1200×800）：右栏队列表**超出其容器右界**；行内「对比」按钮命中检测 = `COVERED_BY`（被容器裁剪面覆盖）且 x 右缘 > 视口宽；「操作」列表头被裁掉一半。
- **根因**：S2 列裁剪后的 7 列在 1200 宽减侧边栏后仍放不下，表格没有横向滚动兜底（或滚动条不可见）。
- **为什么严重**：1200×800 就是默认窗口——S3 的"对比"动线在最常见尺寸下**不可达**，等于没做。

### D1 · 店铺未归一死锁（真机复现）

- **复现**：从克隆库删掉一条 `sk_name_map`（七店仍在 `oi_orders`）→ 重启 → 右栏出现提示条：**纯文本长句，零可点元素**；受阻行的「需先登记店铺」按钮 `disabled`，说明藏在 `title`（触屏/不会悬停的人永远看不到），且实测**被裁出视口右界**。
- **全新安装实测**：侧边栏只有 `今天 / 货与成本 / 便签 / 算钱 / 拣货` ——**没有「店铺账号管家」**（它是市场分发的岛，默认包不含，`modules.config.json`）。
- **结论**：静态报告的"死锁"判断**成立且比静态判断更糟**——不仅提示不可点，连被指的目的地都不在软件里。

### W1–W4 · 包装层问题（真机逐一复现，确认静态报告）

| # | 复现 | 与静态报告的关系 |
|---|---|---|
| **W1** | 编辑抽屉只填款式名 → 「保存」灰、**无任何灰因** → 点 ✕ **静默丢弃，零提示** | 坐实 UX-G3 |
| **W2** | 新建第一款即显示「`0 · 缺 0`」；全新首屏指标条 `待关联 0 / 店铺未归一 0 / 已关联 0 / 关联率 — / 映射记录 0` 全零铺满 | 坐实"全零不是正确表达" |
| **W3** | 展开左栏行后，直连按钮「关联到 123」出现在**右栏顶部**——用户视线正盯着左栏刚展开的那一行 | 静态报告未提：**动线终点不在视线焦点** |
| **W4** | 单行点「关联…」→ 弹层标题「**批量关联 1 项**」；确认键默认灰、不说明"要先勾选" | 坐实术语分裂 |

## §2 重构方案（分四步，每步独立可验收、可回退）

### R0 · 先修四个 bug（不动文案、不动形态）

| 修法 | 验收（全部写成 `goods:ui` 断言） |
|---|---|
| **B1**：认款成功链路（`useSkuPool` 认款落库后）通知左栏作废 `links` 缓存重拉；或干脆把 `loadLinks` 改成"每次展开都拉"（数据量=单款映射数，代价可忽略） | 认款后不刷新页面，重新展开行 → 行内显示「已关联商品 1 个」 |
| **B2**：`showMore` 前置判据改为"还有**未列出**的组"（与列表实现同源），没有更多时**不渲染按钮**而不是渲染一个无效按钮 | 列表已列完时按钮不存在；有剩余时点击后行数增加 |
| **B3**：堆叠布局给左栏 `min-height` 覆盖空态内容，或空态改为不依赖容器高度（居中 + 收紧内边距） | 900×800 两遍视口：空态按钮 `elementFromPoint` 命中自身 |
| **B4**：右栏队列容器加横向滚动（滚动条常显），或按剩余宽度降列（保「店铺/商品ID/订单行/操作」四列） | 1200×800：「对比」「关联…」按钮 `elementFromPoint` 命中自身，表头完整可见 |

**守卫纪律（先于一切改码）**：`goods:ui` 现有断言按元素存在判定，拦不住 B3/B4 这类"渲染了但点不到"。开工第一步是给 runner 补一个 `assertReachable(act)` 助手（`document.elementFromPoint(中心点)` 命中自身或子孙），并把 R0 涉及的 4 组选择器改用它的断言。

### R1 · 解死锁（D1）

1. 提示条从纯文本改为 **「1 家店铺未登记 → [去登记]」按钮形态**；点击后：岛已装 → 切到岛；未装 → 打开插件中心并定位到「店铺账号管家」。
2. 「需先登记店铺」`disabled` 时的灰因从 `title` 提到**按钮旁常显小字**（同一行内）。
3. **待拍板 UX-G6**：根治方案是把"登记店铺"收进**内建**（它只是"原始店名 → 规范店名"的映射，不需要独立岛）——A 内建（建议，彻底消死锁）· B 保持岛 + 引导安装。

### R2 · 包装层（继承静态报告 P0，真机已确认的子集）

1. 术语词表全页统一（UX-G1，待拍板选词）；`批量关联 1 项` → 单项时去"批量"（W4）。
2. 「`0 · 缺 0`」不渲染（W2）；指标条只在非零时列指标（含 `关联率 —`）。
3. 编辑抽屉统一保存模型（UX-G3）：建议全部即时保存，「取消」改「完成」；关闭有未保存改动时给确认（W1）。
4. 直连按钮就近视线（W3）：认款入口优先放在**左栏展开区内**（那里已有「关联…」），右栏顶部直连保留为快捷方式而非唯一入口。

### R3 · 首次动线（新手第一屏）

1. 空库一次性引导卡（UX-G4）：只在**零款 + 零订单**时出现，一张卡三步（① 导入订单 Excel → ② 确认店铺 → ③ 点一款认款），做完即消失；判据区分 `0` 与 `null`（遵守 `2026-10-08-goods-page-entry-guide.md` 裁定）。
2. 应用内帮助入口（UX-G5）：页头「?」放 3 句话 + 30 秒步骤图；`docs/guides/USER_GUIDE.md` 重写或下线。

## §5 采集方法与局限

**做了**：`vite` dev server + `electron . --user-data-dir=<克隆>`（真实 userData 经 APFS clonefile 克隆；另有全新空 userData）；CDP（`--remote-debugging-port`）驱动页面：全量控件 dump（含 `getBoundingClientRect` + `elementFromPoint` 命中检测）、真实点击走查（建档 → 展开行 → 认款全链）、视口覆盖模拟 900px、窗口默认 1200×800 实测、人工摘除 `sk_name_map` 复现死锁、走查库 SQL 取证。截图留档：`01-default.png`（真实窗口瞬态 713px，暴露堆叠裁切）、`03-fresh.png`（全新安装首屏 871px）。

**局限**：① 走查在 dev 模式（未打包产物）下进行——打包版的岛分发行为按 `modules.config.json` 与 `market-out/catalog.json` 静态认定，未逐台比对手持设备；② 未跑 `npm run goods:ui` 基线（R0 开工前必须先跑，见 §2-R0 守卫纪律）；③ 视口覆盖模拟 ≠ 真实窗口缩放（媒体查询一致，但 Chromium 窗口级行为未覆盖）；④ 「显示更多」的精确行数口径（8/7）以代码判据为准，实测记录未逐帧留档。
