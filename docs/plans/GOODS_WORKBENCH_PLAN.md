## 0. 一句话结论

把「产品」与「映射与关联」两个页签**合并成一个左右分栏的工作台**：左栏是**自己的款**（含行展开：SKU + 已关联商品），右栏是**店铺商品池**（待关联队列 / 已建立映射）。

**这是重写，不是加功能** —— 两个 10 列 / 9 列的成熟表格页会被改成两栏中的窄列。所以本方案的三条纪律是：

1. **数据层几乎不动**（只给 `productId` 加一个反向过滤参数，复用既有索引 `idx_pl_shop_sku_product`）；
2. **三条硬约束一条都不丢**（款编码仍是必填锚点 / 队列仍是实时聚合非缓存 / 仍不做硬删）；
3. **既有 72 条界面断言的语义一条都不放松** —— DOM 会变，但 `data-act` 名保持稳定（§8 迁移表），逐条重挂而不是删。

### 2.2 两种关联动线（分栏带来的新能力）

| 动线 | 触发 | 说明 |
| --- | --- | --- |
| **A. 弹层选产品**（现有） | 右栏行「关联…」 | 打开 `ProductPicker`（**加上产品主图**）；批量 = 勾选多行 → 「批量关联选中 N 项…」 |

## 3. 三条硬约束在重构中如何保住（+ 第 4 条）

| # | 约束 | 原文 / 取证 | 重构中的处理 |
| --- | --- | --- | --- |
| 1 | **款编码是跨域锚点**：必填、编辑态只读、批量不可改 | `ProductEditorDrawer.vue:12-24`；`ProductListView.vue:336-338` | 行展开**不放编码编辑**；编辑仍走抽屉，`readonly` 保留。任何新形态的「新建产品」入口都必须带编码字段 |
| 2 | **队列是实时聚合、不是缓存表** | `SkuMappingView.vue:490-496` | 右栏两个**互斥视图**（队列 / 已映射）原样保留；**不合并**、**不给已关联行置灰留在池里**（那会让池子随时间无限增长） |
| 3 | **不做硬删，用「标失效」** | `SkuMappingView.vue:459-462`（删了会让关联率莫名回落且查不出原因） | 右栏映射操作仍是 改绑 / 标失效 / 恢复；左栏行展开的「已关联商品」**只读**，不提供「解除」 |

| 5 | **表格全宽取舍被放弃** | `ProductListView.vue:388-389`（"右侧栏会把表格压到 500px 以下"） | 用**列裁剪 + 行展开**补偿（§7）；并设**窗口宽度下限**（§9-2） |

## 4. 数据层改动（最小面）

**只加一个查询参数**，不新增表、不新增 IPC 通道：

| 层 | 文件 | 改动 |
| --- | --- | --- |
| DB | `electron/product-db.ts` | `SkuMapQuery` 加 `productId?: number`（`:641-647`）；`listSkuMappings` 的 WHERE 加 `AND m.product_id = @productId`（`productId > 0` 时）；**复用既有 `idx_pl_shop_sku_product`（`:717`）** |
| 主进程 | `electron/product-handlers.ts` | `product-sku-list`（`:225-234`）透传 `productId: toId(payload?.productId)` |
| preload | `electron/preload.ts` | `product-sku-list` 入参形状加 `productId?`（`:934`） |
| 渲染层类型 | `src/core/services/ipc.ts` | 声明加 `productId?: number` |
| 渲染层 API | `src/modules/goods/api.ts` | `skuList` 入参加 `productId?: number`（`:105`） |

> ✅ **通道名不变** ⇒ `npm run verify`（IPC 契约）不受影响；也**不新增** preload 分支 ⇒ `ipc:shape:smoke` 只加用例、不加通道。

⚠️ **口径要点**：反向过滤**必须带 `status` 语义** —— 「已关联商品」默认只列 `confirmed`，`invalid` 单列或过滤掉；**不要把失效映射混进来**当"已关联"，否则用户会以为某商品还在用。

每阶段独立可跑、独立可回退；**每阶段结束都跑一遍全量门禁**，不允许"攒到最后一起验"。

- 新增 `GoodsWorkbenchView.vue`（两栏外壳：`data-act="goods-workbench"` / `pane-products` / `pane-pool`），`GoodsView.vue` 用常量 `GOODS_LAYOUT: 'workbench' | 'tabs'` 选择渲染哪套（**回退 = 改一个常量**，同 `SHOP_PRODUCTS_TAB_ENABLED` 先例）。
- 两栏先各挂**现有组件**（左 `ProductListView`、右 `SkuMappingView`）—— 保证 S0 结束功能与现状完全一致。
- 守卫：`goods:ui` 加「两栏同时存在」断言（`pane-products` 与 `pane-pool` 都在 DOM 里）。
- **产出**：`GOODS_LAYOUT` 常量 + 两栏外壳 + **4** 条新断言（原计划写 1 条，实际拆成"锚点都在 / 左栏有内容 / 池栏首屏未激活 / 切过去后两栏同屏可见"）。

**落地时按代码现实回改的两处（实测得出，非偷工）**：

1. **右栏懒挂载**（外壳 `pool` 属性为真才挂 `SkuMappingView`），不是常挂。原计划"S0 两栏各挂现有组件"照抄会
   踩一个静默坑：`SkuMappingView` 挂载即扫队列并 `emit('changed', {unmapped})`，于是 `flow.ts` 三态里
   **`mappedQueue === null`（未知）这一态在界面上永不出现**，引导条从"已配 4 条"改口成报一个它此刻
   不该知道的待办数。变异②实测同时打红两条断言（`queueCalls=1` + 引导条改口）—— 证明这条约束是真的。
   （该三态本身仍由 `tests/goodsFlow.spec.ts` 守着；这里保的是**界面侧**那个哨兵。）
   ⛔ **2026-10-08 续三之后**：三态契约与引导条连同 `flow.ts` 一起撤除，上面这条的**判据理由已失效**；
   但**懒挂载本身仍然保留**（新的理由：不付一次没人看的全量订单聚合），`goods:ui` 那条断言也仍在。
2. **页签仍是 3 个**（合并到 2 个按原计划留在 S4）。因此两栏**只在「映射与关联」页签下同屏**；
   「产品」页签仍是整宽单栏（与重构前逐字一致）。

**变异复核（3 条，全部确认变红后复原，`grep MUTANT` 零残留）**：去池栏容器 → 2 条 FAIL · 池栏常挂载 →
2 条 FAIL · 池栏恒不可见 → 1 条 FAIL（`两栏同屏 L=true R=false`）。详见 `CHANGELOG.md`。

⚠️ **未做**：窄窗口（< 1180px）堆叠的**视口宽度守卫**（CSS 已写，断言推迟到 S2/S4）。
