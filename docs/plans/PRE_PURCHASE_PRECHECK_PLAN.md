## 1. 背景与目标

**用户原话**：「在拿货之前的步骤，如果缺少数据，应该要有入口可以补全，再进入拿货阶段」。

**现状取证**（2026-10-12 实查）：拿货页（第 4 步 `PurchasePanel` 内嵌 `PickingView`）六类缺口——未识别款/缺颜色/缺供应商/无进价/缺图/缺件数——**全部只是纯文本标签**（`wb-tag is-warn`），行内唯一动作是「忽略」（排除而非补全）。用户看到「未识别款 3 件」时无任何「去补」入口。

**目标**：把「缺什么 → 去哪补 → 补完再走」做成**一条看得见、点得到的动线**，落在第 2 步「归类核对」页（拿货前最后一个人工步）。

**成功指标**：
| 指标 | 口径 |
|---|---|
| 缺口可见率 | 进入拿货前，六类缺口在「归类核对」页**各带数量**呈现（当前 0 项有数量） |
| 补全可达性 | 四类可补缺口（未识别款/缺颜色/无进价/缺供应商）**点击 ≤2 步到达补全位置** |
| 口径一致性 | 体检数字与拿货页缺口标签**同源同函数** |

## 2. 名词与口径（先锁死，防「同页两个数不一样」）

| 名词 | 定义 |
|---|---|
| 体检 | 对「**今天导入**」这批订单做的缺口普查（用户 2026-10-12 拍板：与第 1–3 步同口径，不扫全库） |
| 今天导入 | `importDate = date(created_at)`，经 `localDayKey()`，**不用 `toISOString`** |
| 有效颜色 | 拣货行 `color` = **款色优先、回落订单色**（`style_color \|\| o.color`，`picking-db.ts:164`）——缺颜色 = 两者都空 |
| 可补缺口 | 未识别款、缺颜色、无进价、缺供应商（补全位置明确） |
| 仅提示缺口 | 缺图、缺件数（**当前没有补全位置**，只陈述事实） |
| 主数据维护 | 「货与成本」模块（进价 `CostPane` / 供应商 `SupplierView` / 产品档）——**唯一真源**，不在发货台另做录入 |

---

## 3. 范围

**包含**：①「归类核对」页新增**拿货前体检区**；② 六类缺口的统计与分级入口（就地补/跳一次补/仅提示）；③ 「缺颜色」首次纳入缺口统计（当前 `gapsText` 无此项）；④ 体检数据唯一取数口（容器层一个纯函数）。

**不包含（本期不做）**：① 缺图/缺件数的补全入口（需先定义「拿什么补」）；② 「货与成本」主数据维护能力本身改动（只做跳转）；③ 拿货页开单硬禁用（用户第三轮拍板：拦截形态 = 在归类核对中做提示）。

## 4. 方案设计

### 4.1 数据源：容器层一处算，六类一函数出
**纪律依据**：本项目反复确认「同一件事两处摆，迟早两套口径」。拿货页已在用 `aggregatePicking`（`src/lib/picking.ts`）算全部缺口，体检**必须复用同一纯函数**，不在 `ClassifyPanel` 另写一套。

| 层 | 改动 | 说明 |
|---|---|---|
| `electron/picking-db.ts` | `pickingRows` 加**可选** `importDate` 参数 | SQL 加 `date(created_at) = ?`；不传 = 全库（拿货页现状不变） |
| `electron/picking-handlers.ts` | 透传 `importDate` | 校验同既有风格 |
| `src/core/services/ipc.ts` + `src/types.ts` | `pickingRows` payload 加 `importDate?: string` | 契约两处同改 |
| `src/lib/picking.ts` | `aggregatePicking` 加 `missingColor` 计数器 | 判定 `!color`；⚠️ **未识别款优先**（有款没色才算缺颜色） |
| `src/modules/today/flowCtx.ts` | `ShippingSummary.gaps` 加 `color: number` | 容器层汇总形状扩一项 |
| `src/modules/today/TodayView.vue` | `reload()` 加一次 `pickingRows({ importDate })` | 与徽标全库口径调用**并存**（两次 IPC，用途不同，各写各作用域） |

> ⚠️ 两次 `pickingRows` 不是浪费：徽标「N 款色」是**拿货页签跨天缺口**，体检是**今天这批补没补完**。两数同现 UI 必须各写作用域——「今天导入」/「未发货近 30 天」。

### 4.2 体检区：放在「归类核对」页表格上方
位置理由：用户拍板"在归类核对中补最好"——第 2 步是拿货前最后一个人工步，未识别款/缺颜色的补全字段本来就在这一页。

```
┌─ 拿货前体检（今天导入 N 行）──────────────────────────────┐
│ ⚠ 未识别款 3 行      [去看这 3 行 →]   ← 就地补：表格筛选   │
│ ⚠ 缺颜色   2 行      [去看这 2 行 →]   ← 就地补：表格筛选   │
│ ⚠ 无进价   1 个款    [去「货与成本」补] ← 跳一次（唯一真源） │
│ ⚠ 缺供应商 1 个款    [去「货与成本」补] ← 跳一次（唯一真源） │
│ · 缺图 0 · 缺件数 0  （暂无补全位置，暂不拦截）              │
└──────────────────────────────────────────────────────────┘
```
**每项只在非零时出现**（全齐时整区不渲染——「全零」不是正确表达）。

### 4.3 入口分级（核心设计）
| 缺口 | 形态 | 动作 | 落地方式 |
|---|---|---|---|
| 未识别款 | 就地补 | 「去看这 N 行」→ 表格切到**只看未识别**筛选 | `ClassifyPanel` 加筛选态 |
| 缺颜色 | 就地补 | 「去看这 N 行」→ 表格切到**只看缺颜色**筛选 | 同上（含 `colorUnattached` 守卫） |
| 无进价 | 跳一次补 | 「去「货与成本」补」→ `openModule('goods')` 落进价页 | 保持唯一真源，不在本页内嵌录入框 |
| 缺供应商 | 跳一次补 | 「去「货与成本」补」→ `openModule('goods')` 落供应商/产品档 | 同上 |
| 缺图 / 缺件数 | 仅提示 | 无动作，文案说明「暂无补全位置」 | 不造假入口 |

> ⭐ **「跳一次」不是「跳去不管」**：`openModule` 是宿主既有能力（总览卡「去「货与成本」补 SKU 克重」已在用），补完用户自己回发货台——平衡点：**能就地补的绝不跳**，必须跳的只跳一次且原因是「唯一真源在那」。

### 4.4 拦截形态（用户第三轮拍板）
**「再进入拿货阶段」= 在「归类核对」页把缺口说清 + 「确认无误」前给一次知情提示**，不做页面级硬拦：
1. 体检区常显（可补缺口未清时）——"想进拿货，先看见缺什么"。
2. 「全部确认无误」按钮：有可补缺口时点击后弹确认（"还有 N 行未识别款 / N 行缺颜色，确认后它们也离开待核对列表。仍要确认吗？"）——**知情提示而非禁用**。
3. 拿货页**不加**硬拦、不禁用开单。

## 5. 功能需求与验收标准

| 编号 | 需求 | 验收标准（Given/When/Then） |
|---|---|---|
| FR-01 | 体检区按今天导入口径统计六类缺口 | Given 今天导入 5 行含 2 行未识别款；When 打开「归类核对」；Then 显示「未识别款 2 行」，且**缺颜色不把这 2 行重复计入** |
| FR-02 | 缺口项各带数量与动作 | 每项渲染数量文本 + 可点按钮（`data-act` 命名 `cl-precheck-*`） |
| FR-03 | 就地补：未识别款/缺颜色可筛选 | Given 显示未识别款 2 行；When 点「去看这 2 行」；Then 表格只列这 2 行且能直接补 |
| FR-04 | 跳一次补：无进价/缺供应商打开「货与成本」 | 点击 `openModule('goods')` 生效，页面切换 |
| FR-05 | 全齐时体检区不渲染 | Given 六类全 0；When 打开；Then 体检区 DOM 不存在 |
| FR-06 | 「全部确认无误」有可补缺口时给知情提示 | 弹层说明缺什么；选「仍要确认」后行为与现在一致 |
| FR-07 | 口径隔离 | 拿货页签徽标（跨天）与体检区（今天）数字可不同，但**两处都写明作用域** |

## 6. 异常与边界
| 场景 | 处理 |
|---|---|
| 今天还没导入 | 体检区整块不渲染（第 1 步空态已引导导入） |
| `pickingRows` 失败 | 体检区不渲染 + 不弹错（其他部分照常） |
| 未识别款行同时没颜色 | 只计 `missingStyle`，不计 `missingColor` |
| 缺图/缺件数非零 | 只陈述（「暂无补全位置」），**不参与** FR-06 提示文案 |
| 跨天订单 | 不属于体检范围（拿货页签徽标管）；文案写清「今天导入」 |

## 7. 风险登记册
| 编号 | 风险 | 概率 | 影响 | 等级 | 应对 |
|---|---|---|---|---|---|
| RK-01 | 两套口径（徽标 vs 体检）被读成"两个数对不上" | 3 | 3 | 9 中 | 两处都写作用域（FR-07）；冒烟加断言 |
| RK-02 | `missingColor` 与 `missingStyle` 重复计数 | 3 | 2 | 6 低 | 纯函数内未识别优先 + 专用用例钉死（夹具须有"有款无色"与"无款"两行） |
| RK-03 | 「跳一次补」被视为主不满足「不要跳转页面」 | 3 | 2 | 6 低 | §4.3 已平衡；若仍不接受退路 = 体检区内嵌迷你录入（记入后续池，不做） |
| RK-04 | 体检区常显被当噪声 | 2 | 2 | 4 低 | 全齐不渲染；仅提示类压成一行小字 |
| RK-05 | `importDate` 参数加错位置改拿货页口径 | 2 | 4 | 8 中 | 参数**可选、默认不传**；拿货页调用点一字不改；冒烟断言拿货页仍走全库 |
