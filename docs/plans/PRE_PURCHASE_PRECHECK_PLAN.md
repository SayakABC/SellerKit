## 1. 背景与目标

**用户原话**：「在拿货之前的步骤，如果缺少数据，应该要有入口可以补全，再进入拿货阶段」。

**现状取证**（2026-10-12 实查）：拿货页（第 4 步 `PurchasePanel` 内嵌 `PickingView`）的六类缺口——
未识别款 / 缺颜色 / 缺供应商 / 无进价 / 缺图 / 缺件数——**全部只是纯文本标签**（`wb-tag is-warn`），
行内唯一动作是「忽略」（**排除**而非**补全**）。用户看到「未识别款 3 件」时：
没有任何「去补」入口，只能自己想起「这要去第 2 步」再手动切页签。

**目标**：把「缺什么 → 去哪补 → 补完再走」做成**一条看得见、点得到的动线**，落在第 2 步
「归类核对」页（拿货前最后一个人工步）。

**成功指标**：

| 指标 | 口径 |
|---|---|
| 缺口可见率 | 进入拿货阶段前，六类缺口在「归类核对」页**各带数量**呈现（当前：0 项有数量） |
| 补全可达性 | 四类可补缺口（未识别款/缺颜色/无进价/缺供应商）**点击 ≤2 步到达补全位置** |
| 口径一致性 | 体检数字与拿货页缺口标签**同源同函数**（不得两处各算一套） |

## 2. 名词与口径（先锁死，防「同页两个数不一样」）

| 名词 | 定义 |
|---|---|
| 体检 | 对「**今天导入**」这批订单做的缺口普查（用户 2026-10-12 拍板：与第 1–3 步同口径，不扫全库） |
| 今天导入 | `importDate = date(created_at)`，经 `localDayKey()`，**不用 `toISOString`** |
| 有效颜色 | 拣货行 `color` = **款色优先、回落订单色**（`style_color \|\| o.color`，`picking-db.ts:164`）——缺颜色 = 两者都空 |
| 可补缺口 | 未识别款、缺颜色、无进价、缺供应商（补全位置明确） |
| 仅提示缺口 | 缺图、缺件数（**当前没有补全位置**，只陈述事实） |
| 主数据维护 | 「货与成本」模块（进价 `CostPane` / 供应商 `SupplierView` / 产品档）——**唯一真源**，不在发货台另做录入 |

---

## 3. 范围

**包含**：

1. 「归类核对」页新增**拿货前体检区**（缺什么、多少、去哪补）
2. 六类缺口的统计与分级入口（就地补 / 跳一次补 / 仅提示）
3. 「缺颜色」首次纳入缺口统计（当前 `gapsText` **没有颜色这一项**）
4. 体检数据的唯一取数口（容器层，一个纯函数）

**不包含（本期不做，写入后续池）**：

- 缺图 / 缺件数的补全入口（需先定义「拿什么补」——图库选图 / 订单行改件数，都是独立需求）
- 「货与成本」主数据维护能力本身的任何改动（只做跳转）
- 拿货页开单动作的硬禁用（用户第三轮拍板：拦截形态 = **在归类核对中做提示**，详见 §5.4）

## 4. 方案设计

### 4.1 数据源：容器层一处算，六类一函数出

**纪律依据**：本项目反复确认「同一件事两处摆，迟早两套口径」。拿货页已在用
`aggregatePicking`（`src/lib/picking.ts`）算全部缺口，体检**必须复用同一个纯函数**，
不得在 `ClassifyPanel` 里另写一套统计。

改动链：

| 层 | 改动 | 说明 |
|---|---|---|
| `electron/picking-db.ts` | `pickingRows` 加**可选** `importDate` 参数 | SQL 加 `date(created_at) = ?`；**不传 = 全库**（拿货页现状不变——货本来就跨天结转） |
| `electron/picking-handlers.ts` | 透传 `importDate` | 校验同既有参数风格 |
| `src/core/services/ipc.ts` + `src/types.ts` | `pickingRows` payload 加 `importDate?: string` | 契约两处同改 |
| `src/lib/picking.ts` | `aggregatePicking` 加 `missingColor` 计数器 | 判定 `!color`；⚠️ **未识别款优先**（有款没色才算缺颜色，避免两类重复计数） |
| `src/modules/today/flowCtx.ts` | `ShippingSummary.gaps` 加 `color: number` | 容器层汇总的既有形状（`weight/cost/style/rate`）扩一项 |
| `src/modules/today/TodayView.vue` | `reload()` 增加一次 `pickingRows({ importDate })` 调用 | 与徽标用的全库口径调用**并存**（两次 IPC，口径不同、用途不同，页面上各写各的作用域） |

> ⚠️ 两次 `pickingRows` 不是浪费：徽标「N 款色」是**拿货页签的跨天缺口**（用户要知道还要拿多少），
> 体检是**今天这批补没补完**（用户要知道今天能不能收工）。两个数都出现在 UI 上时**必须各自写明作用域**
> ——「今天导入」/「未发货近 30 天」。

### 4.2 体检区：放在「归类核对」页表格上方

位置理由：用户拍板「在归类核对中补最好」——第 2 步是拿货前最后一个人工步，且
未识别款/缺颜色的补全字段**本来就在这一页**。

形态（分段控件下方、表格上方一条 `wb-panel`）：

```
┌─ 拿货前体检（今天导入 N 行）──────────────────────────────┐
│ ⚠ 未识别款 3 行      [去看这 3 行 →]   ← 就地补：表格筛选   │
│ ⚠ 缺颜色   2 行      [去看这 2 行 →]   ← 就地补：表格筛选   │
│ ⚠ 无进价   1 个款    [去「货与成本」补] ← 跳一次（唯一真源） │
│ ⚠ 缺供应商 1 个款    [去「货与成本」补] ← 跳一次（唯一真源） │
│ · 缺图 0 · 缺件数 0  （暂无补全位置，暂不拦截）              │
└──────────────────────────────────────────────────────────┘
```

**每项只在非零时出现**（全齐时整区不渲染——「全零」不是正确表达，空着比报喜更诚实）。

### 4.3 入口分级（核心设计）

| 缺口 | 形态 | 动作 | 落地方式 |
|---|---|---|---|
| 未识别款 | 就地补 | 「去看这 N 行」→ 表格切到**只看未识别**筛选 | `ClassifyPanel` 加筛选态（复用既有搜索框旁加一个 chip，或行内定位） |
| 缺颜色 | 就地补 | 「去看这 N 行」→ 表格切到**只看缺颜色**筛选 | 同上（颜色格本页已有，含上一轮 `colorUnattached` 守卫） |
| 无进价 | 跳一次补 | 「去「货与成本」补」→ `openModule('goods')` 落到进价页 | 保持唯一真源；**不在本页内嵌录入框**（两套口径） |
| 缺供应商 | 跳一次补 | 「去「货与成本」补」→ `openModule('goods')` 落到供应商/产品档 | 同上 |
| 缺图 / 缺件数 | 仅提示 | 无动作，文案说明「暂无补全位置」 | 不造假入口 |

> ⭐ **「跳一次」不是「跳去不管」**：`openModule` 是宿主既有能力（总览卡的「去「货与成本」补 SKU 克重」
> 已在用），补完用户自己回发货台 —— 与「不要跳转页面」的诉求平衡点在于：
> **能就地补的绝不跳**（未识别款/缺颜色），必须跳的只跳一次且原因是「唯一真源在那」。

### 4.4 拦截形态（用户第三轮拍板）

**「再进入拿货阶段」= 在「归类核对」页把缺口说清 + 「确认无误」前给一次知情提示**，不做页面级硬拦：

1. 体检区常显（可补缺口未清时）——这是「拦截」的主形态：**想进拿货，先看见缺什么**
2. 「全部确认无误」按钮：有可补缺口时，点击后弹一次确认（「还有 N 行未识别款 / N 行缺颜色，
   确认后它们也会离开待核对列表。仍要确认吗？」）——**知情提示而非禁用**（缺图/缺件数清不了，
   禁用会把用户卡死）
3. 拿货页**不加**硬拦、不禁用开单（用户改口放弃「不能进拿货页」的强拦截）

## 5. 功能需求与验收标准

| 编号 | 需求 | 验收标准（Given/When/Then） |
|---|---|---|
| FR-01 | 体检区按今天导入口径统计六类缺口 | Given 今天导入 5 行含 2 行未识别款；When 打开「归类核对」；Then 体检区显示「未识别款 2 行」，且**缺颜色不把这 2 行重复计入** |
| FR-02 | 缺口项各自带数量与动作 | 每项渲染出数量文本 + 一个可点按钮（`data-act` 命名 `cl-precheck-*`） |
| FR-03 | 就地补：未识别款/缺颜色可筛选 | Given 体检区显示未识别款 2 行；When 点「去看这 2 行」；Then 表格只列这 2 行（或首行定位高亮），且能直接补 |
| FR-04 | 跳一次补：无进价/缺供应商打开「货与成本」 | 点击后 `openModule('goods')` 生效，页面切换到该模块 |
| FR-05 | 全齐时体检区不渲染 | Given 六类缺口全 0；When 打开页面；Then 体检区 DOM 不存在（不是「显示 0」） |
| FR-06 | 「全部确认无误」在有可补缺口时给知情提示 | 弹层出现且说明缺什么；选「仍要确认」后行为与现在一致（不改变既有写入语义） |
| FR-07 | 口径隔离 | 拿货页签徽标（跨天口径）与体检区（今天口径）数字可以不同，但**两处都写明各自作用域** |

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 今天还没导入 | 体检区整块不渲染（第 1 步的空态已在引导导入，不要再叠一个） |
| `pickingRows` 失败 | 体检区不渲染 + 不弹错（页面上其他部分照常；失败不该让整页汇总挂） |
| 未识别款行同时没颜色 | 只计 `missingStyle`，不计 `missingColor`（未识别款优先，见 §4.1） |
| 缺图/缺件数非零 | 只陈述（「暂无补全位置」），**不参与** FR-06 的确认提示文案（提示只列可补缺口） |
| 跨天订单（昨天导入今天还要拿） | 不属于体检范围（拿货页签徽标管）；若用户问「昨天的呢」，文案写清「今天导入」 |

## 7. 风险登记册

| 编号 | 风险 | 概率 | 影响 | 等级 | 应对 |
|---|---|---|---|---|---|
| RK-01 | 两套口径（徽标 vs 体检）被读成「两个数对不上」 | 3 | 3 | 9 中 | 两处都写作用域（FR-07）；冒烟加「同页两个口径各自标明」断言 |
| RK-02 | `missingColor` 与 `missingStyle` 重复计数，数字虚高 | 3 | 2 | 6 低 | 纯函数内未识别优先 + 专用用例钉死（夹具必须有一行「有款无色」与一行「无款」） |
| RK-03 | 「跳一次补」被用户视为没满足「不要跳转页面」 | 3 | 2 | 6 低 | §4.3 已平衡：能就地补的绝不跳；跳的四项原因是唯一真源在「货与成本」。若评审仍不接受，退路 = 在体检区内嵌迷你录入（记入后续池，不做） |
| RK-04 | 体检区常显被当成噪声 | 2 | 2 | 4 低 | 全齐不渲染；仅提示类压成一行小字 |
| RK-05 | `importDate` 参数加错位置导致拿货页口径被改 | 2 | 4 | 8 中 | 参数**可选、默认不传**；拿货页调用点一字不改；冒烟断言拿货页仍走全库 |
