## 0. 一句话结论

提案**方向正确**（它描述的痛点是真的：认款靠肉眼比图），**数据模型与核心原则现状已落地 90%**（产品=款、SKU=颜色/尺码/克重、商品池=店铺商品ID、**克重是产品固有属性**），但它的**界面形态（单屏左右分栏 + 卡片网格 + 拖拽关联 + 合并视图）是一次大重构**，会废弃两个成熟的多列表格页，并与三条既有硬约束正面冲突。

**建议只采纳其中「三样加法」，其余列明不采纳理由与重新评估条件**：

| 采纳 | 内容 | 价值 |
| --- | --- | --- |
| **①（P1）** | 认款时**看得见产品图**（选产品弹层显示主图） | 直击"图对图认款只有一半" |
| **②（P1）** | **对比模式**（左候选产品图 ↔ 右商品图，键盘确认/切换） | 提案里最值钱、现状最缺的一块；**零新 IPC** |
| **③（P2）** | 产品侧**「已关联商品」只读反查** | 提案的"关联商品列表"首次有落点 |

不采纳/暂缓：整页左右分栏重构、卡片网格替换表格、拖拽关联、合成状态图标（✅🔶⚠️）、"已关联置灰"合并视图、硬"解除关联"。

### 1.1 页面结构

「货与成本」= 外壳（页头 + 可点指标条 + 三步引导 + 页签）+ 三个页签（`src/modules/goods/GoodsView.vue`）：

| --- | --- | --- | --- |

| **映射与关联** | `SkuMappingView.vue` | **两个互斥视图**（分段控件） | 待关联队列（9 列：店铺/平台/图/商品ID/商品标题/订单行/状态/操作）+ 已建立映射（9 列） |
| **供应商** | `SupplierView.vue` | 表格 | 拿货供应商主数据 |

产品编辑 = **右侧抽屉**（`ProductEditorDrawer.vue`）：编码/款式名/供应商/类目/状态/备注/主图/SKU 子表。

### 1.2 数据模型对照

| 提案概念 | 现状载体 | 判定 |
| --- | --- | --- |
| 产品（核心实体）：名称 / 主图 / SKU 列表 / 关联商品列表 | `pl_products`（`electron/product-db.ts:55`）+ 主图 / SKU 子表 | **已有**（"关联商品列表"见下） |
| SKU 属性：颜色、规格、克重 | `pl_variants`：`color` / `size` / `code` / `weight_g`（`electron/product-db.ts:1542-1560`） | **已有**，但**字段比提案多一个「编码」**（全局唯一，拣货锚点），且「规格」现状叫「尺码 size」 |
| 商品（待关联池）：商品ID / 图片 / 店铺 / 关联状态 | `pl_shop_sku`：`(platform, shop_id, item_id, spec, product_id, qty_per_item, status, source, note, image_url…)`（`electron/product-db.ts:694-711`） | **已有** |
| **核心原则：克重是产品固有属性，创建时设置，与关联无关** | 克重挂在 `pl_variants.weight_g`（属于产品），认款只写映射的 `spec`=颜色 | ✅ **已是现状，无需改** |
| 一件商品可关联多个产品（套装） | `UNIQUE(platform, shop_id, item_id, spec, product_id)` —— `product_id` 在唯一键里 ⇒ **一对多原生支持**；`qty_per_item` 即套装数量 | **已有**（数据层） |

### 1.3 关键事实（决定裁定）

1. **选产品弹层没有图**。`ProductPicker.vue:32-36` 只渲染 `款编码 / 款式名 / 类目`，**没有主图**。而认款的队列行**有**商品图（`SkuMappingView.vue:176-194`，可点开看原图）。⇒ **"图对图认款"只有商品一侧，产品一侧是纯文字**。
2. **没有对比模式、没有悬停放大、没有拖拽关联**。全 `src/modules/goods/**` 检索确认（唯一的 `dragMode` 是 SKU 尺码拖选，见 `ProductEditorDrawer.vue:544`，与关联无关）。
3. **产品表是全宽 10 列**，且代码注释已就"分栏会挤"下过判断：*"右侧栏会把表格压到 500px 以下，10 列挤成一团"*（`ProductListView.vue:388-389`）。
4. **款编码是跨域锚点**：必填、编辑态只读、批量不可改（`ProductEditorDrawer.vue:12-24`；`ProductListView.vue:336-338`）。提案的"新建产品弹窗"**漏了编码字段**。
5. **队列是实时聚合订单、不是缓存表**：每次写入后重拉，"关联完就从队列消失"（`SkuMappingView.vue:490-496`）。已关联的**不留在队列里置灰**，而是进"已建立映射"视图。
6. **现状刻意不做"硬解除"**：已建立映射只有 改绑 / 标失效 / 恢复，**没有删除**（`SkuMappingView.vue:361-385`）；理由写在确认弹层里 —— *"直接删掉会让关联率莫名回落且查不出原因"*（`SkuMappingView.vue:459-462`）。
7. **款主图正循环已落地**（上一轮）：认款时若款无主图，顺手采纳订单图为款主图（`electron/product-handlers.ts` 的 `adoptOrderImages`）。⇒ 产品图会**越来越多**，这是做"看图认款"的前置条件，已经就绪。

## 3. 三条硬约束（照抄提案会踩到的）

1. **表格全宽 vs 分栏**
   产品页 10 列、队列页 9 列，各自的设计取舍是"**全宽 + 列多**"。塞进左右分栏后每一半只剩 ~500–700px，两页都要为窄宽度重新设计列/交互 —— 这是**重写**而非增量，且会丢掉当前的"表格扫描效率"。

2. **款编码是跨域锚点**
   提案"新建产品弹窗"只列了 名称/主图/SKU，**没有编码**。而编码是 `订单 / 采购 / 成本` 三域关联的锚点、必填且不可改。任何新形态的产品创建入口都必须保留编码。（`ProductEditorDrawer.vue:12-24`）

3. **队列 = 实时聚合，不是缓存表**
   提案要把"已关联的留在池里置灰"，这要求把映射表**并进队列视图**，且"已关联"行会随时间无限增长。现状的口径（未关联队列 ⇄ 已建立映射两个互斥视图）是为了"关联完就从队列消失 = 真实状态"。

## 4. 采纳清单（分阶段，全部为**加法**，不动页签与表格）

### P0 — 判据对齐（文档 / 名词，零代码）
- 名词统一：**SKU = 颜色 + 尺码 + 编码 + 克重**；提案的"规格"→"尺码"；"关联商品"→"已映射的店铺商品ID"。
- 复核 `docs/features/PRODUCT_LIBRARY.md`：把"关联商品列表/状态标识"作为**待做**登记进进度表（避免以后被当成"已实现"）。
- 产出：本文档 + 一行登记进 `docs/README.md`。

### P1 — 认款看图（**零新 IPC，纯渲染层**）
**① `ProductPicker` 显示产品主图**
- `ProductListItem` 已带 `imagePath`（`ProductListView.vue:534`），`api.imageThumbBatch` 已可批量取缩略图 —— 选产品弹层按当前列出的一页行合批取缩略图即可。
- 取图失败降级：空占位，不挡列表（与产品页/映射页同一套降级）。

**② 对比模式弹层**
- 左右两栏：**候选产品主图**（`imagePath` → 缩略图）+ **商品图**（复用映射页已经取到的 `queueImgs`）。
- 键盘：`←/→` 在候选产品间移动、`空格` 确认关联、`Esc` 关闭。
- ⭐ **零新通道**：产品图走 `imageThumbBatch`，商品图已在 `queueImgs` 缓存里 —— 只新增一个渲染层组件（与 `ProductPicker.vue` 同级目录）。
- ⚠️ 对比的产品图与队列商品图**口径不同**：队列商品是"未配映射"的，`itemImagePool` 对它必然没有产品层（`SkuMappingView.vue:672-673`），所以候选产品图必须**独立取**（来自被选中的那行产品，不是 `itemImagePool`）。

### P2 — 关联的"另一半"（低成本数据层 + 界面）
**③ 产品侧「已关联商品」只读反查**
- 数据层：给 `listSkuMappings` 的 `SkuMapQuery` **加一个 `productId` 过滤**（`product-db.ts:641-647`），复用既有 `idx_pl_shop_sku_product` 索引（`product-db.ts:717`）—— 是**加参数**，不是新表/新域。
- 界面：产品编辑抽屉里新增一块"已关联商品"（只读列表：店铺 / 商品ID / 状态 / 图），入口即"去看这件商品卖了多少行"。
- ⚠️ **只读**：不提供硬"解除"（那是"标失效"的语义，见 §2-19）。

**④ 新建产品「保存并开始关联」**
- 抽屉保存成功后：关抽屉 → 切到「映射与关联」页签 → 带新款的 `productId` 作为**预选**（把 `ProductPicker` 的默认选中项指向它）。
- 只是一次跨页签跳转 + 一个可选的预选参数，不动数据。

### P3 — 评估项（**默认不做**，仅登记触发条件）
| 项 | 触发条件（满足才做） |
| --- | --- |
| 悬停放大预览 | 若实测"点开看原图"的点击成本成为高频抱怨（需界面埋点/用户反馈佐证） |
| 拖拽关联 | 若"勾选→批量"被证明不够用（当前无证据） |
| "已关联置灰"合并视图 | 若"两个互斥视图"被证明让人找不到已配的（先观察一段） |

| 不采纳 | 主要理由 | 重新评估条件 |
