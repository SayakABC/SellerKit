## 0. 一句话结论

提案**方向正确**（痛点真实：认款靠肉眼比图），**数据模型与核心原则现状已落地 90%**（产品=款、SKU=颜色/尺码/克重、商品池=店铺商品ID、**克重是产品固有属性**），但**界面形态（单屏左右分栏 + 卡片网格 + 拖拽 + 合并视图）是一次大重构**，会废弃两个成熟多列表格页，并与三条既有硬约束正面冲突。

**建议只采纳其中「三样加法」，其余列明不采纳理由与重新评估条件**：

| 采纳 | 内容 | 价值 |
| --- | --- | --- |
| **①（P1）** | 认款时**看得见产品图**（选产品弹层显示主图） | 直击"图对图认款只有一半" |
| **②（P1）** | **对比模式**（左候选产品图 ↔ 右商品图，键盘确认/切换） | 提案最值钱、现状最缺；**零新 IPC** |
| **③（P2）** | 产品侧**「已关联商品」只读反查** | 提案"关联商品列表"首次有落点 |

不采纳/暂缓：整页左右分栏重构、卡片网格替换表格、拖拽关联、合成状态图标、合并视图、硬"解除关联"。

## 1. 现状盘点（以代码为准）

### 1.1 页面结构
「货与成本」= 外壳（页头 + 指标条 + 三步引导 + 页签）+ 三页签：
| 页签 | 组件 | 形态 | 承载 |
| --- | --- | --- | --- |
| **产品** | `ProductListView.vue` | **全宽 10 列表格** | 款主数据 + 工具栏（搜索/筛选/导出/导入/新增）+ 批量编辑/删除 + 常驻补克重面板 |
| **映射与关联** | `SkuMappingView.vue` | **两个互斥视图**（分段控件） | 待关联队列（9 列）+ 已建立映射（9 列） |
| **供应商** | `SupplierView.vue` | 表格 | 拿货供应商主数据 |
| ~~商品清单~~ | `ShopProductView.vue` | 表格 | **界面已收起**（`SHOP_PRODUCTS_TAB_ENABLED=false`），数据层与 IPC 保留 |

产品编辑 = **右侧抽屉**（`ProductEditorDrawer.vue`）：编码/款式名/供应商/类目/状态/备注/主图/SKU 子表。

### 1.2 数据模型对照
| 提案概念 | 现状载体 | 判定 |
| --- | --- | --- |
| 产品（名称/主图/SKU/关联商品列表） | `pl_products` + 主图/SKU 子表 | **已有**（"关联商品列表"见下） |
| SKU（颜色/规格/克重） | `pl_variants`：`color`/`size`/`code`/`weight_g` | **已有**，但**多一个「编码」**（全局唯一，拣货锚点），"规格"现状叫"尺码" |
| 商品（待关联池） | `pl_shop_sku`：`(platform, shop_id, item_id, spec, product_id, qty_per_item, status…)` | **已有** |
| **克重是产品固有属性，与关联无关** | 挂在 `pl_variants.weight_g` | ✅ 已是现状 |
| 一件商品可关联多个产品（套装） | `UNIQUE(platform, shop_id, item_id, spec, product_id)` | **已有**（数据层） |

### 1.3 关键事实（决定裁定）
1. **选产品弹层没有图**：`ProductPicker.vue:32-36` 只渲染 款编码/款式名/类目，无主图；而认款队列行**有**商品图（`SkuMappingView.vue:176-194`）。
2. **没有对比模式、悬停放大、拖拽关联**：全 `src/modules/goods/**` 检索确认（`ProductEditorDrawer.vue:544` 的 `dragMode` 是 SKU 尺码拖选，与关联无关）。
3. **产品表全宽 10 列**，代码注释已判"分栏会挤"（`<500px`，10 列挤成一团，`ProductListView.vue:388-389`）。
4. **款编码是跨域锚点**：必填、编辑态只读、批量不可改（`ProductEditorDrawer.vue:12-24`；`ProductListView.vue:336-338`）；提案"新建产品弹窗"**漏了编码字段**。
5. **队列是实时聚合订单，不是缓存表**：写入后重拉，"关联完就从队列消失"（`SkuMappingView.vue:490-496`）。
6. **现状刻意不做"硬解除"**：已建立映射只有 改绑/标失效/恢复，**无删除**（理由："直接删会让关联率莫名回落且查不出原因"，`SkuMappingView.vue:459-462`）。
7. **款主图正循环已落地**：认款时若款无主图，顺手采纳订单图为款主图（`product-handlers.ts` 的 `adoptOrderImages`）。

## 3. 三条硬约束（照抄提案会踩到的）
1. **表格全宽 vs 分栏**：产品页 10 列、队列页 9 列，塞进左右分栏每半 ~500–700px，两页都要为窄宽度重设计 —— 重写非增量，丢表格扫描效率。
2. **款编码是跨域锚点**：提案"新建产品弹窗"只列名称/主图/SKU，**没有编码**（订单/采购/成本三域关联锚点、必填不可改）。
3. **队列 = 实时聚合，不是缓存表**：提案把"已关联的留在池里置灰"要求把映射表并进队列视图，且会无限增长；现状（未关联队列 ⇄ 已建立映射互斥视图）为"关联完就从队列消失 = 真实状态"。

## 4. 采纳清单（分阶段，全部为**加法**，不动页签与表格）

### P0 — 判据对齐（文档/名词，零代码）
- 名词统一：**SKU = 颜色 + 尺码 + 编码 + 克重**；"规格"→"尺码"；"关联商品"→"已映射的店铺商品ID"。
- 复核 `PRODUCT_LIBRARY.md`：把"关联商品列表/状态标识"作**待做**登记进进度表。
- 产出：本文档 + 一行登记进 `docs/README.md`。

### P1 — 认款看图（**零新 IPC，纯渲染层**）
- **① `ProductPicker` 显示产品主图**：`ProductListItem` 已带 `imagePath`（`ProductListView.vue:534`），`api.imageThumbBatch` 可批量取缩略图；取图失败降级空占位。
- **② 对比模式弹层**：左右两栏 = 候选产品主图（`imagePath`→缩略图）+ 商品图（复用 `queueImgs`）；键盘 `←/→` 移动、`空格` 确认、`Esc` 关闭。⭐ 零新通道（产品图走 `imageThumbBatch`，商品图在 `queueImgs` 缓存）。⚠️ 候选产品图须**独立取**（来自选中行产品，不是 `itemImagePool` 的产品层）。

### P2 — 关联的"另一半"（低成本数据层 + 界面）
- **③ 产品侧「已关联商品」只读反查**：给 `listSkuMappings` 的 `SkuMapQuery` **加 `productId` 过滤**（`product-db.ts:641-647`），复用 `idx_pl_shop_sku_product`（`product-db.ts:717`）—— 加参数非新表。界面：产品编辑抽屉新增只读列表（店铺/商品ID/状态/图）。⚠️ **只读**，不提供硬"解除"。
- **④ 新建产品「保存并开始关联」**：抽屉保存成功后关抽屉 → 切「映射与关联」页签 → 带新款 `productId` 作预选。只跨页签跳转 + 可选预选参数。

### P3 — 评估项（**默认不做**，仅登记触发条件）
| 项 | 触发条件 |
| --- | --- |
| 悬停放大预览 | 若"点开看原图"点击成本成高频抱怨 |
| 拖拽关联 | 若"勾选→批量"被证明不够用 |
| "已关联置灰"合并视图 | 若"两个互斥视图"被证明让人找不到已配的 |

## 5. 不采纳 / 暂缓（逐条理由 + 重新评估条件）
| 不采纳 | 主要理由 | 重新评估条件 |
| --- | --- | --- |
| 整页左右分栏 | 与"表格全宽"冲突；＝重写两个成熟页 | 若产品数/商品数降到卡片装得下 |
| 卡片网格替换表格 | 装不下列信息、难排序分页批量导入导出 | 同上 |
| 拖拽关联 | 宽表+分页上拖拽成本高、与批量动线重叠 | P3 成立 |
| 合成状态图标 | 把两件事压一个颜色，丢信息 | 若用户要明确"一眼看哪款没弄好" |
| "已关联置灰"合并视图 | 违反"队列非缓存"；已关联行无限增长 | P3 成立 |
| 硬"解除关联" | 与"不做硬删"冲突 | 不评估（除非改关联率口径） |
| 新建弹窗（无编码） | 漏款编码锚点字段 | ——（P2④ 在现有抽屉补"保存并开始关联"） |
