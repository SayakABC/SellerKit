> ① 体验最重要 —— 操作简单、数据精准、**不存在模糊地带**、上手即用、解决痛点；

## 3. 形态判定：什么做岛、什么内建

**判据**：**岛 = 可选的加工手段；宿主 = 必经的主干与契约。** 主线：**删掉它，"货卖出去 / 钱算清楚"最小闭环还成立吗？** 不成立 → 内建；成立 → 岛。副线：① 要跑不受信/第三方代码才需要岛；② 需要独立发版节律 → 岛。

**三分法**：① 宿主内建（主干）· ② 薄内建 + 重手段留岛 · ③ 纯岛（可选/外部/低频）。**铁律**：**能力可复用，入口必须唯一**。

### 目标 IA（用户看到的面）

| 面 | 职责 | 形态 | 主操作 |
| --- | --- | --- | --- |
| **今天**（首页） | 一眼看到该干什么：待识别/待拣/缺克重·缺成本·缺运价/今日毛利 | ① 内建（新） | 每卡一个按钮 |
| **订单** | 列表·待核对·**拣货单**·导入 | ① 内建（导入从岛收编） | 导入/生成待拣 |
| **货与成本** | 产品·SKU 克重·供应商·拿货对账 | ② 薄内建（批量/导入留岛） | 一次导入（商品信息） |
| **运费** | 运价表 + 试算 | ③ 岛（数据在宿主） | 导报价单 |
| **算钱** | 利润（预测/已结算）+ 成本与汇率 | ① 内建（合并 M2） | 看数/补数据 |
| **设置** | 识别引擎与密钥·列映射·插件·主题 | ① 内建 | — |
| 纯岛（市场） | 店铺账号管家·TV模版·AI 识别加工·报价单解析 | ③ 岛 | 按需装 |

**永不岛**：外壳与导航·主题与快捷键·命令面板·设置中心与插件中心·IPC 与能力门·数据库与迁移·**跨域口径层**（算钱公式、拣货件数口径）。
**永不难内建**：需隔离不受信代码、第三方维护、少数人用行业特化。

## 4. 技术形态（借鉴主流做法）

### 4.1 摄取与主干：单主干 + 适配器
主流做法"一个实体模型 + 多个摄取通道"（解析/清洗在适配器，落同一张表）。现状是两个实体两条链。目标：`orders` + `order_lines`，带 `source`（`import`/`collect`）与 `external_id`；两个适配器（Excel 解析已有 `orderRowSplitter`/`orderMoney`；采集推送已有 `ae-receiver`）。> 风险见 §5-C1（唯一大手术，也可选"两表但一模型"折中）。

### 4.2 口径层：纯函数单源
算钱（`src/lib/orderCost.ts`）与拣货（`src/lib/picking.ts`）已单源，内建页与岛**共用同一实现**（宿主 op 内 `await import('@/lib/…')`）。采集侧口径单源在 **`electron/aeMoney.ts`**（收入 = 商品+买家运费−退款、行收入按行金额占比分摊、退款科目集、`skuProps` 解析）。`ae-engine` 与 `ae-db.collectedOrderRows` **都调它**。**任何跨表/跨域算法只准在 `src/lib/` 写一次**。

### 4.3 能力层：域 op + 门禁
数据表与域 op 永远在宿主（ADR-002 C1/C3）；岛只声明用到域/动作，经权限门调用；内建页走 `core/services/ipc.ts`。**新增功能一律先加域 op，再加界面**。

### 4.4 打包：默认包 = 主干
`standard` 预设重定义为 §3 的"面"所需模块（今天/订单/货与成本/算钱），**不含可选岛**；"装齐"由首启引导一次完成（见 `UX_POLISH_PLAN.md` §2 P1-1）。
