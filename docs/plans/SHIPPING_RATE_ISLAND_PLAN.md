## 0. 结论先行

| 决策项 | 结论 | 依据 |
| --- | --- | --- |
| 岛形态 | **手写 ESM、无构建步骤**（`dist/` 即源码） | 无 npm 依赖、无框架需求；与 `excel-copy` / `order-insight` 同形态，省掉 vite 工程与 `dist/` 产物管理 |
| 解析位置 | **宿主**（读 Excel → 归一化成运价表） | 岛在 iframe 内无 `xlsx`、CSP 无 `unsafe-eval`；与既有两岛的"解析留宿主"策略一致 |
| 计算位置 | **宿主**（纯函数 + db op） | 与解析口径同源，避免两端口径漂移；纯函数可被 vitest 直接覆盖 |
| 数据更新 | 归一化后的运价表落岛自己的 `modules.shipping-rate` 命名空间 | 更新与计算解耦：Excel 换版只需重导一次，之后离线可用 |
| 计费口径 | 普货 / 非普货 / 大包**三类都支持**，按克重自动判定 + 可手动切换 | 报价单本身有三套价，只做普货会让 >2kg 与带电货算不出来 |

关键判断：**运价表归一化后只有约 1.3k 个数据节点**（184 国 × 2–7 张价卡），完全放得进一次 `db.call` 的载荷预算
（`src/core/plugin/payloadBudget.ts` 的 64MB / 5 万节点），因此"每次查询把运价表传给宿主计算"是可行的，
不需要在岛内复制一份计算逻辑。

## 1. 数据模型（先摸清才能设计）

源文件：`ae5a7f6345c82d53575081d63e91b90a.xlsx`（21 个 sheet，默认取「无忧物流-标准」，
可切换到其中 **19 张**—— 覆盖率见 §2.1）。

### 1.1 这张表不是一张二维表，是 **17 张价卡拼在一张 sheet 上**

- 268 行 × 40 列；**17 个分节**，每节 = 3 行表头 + N 行国家数据
- 分节之间的列结构**互不相同**（列位置、档位切分、计价模式都变）
- 全表共 **184 个国家**，且**没有任何国家出现在两个分节**（已逐节比对）——分节是互斥的目的地分组，不是备选方案

| 分节 | 数据行 | 国家数 | 代表国家 |
| ---: | --- | ---: | --- |
| 1 | 16–160 | **144** | 阿尔巴尼亚 … 塞浦路斯（占 78%） |
| 2–7 | 单行 | 各 1 | 俄罗斯 / 乌克兰 / 美国 / 韩国 / 瑞士 / 波兰 |
| 8 | 195–213 | 18 | 奥地利 … 英国 |
| 9–13 | 单行 | 各 1 | 克罗地亚 / 巴西 / 以色列 / 墨西哥 / 智利 |
| 14 | 245–248 | 2 | 马来西亚 / 泰国 |
| 15 | 252–258 | 6 | 捷克 … 葡萄牙 |
| 16 | 262–264 | 2 | 挪威 / 秘鲁 |
| 17 | 268 | 1 | 摩洛哥 |

### 1.2 三种计费类别

| 类别 | 表头字样 | 说明 |
| --- | --- | --- |
| 普货小包 | `小包普货计费` | 无电池 / 非液体化妆品 |
| 非普货小包 | `小包非普货计费` | 含电池 / 非液体化妆品；分节 3 再按 **其他仓 / 香港仓** 分两套 |
| 大包 | `大包计费` / `大包计费（计泡）` | 限重 30kg |

特例：分节 5（韩国）的表头是 `小包普货&小包非普货计费` —— **一个价同时适用两类**，
所以模型里价卡的类别必须是**集合**而不是单值。

### 1.3 两种计价模式

| 模式 | 表头 | 公式 |
| --- | --- | --- |
| `perKg` | `配送服务费 元（RMB）/KG *每1g计重` + `挂号服务费 元（RMB）/包裹` | `费率 × 克重 ÷ 1000 + 挂号费` |
| `firstStep` | `0.5KG首重 元（RMB）/包裹` + `续重(每500G) 元（RMB）/500G` | `首重 + ⌈(克重 − 500) ÷ 500⌉ × 续重`（克重 ≤ 500 时只收首重） |

验算样本（阿尔巴尼亚，普货 0~150g 档）：`209.66 × 100 ÷ 1000 + 18.7 = 39.666` → 39.67 元。

同一个国家的「大包」**可能是两种模式**（摩洛哥：0–5000g 走 `perKg`，5000–30000g 走 `firstStep`），
所以模式是**价卡级**属性，不是国家级或类别级。

### 1.4 重量档位

档位写在表头第 2 行（合并单元格），格式不统一：`0~150g(含)` / `0-2100g（含）` / `2100-30000g` / `限重30kg`。
有的价卡完全没有档位（如分节 1 的大包，只有 `限重30kg`），此时按 `[0, 30000]` 处理。

**「无忧物流-标准」这一节的表头是三行结构**：第 1 行给类别名（跨列合并）、第 2 行给重量档（按"配送+挂号"
两列一组合并）、第 3 行给叶子语义。合并单元格只有左上角有值 —— 这一点决定了归一化算法必须
"向左回溯找最近的合并源"。

⚠️ **但三行只是其中一族**（2026-09-25 用源工作簿 21 张 sheet 逐张实测后修正，见 §2.1）：
燕文 / 超级经济 / 4PX / 顺友 这一大票线路只有 1~2 行表头，且叶子与档位的**上下顺序会颠倒**。
把行数与顺序写死成 `hdr+1` / `hdr+2` 会让这些表全部报「表头结构无法识别，整节跳过」——
文案指向"数据有问题"，真实原因是版式族没覆盖。

## 2. 归一化算法（把 17 种版式收成一种）

核心思路：**不按固定列号解析，而是按语义扫描**。列号一变就崩的写法在这张表上必然失败。

```
对每个分节（hdr = A 列 == '运达国家/地区' 的行）：

① 探测本节表头的**行角色**（detectLayout，行号不写死，见 §2.1）：
     在 [hdr, end) 内逐行统计「叶子语义列数 / 档位列数 / 类别命中数」（遇 A 列非空即停）
     leafRow = 叶子语义列最多的行    zoneRow = 档位列最多的行（排除 leafRow 自身）
     catRow  = 首个出现类别标题的行（无类别标题的表为 -1 → 整表不分品类，类别记 any）

② 扫 leafRow，凡命中叶子语义的列即为「有效列」：
     含「配送服务费」/「重量资费」→ delivery
     含「挂号服务费」/「Item 服务费」/「操作处理费」/「处理费」→ register
     含「首重」→ first   含「续重」→ step   含「最低计费重量」/「起重」→ minCharge（列属性，不建卡）
     其余（如「限重30kg」）丢弃

③ 每个有效列向左回溯定位两个「合并源」（**回溯不得越过类别起点**）：
     groupStart = 最近的、catRow 有值的列  → 决定类别（普货/非普货/大包）+ 变体（其他仓/香港仓）+ 限重
     zoneText   = [groupStart, 本列] 区间内最近的、zoneRow 有值的单元格 → 决定重量档

④ 相邻配对成价卡：delivery 后紧跟同组同档的 register → 一张 perKg 卡
                  first    后紧跟同组同档的 step     → 一张 firstStep 卡

⑤ 数据区起点 = max(leafRow, zoneRow) + 1（叶子在上、档位在下时 max 才落在档位行上）
   逐数据行取数值，构造「国家 → 价卡[]」；minCharge 列的值也在此逐行取（它写在数据行里）

⑥ 整节收齐后**再**决定是否采纳：同一目的地在一节内占多行 → 该节是「行式分档表」，整节拒绝
```

### 2.1 表头版式是一族，行角色只能探测

实测源工作簿 21 张 sheet（覆盖率 3/21 → **19/21**）：

| 版式 | 表头行数 | 实例 | 备注 |
| --- | --- | --- | --- |
| 类别 / 档位 / 叶子 | 3 行 | 无忧物流-标准、特惠、优先、三方清关 | 唯一有"类别标题"的一族 |
| 档位 / 叶子（无类别） | 2 行 | 燕文航空挂号小包、超级经济全系列、顺友、威海优选仓 | 整表不分品类 → 类别记 `any` |
| 叶子 / 档位（**上下颠倒**） | 2 行 | 无忧物流-特货标准、特货标快 | 数据起点必须取 `max(leafRow, zoneRow) + 1` |
| 只有叶子 | 1 行 | 4PX新邮挂号小包、部分超级经济 | 限重写在叶子文本里（`*每1克计重，限重2KG`） |
| 分档行式宽表 | —— | 海运大件专线、超大件专线、优先/特货标准的部分分节 | **不支持**，见下方第 ⑥ 步 |

两个并列的事实：

- 探测三行的**角色**而不是**位置** —— 固定偏移 `hdr+1` / `hdr+2` 在 2 行表上会把**数据行**当成叶子行；
- 探测时必须把「最低计费重量」列**排除在叶子命中之外**，否则表头行会被判成叶子行、真正的档位行被挤掉，
  整节档位退化成 `[0, 30000]`（超级经济-燕文就是这么从 `[0,100]/[101,2000]` 退化的）。

**六个必须写成守卫的点（否则会静默算错）**：

- **回溯必须被 groupStart 截断**。否则分节 1 的大包列（L/M）会向左回溯到非普货的 `0~2000g(含)`，
  把大包错当成 2000g 档 → 大包报价全部算错且不报错。
- **类别判定先剔除「非普货」再找「普货」**。直接 `includes('普货')` 会让 `小包非普货计费` 同时命中两类。
- **档位解析对缺失要退化为 `[0, 30000]` 而不是 `[0, 0]`**。后者会让所有大包查询返回"超出档位"。
- **档位文本里两个相同数字 = 只说上限**。`2KG以内（包含2KG）` → `[2g, 2g]` 会造出一张只覆盖 2 克的价卡；
  且单位必须按**整段文本**判 kg/g，不能只看数字。
- **本列档位优先于整组限重**。摩洛哥大包两档（`0-5000g` 按 KG / `5000-30000g` 首重续重），
  组标题写着「大包计费 限重30kg」—— 让限重盖过档位会把首重续重档整段吃掉。
- **叶子同义词必须成套**。`Item 服务费`（燕文/超级经济/顺友 6 张表）就是「挂号服务费」，
  漏一个等于那半张表的费用整列丢失，界面仍会给出一个偏小的金额。

## 4. 数据更新机制（需求明确要求）

| 环节 | 做法 |
| --- | --- |
| 存什么 | **归一化后的运价表**（不是原始 AOA）。体积小、查询快、且不受源文件后续改动影响 |
| 存哪 | 岛自身命名空间 `modules.shipping-rate`（`storage` 能力的自身命名空间恒放行，无需额外声明） |
| 怎么更新 | 「运价表」页 →「导入 / 更新运价表」→ 对话框选 Excel → 宿主重新解析 → 整体覆盖 + 落盘 → toast 报告新旧国家数对比 |
| 换版怎么做 | 不需要改代码。Excel 的新版只要仍是「含「运达国家/地区」表头 + 分节」结构，重新导入即可（表头 1~3 行、叶子与档位上下颠倒都支持，见 §2.1） |
| 结构变了怎么办 | `normalizeRateSheet` 返回 `warnings`（未识别的分节 / 缺数值的价卡），「运价表」页原样展示，不静默吞掉 |
| 源文件被移动/删除 | 不影响已有报价（数据已入库）；只有"再次导入"时才需要文件 |

**为什么不存原始 AOA**：268×40 的二维数组序列化后远大于归一化结果，且每次查询都要重新归一化。
代价是归一化算法的改进需要重新导入一次 —— 已在 README 中写明。

## 5. 计费口径与边界

- **自动判定**：克重 ≤ 2000g → 普货 → 非普货 → 大包 → `any`；克重 > 2000g → 大包 → 普货 → 非普货 → `any`。
  `any`（该表不分品类）**永远排在最后**：让有明确类别的价卡先说话，但任何类别的查询都能落到它身上。
- **手动切换**：普货 / 非普货 / 大包 / 自动 四态。强制某类时只用该类 **+ `any` 兜底**；
  都命中不到 → 明确提示"该重量段无可用运价"，不静默回落到别的类别。
- **变体**：非普货有 `其他仓` / `香港仓` 两套价（仅乌克兰），默认取无变体价卡，可手动指定。
- **最低计费重量**：报价单有单列「最低计费重量 10g」/「起重 克」→ 计费克重 = `max(实际克重, 该值)`。
  不套用会少算（金额小，但与承运商结算口径不一致）。
- **币种**：只按人民币计价。表头写 `美元（USD）/KG` 的线路（`超级经济` / `无忧物流-特惠`）**明确拒算**
  并说明"未接汇率"，**不套人民币的壳**（差 7 倍且金额看起来完全正常）。
- **超出档位**：返回"该重量段无可用运价"并给出该国可用档位范围，不返回 0。
- **取整**：默认四舍五入到分；可切换为"向上取整到分"（报价单实际多为进位）。
  两种口径都只在 `computeFee` 一处实现。
- **不在本方案内**：体积重（`长×宽×高/8000`）、单边 >60cm / 合计 >90cm 的大包判定、燃油附加费、
  汇率来源。报价单里前三项是"包裹属性"而非"运价数据"，本岛只按用户输入的实际克重计算。
  留作后续增量（见 §8）。

## 6. 守卫（把静默失效钉死）

| 守卫 | 挡什么 |
| --- | --- |
| `normalizeRateSheet` 对**真实 Excel 导出的夹具**断言 184 国 / 17 分节 / 两类模式价卡数 | 版式理解错位（最核心的一条） |
| 分节 1 大包不被回溯到非普货档（显式断言 `minG/maxG`） | §2 的"回溯未截断"陷阱 |
| `小包非普货计费` 不产生 `general` 类别 | 类别判定陷阱 |
| 验算样本：阿尔巴尼亚 100g → 39.67 元；大包首重/续重阶梯 | 公式错（差 10 倍 / 100 倍这类） |

| 7 | 按订单试算的**重量口径** | 只用「商品信息」的单件净重 × 1；体积重（长宽高/8000）、包材重、合单重量分摊都不在内 —— 与 §5 的"包裹属性不进运价表"同一原则 |
