> 设计：UI Designer ｜ 审查日期 2026-11-03 ｜ 对照稿：[`docs/mockups/UI_PROPOSAL_2026-11-03.html`](../mockups/UI_PROPOSAL_2026-11-03.html)
> 审查对象：`src/` 当前构建产物 v1.1.0（`profile: standard`，含 today / shop-accounts / mail / order-cost / ledger / quick-note）
> 方法：真产物无头渲染取证（4 张）+ 令牌与模板级代码审计

## 0. 一句话结论

**控件层已经干净了，缺的是"节奏"。**
按钮 / 输入 / 标签 / 五种骨架都已收敛到 `src/styles/index.css` 的 `@layer components`，模板里的字号硬编码只剩 23 处 —— 这部分不必再动。
让它"看起来还是一块灰"的是三件与控件无关的事：**级差**（五档字级挤在 12–17px，相邻只差 0.5–2px）、
**留白**（面板一律撑满，2 行数据下面留 400px 死白）、**发声**（全屏唯一彩色是警告橙，同屏出现两条几乎一样的橙条）。

所以本方案的第一条纪律是：**一个颜色都不加**，只把级差拉开、把留白收住、把发声点从 N 处收到 1 处。

> 与既有审查的分工：`docs/reviews/UX_REVIEW_2026-09-30.md` 与 `...R2` 审的是"功能能不能走通"，
> `docs/plans/GOODS_TAB_REDESIGN_2026-10-25.md` 审的是"信息架构要不要减"。
> 本文只审**已经能走通的东西长什么样**，不重提它们的结论，也不改数据模型与能力域。

## 2. 四个视觉病根

### A · 级差过窄

页标题 17px、主数字 15px、正文 13px、说明 12.5px、表头 12px —— 五档之间相邻只差 0.5–2px。
在 1440 宽的窗口里这等于没有层级：用户扫屏时找不到"从哪开始读"。

```
取证 src/styles/index.css:
  .wb-head__title   font-size: 17px
  .wb-metric b      font-size: 15px
  .wb-table         font-size: 13px
  .wb-head__desc    font-size: 12.5px
  .wb-table th      font-size: 12px
```

### B · 数字不是主角

`.wb-metric` 是 `inline-flex` + `align-items: baseline`，标签 12.5px、数字 15px —— **只差 2.5px 且横向串读**。
「订单行 1　收入合计 165.18」读起来是一句话，用户得逐字读完才知道哪个是数。
业务是"看数、点单"，数字却与说明文字同级。

### C · 死白无收束

面板一律 `flex: 1` 撑满容器，空白留在面板**内部**：2 行数据下面 400px 纯白，没有任何"到这为止"的信号。
用户感知不是"内容少"，而是**"是不是没加载完 / 下面还有"**。

### D · 发声点太多

全屏唯一强色是 `--wb-warning`，而它同时出现在两条几乎相同的提示条上
（「1 家店还没登记，卖出去的挂不上款: 新奇怪物店」/「1 家店还没登记，采回来的先认不了: 芒果旗舰店」，`full-1440x900.png` y≈140 与 y≈168）。
**同一条根因拆成两条并列** ⇒ 橙色从"注意"退化成"背景噪音"，这一屏之后它就不起作用了。

## 3. 五条原则（出现分歧时用它裁决）

1. **一个焦点** —— 每屏只允许一个实心主按钮 + 一个最大字号数字。出现第二个要能解释"凭什么同级"。
2. **级差 ≥ 1.25×** —— 相邻字级差 1.25 倍以上（13 → 16 → 20 → 26）。差 2px 不算层级。
3. **安静默认，一处发声** —— 强色底（warn / danger / 实心主色）同屏最多一处；同根因多条合并为「N 条 › 去看」。
4. **位置恒定** —— 动作钉在它作用的对象上（列表头 / 行尾 / 段尾），不随数据量漂移；常驻条只在有内容时存在。
5. **手不离键** —— 高频动线（导单 → 归类 → 拿货 → 对账）全程可键盘。

## 4. 规范

### 4.1 字阶：等差 2px → 比例级差

| 角色 | 现状 | 建议 | 倍率 | 说明 |
| --- | --- | --- | --- | --- |
| Hero 数字 | 15px | **26px / 650** | — | 每屏唯一的"今天要处理多少" |
| 页标题 | 17px | 17px / 650 | 1.53× | 不动（17 是对的，断的是它下面） |
| 面板标题 | 13px | 14px / 650 | 1.17× | 与正文拉开半档 |
| 正文 / 表格 | 13px | **12.5px** | 1.40× | 不升反降：桌面高密度工具，密度是资产 |
| 表头 / 说明 | 12px | 11.5px | 1.09× | 辅助信息（仍在可读下限 11px 之上） |
| 徽标 / 单位 | 12px | 10.5px | 1.10× | 仅 pill 内，配 `tabular-nums` |

**只升两处（Hero 数字、面板标题），降的是辅助级 —— 总密度不变，这是"拉开"不是"放大"。**

### 4.2 指标条：标签在上、数字在下，且不改一行 DOM

`.wb-metric` 里必须是 `标签 <b>数字</b>` **同一串文本**（三个冒烟脚本用 `textContent` 做子串断言，拆成兄弟元素会拼成 `产品2` 直接变红）。
所以用 CSS 反转视觉顺序，DOM 一个字不动：

```css
/* src/styles/index.css · @layer components */
.wb-metric {
  flex-direction: column-reverse; /* 视觉：数字在上、标签在下；读屏与 textContent 顺序不变 */
  justify-content: center;
  align-items: flex-start;
  gap: 0;
  padding: 8px 18px;
  min-width: 96px;
}
.wb-metric b {
  font-size: 20px; /* 常规指标 */
  line-height: 1.25;
  letter-spacing: -0.02em;
}
.wb-metric.is-hero b {
  font-size: 26px; /* 每屏最多一处 */
}
.wb-metric span { font-size: 11.5px; line-height: 1.2; }
```

这套改法**零 DOM 变化、零断言影响**，是本次唯一"纯 CSS 就能拿到大幅收益"的一处。

### 4.3 留白节奏

| 场景 | 现状 | 建议 |
| --- | --- | --- |
| 面板内数据不满 | `flex:1` 撑满，空白留在面板内 | 面板 `align-self: start`（高度自适应），空白归画布 |
| 列表结束处 | 无 | 收束行「共 2 款 · 已全部显示」（11.5px muted，贴最后一行下 8px） |
| 整页无待办 | 一片空白 | 紧凑空态 `.wb-empty--sm`：图标 32px、padding 52px → 28px |
| 双栏比例 | 左 420 / 右 520（固定） | ~~左 38% / 右 62%（`minmax(0,38fr)`）~~ **已否决，见 §7 落地记录** |

### 4.4 侧栏层级

二级项当前带 14px 图标、与一级项**同尺寸同色**，视觉上像一列平级项。改法：
去掉二级图标，改用左侧 1.5px 引导线（`left: 21px`，对齐一级项图标中心）+ 字号降一档（12.5px）+ 文字色 `--wb-text-muted`（当前项除外）。
**引导线是"从属"最省的表达**，不需要第二层背景色。

## 6. 键盘动线

现状：焦点环已补（`:focus-visible`），但**没有任何快捷键约定**。这个软件一天用很多次、每次做同样几件事，效率天花板在键盘上。

| 按键 | 作用域 | 行为 |
| --- | --- | --- |
| `↑ ↓` | 表格 | 移动当前行（**不改勾选**：选中是"标记要处理"，移动是"看下一行"） |
| `Space` | 表格 | 勾选 / 取消当前行 |
| `Enter` | 表格 / 抽屉 | 进详情 / 提交主操作 |
| `⌘ Enter` | 抽屉 | **提交并继续下一项** —— 连续录入（认款、批量改价）唯一省力的地方 |
| `Esc` | 抽屉 / 弹层 | 关闭；有未保存改动时先问一次 |
| `⌘ Z` | 全局 | 撤销上一步写操作（toast 上给「撤销」，3 秒内有效） |
| `⌘ K` | 全局 | 已有；是否纳入模块内页签见 D-3 |

**已落地的是前三行的表格部分**（2026-11-03，货品产品表 + 待认表 + 已认映射表）：`src/core/composables/useRowNav.ts`
一个组合式函数，表上挂 `tabindex="0"` + `@keydown`。其余表格接同一份，不各写一套 —— 键盘约定一旦有两份实现，
就会出现"这张表 ↑↓ 能动、那张表不能"的随机体验，而没有任何报错提示这件事。

**已认表带出的一条新约定**：`onToggle` 是**可选**的。这张表没有 checkbox、没有批量出口，
所以不传 —— `Space` 整条交还页面（照常滚动），而不是塞一个空回调把按键吞掉。
塞空回调的坏处不是"没反应"这么简单：它把"这张表不支持勾选"这件事从代码里抹掉了，
将来有人补上真实现时，行为会从"没反应"直接跳到"勾上了"，中间没有任何痕迹。

⚠️ 三条只在实现时才发现、方案里没写的事：

1. **`tr` 不可获焦**：`tabindex` 加在行上会造出 N 个焦停点（表一长 Tab 就废了）。所以焦停点给**表**，
   `↑↓` 在表内移动；并且**点完一行要把焦点收回表上**（`selectRow` 里 `focus({preventScroll:true})`），
   否则"鼠标点了行、接着按 ↓"什么都不会发生 —— 键盘动线只对纯键盘用户有效。
2. **焦点在行内控件上必须让路**：表里布满勾选框与行尾按钮，`keydown` 从它们冒泡上来。
   不判的话 Space 是"原生切换 + 我们又一次" ⇒ 勾上又立刻取消，用户看到的是**"按了没反应"**。
3. **首尾不环绕**：到底停住。环绕意味着再按一下跳回顶部，在长表里会让人瞬间失去位置感。
