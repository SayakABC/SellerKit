# 体验优化计划（UX_POLISH_PLAN）

> **性质**：对 [`docs/reviews/UX_REVIEW_2026-09-30.md`](../reviews/UX_REVIEW_2026-09-30.md) 的**复核 + 实施计划**。
> 不是新方案 —— 审查里的每一条都逐条复核过（含取证是否成立、改法是否与既定架构冲突、代价算没算够）。
>
> **两个视角**（本计划的每条都同时过这两关）：
> - **开发**：改动落在宿主外壳还是岛（岛＝一次发版：发布口 + 本机同步 + 重启宿主）· 会碰哪些守卫/契约 · 是否动数据模型。
> - **一线运营**（一个人卖货，要的是"货卖出去、钱算清楚"）：这一步**省掉了几次手动接力**、有没有让"我该做什么"更清楚；
>   不能只让界面更好看 —— 那不算优化。
>
> **判据总原则**：**先做"零发版 + 直接减少用户手工步骤"的**；需要发版的积攒成 **1~2 批**再一次发出。

## 3. 不采纳 / 改法清单（含理由）

### 3.1 ❌ 不采纳：把「订单归类」移回默认包（UX-G1 选项 A）

**审查的建议**：源头功能没有前置依赖，放回默认包收益最大。

**为什么不能这么做**（开发视角，三条硬约束）：
1. **与红线 23 直接冲突**：内建模块会占用同名 id，`managerDiscover` 见 `records.has(id)` 即**静默跳过** →
   市场安装的同名岛永远没有入口。移回默认包 = **市场版「订单归类」作废**（用户只能二选一，且切换要重装）。
2. **留档的内建版是旧的**：`extensions/order-insight/` 是下记时的 Vue 源码（留档，不进构建），
   而**在维护的实现在 `ui-plugins/order-insight/dist`**（手写岛，1.5.0 刚加了拣货页签）。
   "移回默认包"等于**复活一份停更的旧实现**再丢掉维护中的那份 —— 这是净损失。
3. **默认包大小与语义**：`MODULE_PROFILE`/`MODULE_IDS` 的存在说明"打哪些模块进包"是产品化选项；
   把数据源头塞进默认包，会让"精简外壳 + 按需装"这条已定路线反复。

**替代做法（已进 P1-1）**：留岛，但把"装"这一步变成**两下点击**：侧栏/空态给"安装「订单归类」"按钮 +
首启推荐包卡片 + 离线文案。**收益（新用户走通第一条链）不变，代价小一个量级。**

### 3.2 ⚠️ 改法：任务向导 → 先做"只读就绪检查"

**审查的建议**（P1-1）是把三条链做成**步骤条**（每步"已就绪/待完成/缺什么"、点击直达）。

**我的判断**：方向对（"我现在该做什么"确实是最大的体验缺口），但**完整向导代价大且会漂移** ——
步骤的"就绪判据"散落在各岛（订单量、店铺归一、映射、克重、运价表、成本各有各的口径），
宿主只能看到其中一部分（`shop` / `product` / `ship-rate` 在宿主侧，订单量在 `oi_orders` 也在宿主侧 ✓
但"映射是否 confirmed"「克重是否导入」等判定逻辑在岛里），硬做就会出现"向导说就绪、页面里算不出"。

**改法**：v1 只做**宿主能自证的部分**：一个只读「待办/就绪」卡片（放侧栏或模块首屏），每项 = 一句"现状 + 缺什么 + 跳转"，
**判据只用宿主自己的表**（订单行数 / 未归属店铺数 / 产品与 SKU 数 / 运价表快照是否存在 / 成本行数），
拿不到的项**不猜**（写"详见对应功能"）。等用户真实用起来后再决定要不要升级成向导。

### 3.3 ❌ 取证不成立（已过时）

- **C3 的"两个入口互不说明"** —— 成立，但源头是**上一步刚按需求做的 P5**（岛内页签），不是历史遗留；
  处理见 §4-UX-P2（要拍板去留，不是单纯改文案）。
- **A1 里"拣货页也指向订单归类"** —— 实际没有指向（`PickingView.vue:67` 只写了操作提示）。
  **但比"指向不存在"更糟**：它**没有告诉用户订单从哪来**，且"生成后为空"时仍显示"点生成"（见 §0 末）。

### 3.4 ❌ 不采纳：合并两条重量数据源（E1 的深层改法）

审查只建议"互相说明"，我同意；但更深的"统一成一张表"**不做** —— 这是**刻意的两条源**
（按订单试算用 `pl_item_weights`（键=商品ID）／按产品试算用 `pl_variants.weight_g`（键=SKU）），
合并需要数据模型变更 + 两条链口径重定，收益（少导一次 Excel）远小于风险（运费算错）。
