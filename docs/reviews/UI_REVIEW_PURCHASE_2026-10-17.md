## §2 问题清单（现象 → 影响 → 改法）

### 1. 【P0】未指定厂家卡的「复制清单图」是假动作

- **现象**：`copyingId = ref(0)` 以 0 表"空闲"；而"未指定厂家"卡的 `supplierId` 恰为 0。`copyingId === c.supplierId` 即 `0 === 0` 恒真 ⇒ 该按钮**恒渲染为「生成中…」且 disabled**（两组截图均可见）。
- **影响**：这一格的用户永远无法复制清单图；且"生成中…"常驻会让用户以为卡在什么任务上。这是项目明令禁止的"假动作"形态。
- **改法**（三行）：
  ```ts
  const copyingId = ref<number | null>(null);          // null = 空闲
  // copyForSupplier 开头：if (copyingId.value !== null) return;  finally 里置 null
  // 模板：:disabled="copyingId !== null && copyingId === c.supplierId"
  ```
  注意 `copyingId` 的守卫 `if (copyingId.value) return` 要同步改成判 `!== null`。

### 2. 【P1】页签徽标与页内数字不同源

- **现象**：页签「拿货 1 款色」来自 `purchaseCounts().gap = purchaseOutstanding().rows.length`（`today/purchase.ts:330`）；点进去卡面是「合计 2 款色 · 待拿 3 件」，两张待拿卡合计 3 款色 4 件。
- **影响**：用户在页签上建立的预期与页面实际对不上；这正是项目铁律"同屏并列的两个数必须同口径"要拦的场景。
- **改法**：徽标改读与清单同源的数（`reload()` 里 `aggregatePicking` 已算过 `picking.sku`，但那是"未发货近 30 天"口径，含已忽略——需按 `pendingOf` 判据取一次"待拿款色数"），或在徽标 title 里写清口径。**口径选哪个属业务决策，见 §4-G2。**

### 3. 【P1】宫格等高拉伸 → 矮卡真空

- **现象**：`.pu-grid`（`PickingView.vue:1383`）未设 `align-items`，grid 默认 stretch ⇒ 同行的瘦卡（未指定厂家 / 暂不拿 / 已拿）被拉成与最高全卡等高；卡内吸底块 `margin-top:auto` 把动作钉到拉高后的卡底，**中部出现大片空白**（1440 图的"未指定厂家"卡、1152 图更明显）。
- **影响**：第三轮"瘦卡一行高起"的设计意图被 stretch 抵消；页面看起来"空而散"。
- **改法**：`.pu-grid { align-items: start; }` —— 一行 CSS，瘦卡立刻缩回内容高。注意验证同行混排时卡底不再横向对齐（那本来就是瘦卡，可接受）。

### 4. 【P1】拖拽改厂家零可发现性

- **现象**："款色行可拖到别家的格子"这条新能力，唯一提示是行 `title`（悬停才出现，`PickingView.vue:955`）。截图上没有任何可拖的视觉线索。
- **影响**：功能等于不存在；知道的人也会先误以为行不可交互。
- **改法**（按成本递增任选）：① 款色行左缘加 grab 手柄（`⋮⋮` 六点图标，`cursor: grab` 已有）；② 卡头「待拿」签旁加一句常驻微文案"行可拖到别家改厂家"；③ 首次进入本页签时 toast 一次（最少侵入）。**不建议**弹引导层。

### 5. 【P1】已忽略折叠头的说明文字常驻

- **现象**：收起态整行显示「已忽略 1 项（无需补货）按「款编码 + 款色」整组生效；取消后该款色所有尺码会重新回到缺口……展开」——后半段是**展开后才需要的后果说明**，且出现「款编码」内部术语。
- **影响**：低频信息占据了每屏一行；折叠的价值（低频折起来）被自己稀释。
- **改法**：说明 `<span>` 挪进 `v-if="showIgnores"` 的展开区（表格上方一行）；收起态只留「已忽略 N 项（无需补货）」+「展开」。断言按 `pu-ignore-table` 仍在展开区选，不受影响。

### 6.【P2】编辑器空行显示 0 值

新加的空行直接渲染「实拿 0」「金额 0.00」，读起来像"实拿了 0 件"。建议：`qty` 未触碰过时显示 placeholder（`0` 改 placeholder="0"），金额列在 qty×price 均空时显示「—」。

### 7.【P2】弹层 Esc 与焦点管理

编辑抽屉与确认弹层都无 `keydown(Escape)`（一致地缺）。桌面用户 Esc 关弹层是肌肉记忆。建议在 `wb-mask` 层统一接管 Esc（关最上层），顺带补焦点陷阱。两处一起做才一致。

### 8.【P2】两个复制按钮难分辨

「复制拿货清单」（文字）/「复制清单图」（图）是两个同级 sm 按钮，扫读时只差一个词。建议：清单图升为次主按钮或加图标（图/文档），文字清单降为 `wb-link`；tooltip 各写一句"给谁用"（图→照着备货，字→转发备忘）。

### 9.【P2】已拿卡半透明压灰

`opacity:0.72` 让整卡文字对比度打折（muted 字再乘 0.72 已接近 AA 下限），且视觉上与"暂不拿"灰卡趋同。建议去 opacity，改弱化手段：淡边框 + ✓ 徽标 + 状态签即可承载"安静"。

### 10.【P2】顶部精简条空悬

第五轮撤壳后该行左半永远空白，与页签行之间形成一条"什么都没有"的行。彻底解法是动作并入页签行右端（跨组件，见 §4-G1）；保守解法是接受现状（有 loading 时左侧会出现"正在汇总…"，不算全空）。

### 6.1 修复过程新发现的 P0：敲单价 ⇒ 编辑器整个消失（已修 + 守卫）

修 #6（空行金额「—」）时引入的 `rowAmountText` 直接调 `r.priceText.trim()`，被截图脚本的填行阶段当场打崩——**且这是真实用户必踩的回归**：

- **根因**：`pue-price` 是 `<input type="number">`，其 `v-model` 会把用户输入 **coerce 成 number**（变异实测确认，不是 string）。`priceText` 类型虽声明 `string`，运行期敲价后是 number ⇒ `.trim()` 抛 `TypeError: e.priceText.trim is not a function`。
- **症状隐蔽**：崩在**渲染期**，不走 `window.onerror`，只有 `console.error`；Vue 把整个编辑器组件卸载 ⇒ 现象是"一敲单价抽屉自己消失"，无任何报错浮出（`errs:[]`、`close()` 未被调用、无 `purchaseOrderUpdate`——三个方向都排空后才靠覆盖 `console.error` 逮到）。
- **修法**：`String(r.priceText ?? '').trim()` 防御式包一层（`rowCents` 本就用 `Number()` 吃两种，别处无此坑）。
- **守卫**：`today-ui-smoke.mjs` 新增「敲单价：编辑器不崩」断言（往 `pue-price-1` 敲 25.5 ⇒ 断言编辑器仍在 + 金额格实时重算 ¥76.50）。**变异验证**：还原崩溃版重构建 ⇒ 该断言精确变红（`editor-unmounted`）且后续步骤连锁失败；还原修复版 ⇒ 回绿。
- **方法论沉淀**：对"元素在不在"类冒烟，渲染期崩溃只会表现为"元素消失"，断"元素在"恰好是唯一抓得住它的姿势；而合成事件脚本（`el.value=` + `dispatchEvent`）与真实输入同路径，能复现真实用户敲键的后果。

### 6.2 截图脚本的定位链路（方法论）

`purchase-shot.mjs` 填行阶段抽屉消失的定位顺序，复用价值在于**排除法次序**：先 IDLE-CHECK 排除"放着就坏"→ 拦 `keydown`/`click` 排除误触 → 拦 `Node.removeChild` 抓卸载栈（确认是 Vue 主动卸载）→ `window.__smokeCalls` 排除保存路径（`upd:0`）→ 源码 `close()` 埋栈排除主动关闭（`cp:null`）→ 最后覆盖 `console.error` 逮到渲染崩溃。每一步都把一个假设钉死，剩到最后一个解释为止。
