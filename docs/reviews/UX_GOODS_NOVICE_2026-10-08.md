## §0 结论速览

**一句话诊断**：这一页在**数据与工程上是成熟的**（三栏口径、状态区分、空态与失败回执都做得比多数产品页好），但它把用户**假定成一个已经懂"款 / SKU / 映射 / 店铺归一"这套模型的人**；对不会电脑的人，**它是一堵术语墙 + 一张需要同时看两边的表 + 一组看不见的鼠标/键盘约定**，而且**没有任何一处告诉他"第一步做什么"**。

## §2 问题清单

### A 上手与前置

**A-1（P0）页内没有"起点"。** 页首只剩「页头 + 页签」两层（`GoodsView.vue:19-27`）；「起点引导条」已按用户要求整体撤除（见 `../notes/2026-10-08-goods-page-entry-guide.md:3-8`）。对熟练用户这是"少占一行"，对非技术用户这是"没有说明书"。**注意 §3：我不重提被撤的那条常驻步骤条。**

**A-2（P0）唯一跨越"能力缺口"的提示是不可点的长句。** `PoolPane.vue:86-89` 完整原文：

> 下面这些店铺还没归一，它们的商品**无法**写映射（订单里没有平台，平台只能从店铺实体取）：**XX**。请先到「店铺账号管家」的「店铺登记」把门店认下来，再回来刷新。

整句是**给开发者看的**（"写映射""平台只能从店铺实体取"）；对用户唯一有用的信息是"去某个地方登记一下店铺"，而那**不是按钮**。同类还有 `PoolPane.vue:243-251` 的 disabled 按钮 title。

**A-3（P0）"店铺账号管家"是需要**另行安装**的 UI 岛，默认包里没有。** 默认预设只含 `today / goods / quick-note / order-cost / picking`（`modules.config.json:42`）；「店铺账号管家」只在插件市场分发（`market-out/catalog.json`，线上版本 1.5.2）。⇒ 新装的软件上，用户**根本看不到**这个入口，也不知道要去插件中心装。这是本页唯一的**硬死锁**。

**A-4（P1）左栏与右栏的空态把用户指向两个不同的"第一步"。** 左栏说「导入 Excel / 新增产品」（`ProductPane.vue:349-368`），右栏说「去「今天」导入订单」（`PoolPane.vue:271-287`）。真实顺序是从订单来（队列是订单的实时聚合，`PoolPane.vue:275`），但页面没有告诉用户先做哪个。

### B 术语与文案

**B-1（P0）术语密度。** 同一屏内的领域词：`款编码`、`款式名`、`SKU`、`克重`、`缺 N`、`待关联队列`、`已建立映射`、`店铺未归一`、`关联率`、`映射记录`、`订单行`、`平台`、`店铺原始`、`标失效`、`建档`、`存量订单`、`款主图`。取证：`ProductPane.vue:172-175,217-221,353`；`PoolPane.vue:28,40,59-69,275`；`useSkuPool.ts:534-539`。

**B-2（P0）同一个东西三个名字 —— 产品 / 款 / 款式。**

| 词  | 出现处                                                                                     |
| -- | --------------------------------------------------------------------------------------- |
| 产品 | `ProductPane.vue:348`「还没有产品」；`:57`「新增产品」；`SupplierView.vue:8`「「产品」页」                    |
| 款  | `GoodsView.vue:164`「给自己的款…建档」；`ProductPane.vue:131`「已选 N 个款」；`:172`「款编码」                |
| 款式 | `ProductPane.vue:173`「款式名」；`SupplierView.vue:8`「给款式指定用哪家」；`ProductImportDialog.vue:117` |

**B-3（P0）同一个动作三个名字 —— 映射 / 关联 / 认。**

| 词  | 出现处                                                                                          |
| -- | -------------------------------------------------------------------------------------------- |
| 关联 | `PoolPane.vue:28`「待关联队列」；`:111`「关联到 S1」；`useSkuPool.ts:173`                                  |
| 映射 | `PoolPane.vue:40`「已建立映射」；`:68`「映射记录」；`:87`「无法写映射」                                            |
| 认  | `PoolPane.vue:264`「还没有要认的商品」；`GoodsView.vue:164`「把店铺商品认到款上」；`ProductPane.vue:302`「把商品认到这个款上」 |

**B-4（P0）"缺 0" 逐行重复**（对应"全零不是正确表达"）。`ProductPane.vue:217-221` 对每一行都渲染 `SKU 数 · 缺 N`；一款 SKU 齐全的货，用户看到的是"`3 · 缺 0`"。列表全齐时要读 N 个 `缺 0` 才能确认"都齐了"。**建议：`missingOf>0` 才渲染，否则整段不出现。**

**B-5（P0）指标条五项全零也铺满。** `PoolPane.vue:59-69` 常显 `待关联 / 店铺未归一 / 已关联 / 关联率 / 映射记录`。空库时是"0 · 0 · 0 · — · 0"，读起来像"页面坏了"。

**B-6（P0）空态文案偏"讲原理"。** `ProductPane.vue:353`：「产品库是订单 / 采购 / 成本三域的关联锚点 —— 先建档，后面才有得算。」改法：一句人话 + 一个按钮（"先建第一款货"）。

**B-7（P1）成功回执带行话。** `useSkuPool.ts:534-539` 的 toast 含「已自动关联 12 行**存量订单**」「把 2 张订单图设为**款主图**」。

**B-8（P1）"问题件"这个词不指向它真正做的事。** `ProductPane.vue:39-51` 的下拉叫「问题件」，选项是「缺克重 / 未关联供应商」。用户不会想到"补重量"在"问题件"里。

### C 交互门槛（鼠标精度 / 隐式约定 / 快捷键）

**C-1（P1）多选 + 批量 + 物理删除。** 每行一个复选框（`ProductPane.vue:162-169,198-205`），选中后浮出「已选 N 个款 / 批量编辑 / **删除选中** / 清空选择」（`:130-146`）；删除确认里写明"**物理删除且不可撤销**"（`:478-481`）。对不熟复选框的人，"勾了什么"本身就不易察觉，而后果是不可逆的。

**C-2（P1）信息藏在行展开里。** 供应商 / 类目 / 操作 / SKU 子表 / 已关联商品全在 `row-detail`（`ProductPane.vue:232-337`），靠行首那个 `▸/▾` 小三角触发（`:187-196`）。没有任何提示告诉用户"点这一行会打开更多"。

**C-3（P1）关键说明挂在悬停 `title` 上。** 平台标签（`PoolPane.vue:192`）、来源与更新时间（`:342`）、"点击看大图"（`:209`）、禁用原因（`:248`）——`title` 要鼠标悬停约 1 秒才出现，触屏不可得，不熟鼠标的人也发现不了。

**C-4（P2）编辑抽屉里的"按住拖动可连选 / 连消"。** `ProductEditorDrawer.vue:117,127-129` 的拖选是纯鼠标约定（键盘不可达）。公平地说：**单击也能选**（`sizePress` 在 mousedown 上切换），拖拽只是加速器，不构成阻塞；但"按住拖动"这句提示会让新手不敢动。

**C-5（P2）对比认款的键盘提示。** `CompareModal.vue:59` 写着「← / → 换候选 · 空格 关联 · Esc 关闭」。公平地说：**同屏已有可点的「← 上一款 / 下一款 → / 关联到 xx / 关闭」按钮**（`:53-60`），键盘只是加速器。建议把提示降级为次要文案，别让新手以为"必须用键盘"。

### D 状态反馈与危险操作

**D-1（P1）破坏性操作"两个词"的选择成本高。** 「删除」（物理、不可撤销）与「标失效」（可恢复）是两种语义，但界面上分处两处：删除在左栏行展开（`ProductPane.vue:327-333`），标失效在右栏「已建立映射」（`PoolPane.vue:405-414`）。新手分不清"停用 / 标失效 / 删除"三者区别——**页面上有三个"让它消失"的词**（停用 `:222-225`、标失效、删除）。

**D-2（P1）「恢复」藏得很深。** `PoolPane.vue:395-404` 的「恢复」只在当前行 `status === 'invalid'` 时出现，而「已建立映射」默认筛选是"全部状态"→ 失效行确实在列表里，但用户要先切分段、再在长列表里找到那一行。没有"有 N 条已失效 → 查看"的汇总入口。

**D-3（P1）保存模型一半一半。** `ProductEditorDrawer.vue:248-251` 明确写着：主图与 SKU 是**即时保存**，而表单（编码 / 名称 / 供应商 / 类目 / 状态 / 备注）要按底部「保存」。底部只有「取消 / 保存」两个按钮（`:226-236`），「取消」**不提示有未保存改动**就会关掉。对新手 = "我填了，然后没了"。

**D-4（P2）toast 一闪而过。** 成功回执走 toast（`useProductList.ts:357`、`useSkuPool.ts:538`）。值得肯定的一面：**重要错误都留在了正文**（表单内 `ProductEditorDrawer.vue:223`、行级失败清单 `PoolPane.vue:74-81`），这一点比多数产品做得好。

### E 重复劳动与口径

**E-1（P2）"已关联商品"与右栏"已建立映射"是同一份数据的两个视图**，但用户在左栏展开区看不到任何"去右栏改绑"的线索（左栏刻意只读，`ProductPane.vue:281-313`），要改只能自己想到去右栏。

**E-2（P1）跨页指路名漂移（悬空引用）。** `ClassifyPanel.vue:393` 与 `:580` 让用户去「货与成本」的**映射清单**；而这一页里**没有任何叫"映射清单"的地方**（对应的是分段控件「已建立映射」，`PoolPane.vue:40`）。用户照着字面找不到。同类还有 `ClassifyPanel.vue:583` 的「店铺账号管家 › 店铺登记」。


### F 导航与帮助

**F-1（P0）页签名「建档与关联」（`GoodsView.vue:143`）是两个行话的合成词**，而页头那句描述（`:164`）本身就是解释——页签在承担它承担不了的职责。

**F-2（P0）应用内零帮助。** 全仓扫描 `教|教程|帮助|引导|新手|指南|第一次|首次`，在 `src/**` 的命中**全部是代码注释**，没有任何用户可见的帮助入口/教程/首启引导。`docs/guides/USER_GUIDE.md` 在 `docs/README.md` 里被标为「⚠️ 已过期：描述的是「TV模版」时代的界面」，且它根本不是「货与成本」的说明。

## §6 采集方法与局限

**做了**：静态通读本页全部 12 个界面文件与 2 个逻辑文件（`useProductList.ts` / `useSkuPool.ts`）；对两处**肯定性结论**做了双命令复核 ——  
① "应用内无帮助"：以 `Grep` 扫 `教|教程|帮助|引导|新手|指南|第一次|首次`，`src/**` 命中全为注释，未见任何用户可见帮助入口；  
② "映射清单不存在于本页"：`Grep 映射清单` 仅命中 `ClassifyPanel.vue` 三处（跨页文案），本页组件零命中。

**没做（因此结论有其边界）**：

1. **未做真机走查、未跑 `goods:ui` 冒烟、未截图** —— 本文所有结论来自**静态读码**。因此"看起来会不会卡住"这一类判断是推断，不是实测；**建议在动手前先跑一遍 `npm run goods:ui`（当前 110 条，见 `../plans/GOODS_WORKBENCH_PLAN.md` §11）确认基线绿**，再开始改文案。
2. **未核验"分发端 vs 本机"三坐标版本差** —— 本文只断言"默认包不含岛、岛在线上市场有 1.5.2"（`modules.config.json:42`、`market-out/catalog.json`），未逐台比对用户机器上真正跑着的版本。
3. **未测平台差异** —— 例如 `title` 悬停行为在不同输入设备下的可达性，属通用推断，未做真机实验。
4. **控件计数是静态计数**（含条件渲染的分支），用于表达"同屏复杂度量级"，不是精确的用户可点元素数。

**净结论**：这一页不需要重构（形态与数据都已被 110 条守卫钉住），需要的是**在它外面包一层"给外行人的皮"** —— 术语白话化 + 隐藏高级控件 + 三处提示改成按钮 + 一个空库入口。P0 全部落在文案与模板层，不发版、不动数据。
