## §0 结论速览

**一句话诊断**：这一页在**数据与工程上成熟**（三栏口径、状态区分、空态与失败回执比多数产品页好），但它把用户**假定成已懂"款/SKU/映射/店铺归一"模型的人**；对不会电脑的人，它是一堵术语墙 + 一张需同时看两边的表 + 一组看不见的鼠标/键盘约定，且**没有任何一处告诉他"第一步做什么"**。

### 六维打分（1–5，5 = 对非技术用户最友好）

## §1 功能全景（从"第一次双击图标"开始）

### 1.1 新用户实际会看到什么
侧边栏点「货与成本」（`src/modules/goods/meta.ts`，icon `box`，order 2）→ 到达两栏工作台：页头一句话"左边给自己的款和 SKU 建档，右边把店铺商品认到款上——左栏选一款，右栏就能直接关联过去"；下方两个页签「建档与关联」「供应商」。左栏（~40%）含搜索/状态/供应商/问题件筛选、「导出」「导入 Excel」「新增产品」、款列表（每行可展开看 SKU 表+已关联商品）；右栏（占余下）含「待关联队列」「已建立映射」分段、指标条、工具按钮。**实测同屏约 43 个可交互点、4 种弹层形态**（编辑抽屉/产品选择器/对比认款/看大图）——控件计数含条件渲染分支，用于表达复杂度量级。

### 1.2 这一页现在能做哪些事（形态 · 入口深度 · 前置）
| 用户想干的事 | 入口 | 深度 | 前置（不满足时界面会怎样） |
| ----------- | --- | --- | --- |
| 新增一款货 | 左栏「新增产品」 | 1 级 | 无（"款编码"必填且编辑时不可改，`ProductEditorDrawer.vue:12-24`） |
| 批量导入款式表 | 左栏「导入 Excel」→ 三步向导 | 2 级 | 需表头含「款编码/款式名」的 Excel；向导质量高（`ProductImportDialog.vue`） |
| 补 SKU 克重 | 左栏点行展开→改克重；或「问题件=缺克重」 | **2 级** | 该款已有 SKU；无 SKU 时展开区说"点编辑用颜色×尺码批量生成" |
| 把订单商品认到款上 | 右栏「关联…」/「对比」 | **2–3 级** | 队列非空 ⇒ **必须先「今天」导过订单**（`PoolPane.vue:275`） |
| 直连认款（借两栏同屏） | **先展开左栏一行** → 右栏出现「关联到 S1」 | **3 级** | 左栏必须真展开过一款（`ProductPane.vue:576-589`） |
| 看某款已认哪些商品 | 左栏点行展开→「已关联商品」 | 2 级 | 无（只读，刻意无"解除"按钮） |
| 标注失效/恢复 | 右栏「已建立映射」→ 行内「标失效」/「恢复」 | **3 级**（先切分段、恢复只在已失效行出现） | 无 |
| 给商品 ID 指定图 | 右栏「已建立映射」→ 图下「设图/换图」 | 3 级 | 无 |

### 1.3 主流程逐步骤走查（`■` = 新手断点）
① 打开应用→侧栏「货与成本」。■ 页首没有"第一步做什么"（页头是描述不是指令）。② 左栏空→「还没有产品」+ 导入/新增；■ 空态文案"产品库是订单/采购/成本三域的关联锚点——先建档"（行话，`ProductPane.vue:353`）。③ 照"新增产品"建第一款→抽屉要填「款编码」（例 STYLE-001），■ 无解释只有 placeholder，用户随手打"123"；■ 填完名字直接 ✕ 关 → **没保存**且无提示（§2-D-3）。④ 建完款→想认货→右栏「还没有要认的商品」；■ 空态指向「去「今天」导入订单」（有按钮，`PoolPane.vue:282`）。⑤ 去「今天」导订单→回来→队列出现若干行；■ 若店铺没在「店铺账号管家→店铺登记」认过，这些行**整行浅底、按钮禁用**，只有 disabled 上的 title「先到店铺账号管家→店铺登记把 XX 归一」（无按钮、无"去哪装"，`PoolPane.vue:243-251`）⇒ **死锁**。⑥ 认款：勾选行→「批量关联选中 N 项」→ 弹层选款/或先展开左栏走直连/或「对比」；■ 弹层靠**色号编码**与小缩略图辨认，对认不出编码的人是硬门槛。⑦ 认完→回执 toast「新增 3 条、更新 0 条，已自动关联 12 行存量订单，并把 2 张订单图设为款主图」（行话，`useSkuPool.ts:534-539`；toast 一闪而过）。

## §2 问题清单

### A 上手与前置
- **A-1（P0）页内没有"起点"**：页首只剩「页头+页签」（`GoodsView.vue:19-27`）；「起点引导条」已按用户要求整体撤除（见 `../notes/2026-10-30-goods-list-and-pool.md:3-8`）。对熟练用户是少占一行，对非技术用户是"没有说明书"。**注意 §3：不重提被撤的常驻步骤条。**
- **A-2（P0）唯一跨越"能力缺口"的提示是不可点的长句**：`PoolPane.vue:86-89` 写"请先到「店铺账号管家」的「店铺登记」把门店认下来，再回来刷新"——给开发者看的，对用户唯一有用信息是"去某个地方登记"，而那**不是按钮**。同类有 `PoolPane.vue:243-251` 的 disabled 按钮 title。
- **A-3（P0）"店铺账号管家"是需要另行安装的 UI 岛，默认包没有**：默认预设只含 `today/goods/quick-note/order-cost/picking`（`modules.config.json:42`）；「店铺账号管家」只在插件市场分发（线上 1.5.2）。⇒ 新装软件上用户**根本看不到**该入口，也不知去插件中心装。本页唯一**硬死锁**。
- **A-4（P1）左栏与右栏空态把用户指向两个不同"第一步"**：左栏说「导入 Excel/新增产品」（`ProductPane.vue:349-368`），右栏说「去「今天」导入订单」（`PoolPane.vue:271-287`）。真实顺序从订单来（队列是订单实时聚合，`PoolPane.vue:275`），页面没告诉用户先做哪个。

### B 术语与文案
- **B-1（P0）术语密度**：同屏领域词 `款编码/款式名/SKU/克重/缺 N/待关联队列/已建立映射/店铺未归一/关联率/映射记录/订单行/平台/店铺原始/标失效/建档/存量订单/款主图`（`ProductPane.vue:172-175,217-221,353`；`PoolPane.vue:28,40,59-69,275`；`useSkuPool.ts:534-539`）。
- **B-2（P0）同一东西三个名字——产品/款/款式**：产品（`ProductPane.vue:348/57`、`SupplierView.vue:8`）/ 款（`GoodsView.vue:164`、`ProductPane.vue:131/172`）/ 款式（`ProductPane.vue:173`、`SupplierView.vue:8`、`ProductImportDialog.vue:117`）。
- **B-3（P0）同一动作三个名字——映射/关联/认**：关联（`PoolPane.vue:28/111`、`useSkuPool.ts:173`）/ 映射（`PoolPane.vue:40/68/87`）/ 认（`PoolPane.vue:264`、`GoodsView.vue:164`、`ProductPane.vue:302`）。
- **B-4（P0）"缺 0" 逐行重复**：`ProductPane.vue:217-221` 每行渲染 `SKU 数 · 缺 N`；齐全货用户看到"`3 · 缺 0`"，全齐时要读 N 个 `缺 0` 才确认。**建议**：`missingOf>0` 才渲染。
- **B-5（P0）指标条五项全零也铺满**：`PoolPane.vue:59-69` 常显「待关联/店铺未归一/已关联/关联率/映射记录」，空库时"0·0·0·—·0"像"页面坏了"。
- **B-6（P0）空态文案偏"讲原理"**：`ProductPane.vue:353`"产品库是订单/采购/成本三域的关联锚点——先建档"。改法：一句人话+一个按钮（"先建第一款货"）。
- **B-7（P1）成功回执带行话**：`useSkuPool.ts:534-539` toast 含"已自动关联 12 行**存量订单**""把 2 张订单图设为**款主图**"。
- **B-8（P1）"问题件"不指向真做的事**：`ProductPane.vue:39-51` 下拉叫「问题件」，选项是「缺克重/未关联供应商」，用户不会想到"补重量"在"问题件"里。

### C 交互门槛（鼠标精度/隐式约定/快捷键）
- **C-1（P1）多选+批量+物理删除**：每行复选框（`ProductPane.vue:162-169,198-205`），选中浮出「已选 N 个款/批量编辑/**删除选中**/清空选择」（`:130-146`）；删除确认写"**物理删除且不可撤销**"（`:478-481`）。后果不可逆。
- **C-2（P1）信息藏在行展开里**：供应商/类目/操作/SKU 子表/已关联商品全在 `row-detail`（`ProductPane.vue:232-337`），靠行首 `▸/▾` 小三角触发（`:187-196`），无任何提示"点这行会打开更多"。
- **C-3（P1）关键说明挂悬停 `title`**：平台标签（`PoolPane.vue:192`）、来源与更新时间（`:342`）、"点击看大图"（`:209`）、禁用原因（`:248`）——`title` 要悬停约 1 秒才出现，触屏不可得。
- **C-4（P2）编辑抽屉"按住拖动可连选/连消"**：`ProductEditorDrawer.vue:117,127-129` 纯鼠标约定（键盘不可达）。公平说：**单击也能选**，拖拽只是加速器，不构成阻塞；但提示会让新手不敢动。
- **C-5（P2）对比认款键盘提示**：`CompareModal.vue:59` 写"←/→ 换候选·空格关联·Esc 关闭"。公平说：**同屏已有可点按钮**（`:53-60`），键盘只是加速器。建议降级为次要文案。

### D 状态反馈与危险操作
- **D-1（P1）破坏性操作"两个词"选择成本高**：「删除」（物理、不可撤销）与「标失效」（可恢复）分处两处——删除在左栏行展开（`ProductPane.vue:327-333`），标失效在右栏「已建立映射」（`PoolPane.vue:405-414`）。新手分不清"停用/标失效/删除"三者区别——**页面上有三个"让它消失"的词**（停用 `:222-225`、标失效、删除）。
- **D-2（P1）「恢复」藏得深**：`PoolPane.vue:395-404` 的「恢复」只在当前行 `status==='invalid'` 时出现，而「已建立映射」默认筛"全部状态"。无"有 N 条已失效→查看"汇总入口。
- **D-3（P1）保存模型一半一半**：`ProductEditorDrawer.vue:248-251` 明确主图与 SKU **即时保存**，表单（编码/名称/供应商/类目/状态/备注）要按底部「保存」；「取消」**不提示未保存改动**就关。对新手 ="我填了，然后没了"。
- **D-4（P2）toast 一闪而过**：成功回执走 toast（`useProductList.ts:357`、`useSkuPool.ts:538`）。值得肯定：重要错误都留在正文（表单内 `ProductEditorDrawer.vue:223`、行级失败清单 `PoolPane.vue:74-81`），比多数产品好。

### E 重复劳动与口径
- **E-1（P2）"已关联商品"与右栏"已建立映射"是同一份数据两个视图**，但左栏展开区看不到"去右栏改绑"线索（左栏刻意只读，`ProductPane.vue:281-313`），要改只能自己想到去右栏。
- **E-2（P1）跨页指路名漂移（悬空引用）**：`ClassifyPanel.vue:393` 与 `:580` 让用户去「货与成本」的**映射清单**；而本页**没有任何叫"映射清单"的地方**（对应分段「已建立映射」，`PoolPane.vue:40`）。同类有 `:583` 的「店铺账号管家›店铺登记」。

### F 导航与帮助
- **F-1（P0）页签名「建档与关联」**（`GoodsView.vue:143`）是两个行话合成词，页头描述（`:164`）本身就在解释——页签承担不了。
- **F-2（P0）应用内零帮助**：全仓扫 `教|教程|帮助|引导|新手|指南|第一次|首次`，`src/**` 命中**全为代码注释**，无任何用户可见帮助入口/教程/首启引导。`docs/guides/USER_GUIDE.md` 在 `docs/README.md` 标"⚠️ 已过期：TV模版时代界面"，且根本不是「货与成本」说明。

## §6 采集方法与局限

**做了**：静态通读本页全部 12 个界面文件与 2 个逻辑文件（`useProductList.ts`/`useSkuPool.ts`）；两处**肯定性结论**双命令复核——①"应用内无帮助"：`Grep` 扫 `教|教程|帮助|引导|新手|指南|第一次|首次`，`src/**` 命中全为注释，无用户可见入口；②"映射清单不存在于本页"：`Grep 映射清单` 仅命中 `ClassifyPanel.vue` 三处（跨页文案），本页组件零命中。

**没做（结论有其边界）**：
1. **未做真机走查、未跑 `goods:ui` 冒烟、未截图**——结论来自静态读码；动手前先跑 `npm run goods:ui`（当前 110 条，见 `../plans/GOODS_WORKBENCH_PLAN.md` §11）确认基线绿，再改文案。
2. **未核验"分发端 vs 本机"三坐标版本差**——只断言"默认包不含岛、岛在线上市场有 1.5.2"（`modules.config.json:42`、`market-out/catalog.json`）。
3. **未测平台差异**——`title` 悬停在不同输入设备的可达性，属通用推断，未真机实验。
4. **控件计数是静态计数**（含条件渲染分支），表达同屏复杂度量级，非精确可点元素数。

**净结论**：这一页不需要重构（形态与数据已被 110 条守卫钉住），需要的是**在外面包一层"给外行人的皮"**——术语白话化 + 隐藏高级控件 + 三处提示改成按钮 + 一个空库入口。P0 全落文案与模板层，不发版、不动数据。
