## 0. 结论速览

### 0.1 一句话诊断
**宿主这一层已"能自己走完一件事"了；但用户实际拿到的岛还是重构前的旧版——重构成果卡在"没发布"这一步，而发布依赖的市场当前已经装不上东西。**

第一轮病根是"功能做出来了，但装/串/看懂的成本全转嫁给用户"。S1–S3 后宿主侧治好了：默认包自洽、首页「今天」把三链变三张待办卡、空态带可点按钮且点击真走链路（§6 四个冒烟实跑）。**但岛侧原地未动，且比"未动"更糟——仓库里改好的岛一个都没发出去。**

### 1.3 三条主流程走查
- **流程 A：这条订单赚多少钱？**（宿主侧已能独立走通前两步）① 今天·导入 Excel（✅ 冒烟实证，多产品单拆行）② 今天·缺口卡（✅ 有）③ 货与成本（✅ 就地改克重，保存带全字段不静默清空）④ 运价表（卡③标红**但无动作** 🔴 §2-N4）⑤ 算钱（点「刷新」才出数；无运价表时 toast 指向「无忧物流运费」🔴 §2-N4，该岛装不上）。
- **流程 B：这批货要拣什么？** ① 今天·导入 → ② 待拣卡 → ③ 拣货·生成清单。✅ 单向直路（「拣货」两份入口随 C2 收敛）；空态区分"没生成过"与"生成了没货可拣"并写"扫了几行/被谁排除/怎么放宽"（冒烟实证）。
- **流程 C：这家店卖得怎么样？/ 建主数据与映射** ① 店铺账号管家·店铺登记 ② 产品库·商品清单（导商品 Excel）③ 产品库·映射与关联。**卡点 1**：②导入时店铺恒为空（`ShopProductView.vue:299` `shopId:0`），列表却把"店铺"当正式列。**卡点 2**：③按钮要求先归一店铺，提示写"先到店铺账号管家→店铺登记把 X 归一"——可信跨岛指路，但店铺登记在**另一个装不上的岛**里（§2-N2）。

## 2. 问题清单

> 严重度：🔴 阻断 · 🟡 摩擦 · ⚪ 打磨。编号沿用第一轮 A–F；`N*` 本轮新发现。

### A. 上手与安装
- **A1 🔴 N2 · 插件市场当前装不上**：线上 catalog 实测——shop-accounts 的 `downloadUrl="<BASE_URL>/..."` 被主进程静默丢弃（`plugins-market-handlers.ts:56` `if(!isHttpUrl) return null`）；order-insight 指向 `http://127.0.0.1:8000/…` 点安装必失败；ae-profit 1.0.1（GitHub raw，唯一可用）但本机 1.0.2 更高→"无更新"；shipping-rate/excel-copy/product-library **完全不在目录**。**这是"装插件"唯一路径，新用户永远装不齐**；`P1-1 首启引导` 前置不存在。**建议**：① 发布前 catalog 的 `downloadUrl` 全改绝对 https（`publish-plugin.js` 现会写出 `127.0.0.1` 与 `<BASE_URL>`）；② 加发布口守卫（每条必须 `isHttpUrl` 且非回环）；③ 主进程丢弃条目不该静默，至少 log/返回"N 条被丢弃"。
- **A2 🟡 市场地址记在 localStorage，改坏无恢复入口**：`marketClient.ts:15-23`（`sk.market.url`）。本机 leveldb 翻到三个历史值，其中一个 GitHub raw 已 404（仓库名大小写不同）。**建议**：市场页给"恢复默认地址"按钮 + 当前地址可见。
- **A3 🔴 A4 · 仍无首启引导**（第一轮结论未做）。
- **A4 ⚪ 默认包仍留「便签」**：`modules.config.json:42`、`quick-note/meta.ts:10`（`order:2`，与 `goods` 撞号）。重构目标 IA 无这一面。**建议**：移出 `standard`（或 `order:99`）。

### B. 术语与文案（统一规则：用户可见文案不得出现能力域/表名/op 名、进程协议名、内部编号）
- **B1 🟡 岛顶栏"桥/宿主"没改**（P0-2 只改了宿主那层）：各岛 `dist/index.html`/`main.js`/`App.vue` 仍印"等待桥握手…"/"未连接宿主"/"未检测到宿主桥（window.__sk）"等。宿主工具条已说人话，业务页顶部紧挨又出现岛的"未连接宿主"——两层自相矛盾。**建议**：岛顶栏改人话（未连接/正在连接…/连接失败点此重试）；`waitForBridge` 超时文案改"页面没加载起来，点此重试"。归入岛发版批。
- **B2 🟡 表名/实现约束/协议词仍在岛里渲染**：如 excel-copy 设置页"求值在宿主完成（CSP 禁止 eval）"、order-insight"reclassify/styleAssign"、shipping-rate"运价表存在宿主快照"、product-library"宿主守卫/编码是跨域关联的锚点"、ae-profit"X-Ae-Token: sk-ae-dev-token / v2 帧"、多处主键数字 ID。**建议**：照 `AGENTS.md` §1.10 禁用族表清一遍，归入两批岛发版。
- **B3 🟡 「导入设置」页首面板标题仍是「识别引擎与密钥」，里面却只有一个说明段落**（`order-insight/dist/views/settings.js:41→42-45`）。C4 把控件搬走了、标题留下。**建议**：标题改「识别引擎（已移到应用设置）」+ 可点跳转，或直接删空面板。一行改动，归入订单归类发版批。
- **B4 🟡 「导入与识别」页与「导入设置」页都能改同一份列映射**（label 完全同名，两处都能保存）。**建议**：留「导入设置」一处（ADR-001 判据），「导入与识别」页映射表单改只读摘要 + "去导入设置修改"链接。

### C. 导航与一致性
- **C1 🟡 目标 IA 的「订单」面与「运费」面缺位**：侧栏实际 `今天/货与成本/便签/算钱/拣货`，目标面是 `今天/订单/货与成本/运费/算钱/设置`。用户看完「今天」的"订单 2 行"想看是哪两行时无直观去处；「运费」完全依赖装不上的岛。**建议**：短期「今天」订单卡按钮文案改「看订单明细与利润」；中期见 §4-P2。
- **C2 ⚪ 两个模块 `order` 撞号**：`goods/meta.ts:12` 与 `quick-note/meta.ts:10` 都是 `order:2`（靠稳定排序能跑但脆弱）；shipping-rate 的 `rates.js`/`orders.js` 也是 `order:2`/`order:2`。**建议**：`order` 唯一化 + 守卫。
- **C3 🔴 C5+ · 供应商维护指路成环**（第一轮 C5 未修且更绕）：订单归类说"去产品库→供应商新增"，产品库 `ProductEditor.vue:40` 说"厂家在拿货对账里维护，这里只做关联"——**A→B→A 死循环**，真入口（产品库·供应商页签）两边都没指。**建议**：改 `ProductEditor.vue:40` 为"厂家在「供应商」页签维护，这里只做关联"（一行改动，收益最高）。
- **C4 ⚪ 侧栏 logo 点击=回首页「今天」**（`AppShell.vue:31` `sortedMetas[0]`，靠排序保证，不稳）。**建议**：显式写"回首页"目标 id。

### D. 状态反馈与危险操作
- **D1 🟡 D3 · 岛侧弱空态仍是主体**：订单归类 12+ 处（"暂无订单数据"/"没有待纠正的订单"/"识别库为空"×2/"暂无拿货单"等）、TV模版 3 处（"暂无模板"/"暂无规则"/"当前筛选下没有记录"无"清除筛选"）、店铺账号 1 处、运费 4 处（"没有匹配的国家"×2/"请输入大于 0 的克重"/"已导入 0 个商品"）。好空态可作样板（`pivot.js:117`/`stockin.js:708`/`ProductListView.vue:98`/`ShopProductView.vue:79`/`quote.js:114-119`）。**建议**：按 `AGENTS.md` §1.10 逐条补"现状+原因+可点下一步"，归入两批岛发版。
- **D2 🟡 D2 · 破坏性操作确认四种方式混用，且 6 处无确认**：原生 `confirm()`（shop-accounts `ShopAccountsView.vue:71`/`CompanyManageView.vue:257,355`、宿主 `SettingsModal.vue:319,362`）/ 原生 `prompt()`（order-insight `stockin.js:950`，Electron 必抛错，§2-N3）/ 自绘二次确认（order-insight `util.js` 6 处、excel-copy `util.js` 3 处、product-library `pl-mask/pl-dialog` 5 处）；**完全无确认** 6 处（产品库移除关联/删除 SKU/移除主图/清除覆盖图、店铺账号取消接入邮箱连带删缓存/清空缓存/解绑名下店铺）；**覆盖式无确认** 3 处（运费岛「导入/更新运价表」整表替换、「切换工作表」、`「导入/更新商品信息」覆盖重量表）。**建议**：宿主先抽 `ConfirmDialog`（三段式）替 SettingsModal 两处；岛侧按批替换，给 6 处无确认补确认。
- **D3 ⚪ 「算钱」页缺口标签 8 个并列不分优先级**（`OrderCostView.vue:288` 一行 `缺收入/缺国家/缺克重/缺运价卡/未识别款/缺成本/税未知/缺件数`）。**建议**：按补齐收益排序 + 可跳转（与「今天」卡③口径对齐）。
- **D4 ⚪ order-insight「数据纠正」计数与可见行数不一致**：`correction.js:104` 显示 `s.total`（全量），列表固定 `LIMIT=100`（`:20,:38`）**无分页**；同岛「订单明细」有分页。用户会以为"只剩 20 条"其实 120 条。
