## 0. 结论速览

### 0.1 一句话诊断

**宿主这一层已经"能自己走完一件事"了；但用户实际拿到的岛还是重构前的旧版 —— 重构成果卡在"没发布"这一步，而发布依赖的市场当前已经装不上东西。**

第一轮的病根是"功能都做出来了，但装起来/串起来/看懂它 的成本全转嫁给了用户"。S1–S3 之后，**宿主侧的那一半治好了**：
默认包自洽（宿主自己能拆行导订单、写成本、改克重）、首页「今天」把三条链变成三张待办卡、空态带可点按钮且点击真走链路（§6 有四个冒烟实跑记录）。
**但另一半（岛侧）原地未动，且比"未动"更糟 —— 仓库里改好的岛，一个都还没发出去。**

## 1. 用户视角的功能全景

### 1.1 一个新用户第一次双击图标会看到什么

| 阶段 | 用户看到 | 取证 |

### 1.3 三条主流程走查

**流程 A：这条订单赚多少钱？**（宿主侧已能独立走通前两步）

```
① 今天·导入 Excel          导订单报表 → 自动识别 → 落主干（含多产品单拆行）      ✅ 冒烟实证
② 今天·缺口卡             看到"缺克重 N / 缺成本 N / 未识别款 N / 运价表 没有"   ✅ 有
③ 货与成本                就地改克重（保存带全字段，不会静默清空颜色/尺码）      ✅ 冒烟实证
④ 运价表                  卡③把"运价表 没有"标红了，**但没有任何可点的动作**    🔴 §2-N4
⑤ 算钱                    点「刷新」才出数；无运价表时 toast 指向「无忧物流运费」 🔴 §2-N4（该岛当前装不上）
```

**流程 B：这批货要拣什么、要多少？**

```
① 今天·导入 Excel → ② 今天·待拣卡 → ③ 拣货·生成待拣清单
```
✅ 已是单向直路（「拣货」两份入口随 C2 收敛为一处）；空态区分"没生成过"与"生成了没货可拣"，并写出"扫了几行、被谁排除、怎么放宽"（`src/modules/picking/PickingView.vue:66-77`，冒烟实证）。

**流程 C：这个店铺上面卖得怎么样？/ 建主数据与映射**

```
① 店铺账号管家·店铺登记（把历史店名归一成店铺实体）
② 产品库·商品清单（导商品 Excel）→ ③ 产品库·映射与关联（商品ID ↔ 产品）
```
🔴 卡点 1：②导入时店铺**恒为空**（`ShopProductView.vue:299` `shopId: 0`），但列表把"店铺"当正式列展示。
🔴 卡点 2：③的按钮要求先归一店铺，提示写"先到「店铺账号管家 → 店铺登记」把「X」归一"（`SkuMappingView.vue:156`）—— 这是一条**可信**的跨岛指路，但店铺登记在**另一个装不上的岛**里（§2-N2）。

## 2. 问题清单

> 严重度：🔴 阻断（用户自己走不完）· 🟡 摩擦（能走完但体验差）· ⚪ 打磨。

### A. 上手与安装

**A1 🔴 N2 · 插件市场当前装不上东西（新）**

用户点「插件中心 → 插件市场」，实际能拿到的：

| 岛 | 线上 catalog | 本机已装 | 结果 |
| --- | --- | --- | --- |
| shop-accounts | 1.0.0，`downloadUrl = "<BASE_URL>/shop-accounts-1.0.0.zip"` | 1.5.2 | **条目被主进程静默丢弃**（`plugins-market-handlers.ts:56` `if (!isHttpUrl(downloadUrl)) return null;`）→ 用户看不到它，也没有任何解释 |
| order-insight | 1.0.0，`downloadUrl = "http://127.0.0.1:8000/…"` | 1.3.0 | 条目显示，但**点安装必然下载失败**（装的是用户的 127.0.0.1） |
| ae-profit | 1.0.1（GitHub raw，唯一可用） | 1.0.2 | 已装版本更高 → 市场"无更新可用"（`plugins-market-handlers.ts:222`） |
| shipping-rate / excel-copy / product-library | **完全不在目录里** | 有 | 市场上看不到 |

**影响**：这是"装插件"的**唯一**路径。新用户永远装不齐；`P1-1 首启引导一键装齐`这个方案的**前置条件不存在** —— 引导做出来也点不动。
**建议**：① 发布前把 catalog 的 `downloadUrl` 全部改成**绝对 https**（`publish-plugin.js` 目前会写出 `127.0.0.1:8000` 与 `<BASE_URL>` 占位，见 `market-out/catalog.json`）；② 加一条**发布口守卫**：catalog 里每条 `downloadUrl` 必须 `isHttpUrl` 且非回环地址，否则 `publish-plugin` 直接失败；③ 主进程丢弃条目时不该静默 —— 至少 log/返回一条"目录里有 N 条被丢弃"。

**A2 🟡 市场地址记在 localStorage，用户改坏了没有任何恢复入口**
`src/core/plugin/marketClient.ts:15-23`（`sk.market.url`）。本机 leveldb 里能翻到**三个**历史值，其中 `https://raw.githubusercontent.com/SayakABC/sellerkit-plugins/main/catalog.json` 已 404（仓库名大小写不同）。
**建议**：市场页给"恢复默认地址"按钮 + 当前地址可见（现在地址藏在哪要看代码）。

**A3 🔴 A4 · 仍无首启引导**（第一轮结论，未做）

**A4 ⚪ 默认包仍留「便签」**
`modules.config.json:42`、`src/modules/quick-note/meta.ts:10`（`order: 2`，与 `goods` 撞号）。重构目标 IA（`RESTRUCTURE_PLAN.md` §3）里没有这一面。
**建议**：移出 `standard`（或 `order: 99` 排到最后），别让它和业务面并列。

## 4. 优化建议（分阶段）

> 判据照 `UX_POLISH_PLAN.md`：**先做"零发版 + 直接减少用户手工步骤"的**；需要发版的攒成 **2 批**（订单归类一批 / 产品库+其余一批）。

### P0 · 零发版止血（宿主侧，本机改完即生效）

| # | 动作 | 落点 | 验收判据 |
| --- | --- | --- | --- |

## 6. 采集方法与局限

**做了什么（可复现）**：

1. **读**：本文件 §1/§2 的每一条都带 `文件:行`，跨岛结论（三个子代理并行梳理 6 个岛）中**抽验了 6 条最重的**：`stockin.js:950` 的 `window.prompt`、`settings.js:41` 的空面板标题、`overview.js:341` vs `settings.js:84` 的双保存、`rates.js:139` 的覆盖式导入、`ProductEditor.vue:40` 的失效指向、`excel-copy/settings.js:285` 的 CSP 文案 —— 全部回读命中。
2. **跑**（宿主页真机行为，假桥无头）：`npm run today:ui` / `goods:ui` / `order-profit:ui` / `picking:ui` **四个全绿**（合计 100+ 条断言）。关键实测：空态按钮真派发 `switch-module`（`[{"moduleId":"today"}]`）、统一导入真解析真落库（`{"items":[{"itemId":"ITEM9","name":"某款外套","weightG":320}]}`）、改克重真带全字段提交（`{"id":12,...,"color":"黑","size":"M","weightG":275,...}`）、拣货超窗/已终结剔除数写在标签上。
3. **实测平台行为**：用 Electron 24 起一个隐藏窗口执行 `window.prompt('t','')`，实测返回 `threw: prompt() is not supported.` → 这是 §2-N3 的判据（不是推测）。
4. **对照"用户实际拿到的版本"**：逐个读 `ui-plugins/*/manifest.json` 与本机 `~/Library/Application Support/seller-kit/plugins/*/manifest.json`，并拉取线上 `catalog.json`。
