# 用户体验审查（用户视角的流程梳理与优化建议）

> **性质**：体验审查报告 + 优化清单。§1 是**用户视角的现状事实**（带 `文件:行` 取证），§2 是**问题清单**（每条含影响与建议），§3 是**分阶段建议**，§4 是**待拍板项**。
> **视角**：一个**第一次拿到这个软件、只关心"我要把货卖出去、把钱算清楚"的运营**，不是开发者。
> **审查对象**：宿主外壳（`src/core/`）+ 3 个内建模块（`src/modules/`）+ 6 个 UI 岛（`ui-plugins/`）+ 用户文档。
> **取数时点**：2026-09-30。
> **前置阅读**：`docs/plans/DOMAIN_INTEGRATION_PLAN.md`（数据为什么串不起来）、`docs/reviews/BUSINESS_GAP_ANALYSIS_2026-09-29.md`（业务能力缺什么）、`docs/decisions/ADR-002-master-data-layer.md`。
> **与既有审查的关系**：那两份审的是**能力有没有**；本报告审的是**能力递到用户手里之后长什么样**。两者不重叠，但部分修法会共用同一处改动（见 §3 备注）。

## 0. 结论速览

### 0.1 一句话诊断

**功能都做出来了，但"把它装起来、串起来、看懂它"的成本全部转嫁给了用户。**
产品当前形态是**六个能独立工作的工具并排放在侧栏**，而不是**一条从订单到利润的流程**。用户必须自己知道：哪三个工具要先装、先导哪个文件、装完还要重启。

### 0.2 体验健康度（按维度打分）

| 维度 | 分数 | 判据 |
| --- | --- | --- |
| 上手可发现性 | 🔴 **30%** | 默认包里没有"上游"功能，空态把用户指向一个**尚未安装**的岛（§2-A1） |
| 流程连贯性 | 🔴 **25%** | 走完"订单→利润"要跨 5 个岛、6 次手动接力，中间无指引（§1.3） |
| 术语友好度 | 🔴 **35%** | `桥握手` / `L0/L2` / `ae_rates upsert` / `越权调用由宿主权限门拒绝` 直接出现在用户界面（§2-B） |
| 导航一致性 | 🟡 **55%** | 侧栏是一级、岛内页签是二级，但两级视觉连续且风格各异；同名功能有两份（§2-C） |
| 反馈完整性 | 🟡 **50%** | 空态文案质量参差；更新插件后不重载；破坏性操作确认方式三种混用（§2-D） |
| 帮助完备性 | 🔴 **20%** | `docs/guides/USER_GUIDE.md` 描述的仍是 Excel 复制工具时代的界面，与实际产品不符（§2-F） |

### 0.3 Top 10 问题（按"妨碍用户走完一件事"排序）

| # | 问题 | 一句话 |
| --- | --- | --- |
| 1 | 首启指向不存在的入口 | 「订单利润」空态说"先去「订单归类」导入报表"，而「订单归类」此时还没安装 |
| 2 | 业务岛要自己去设置里找 | 所有业务功能都是岛，安装/更新/卸载全在「设置 → 插件」二级页 |
| 3 | 一条业务链跨 5 个岛无向导 | 无"先做什么、再做什么"的任务视图 |
| 4 | 岛工具条是调试台 | 「宿主→岛事件」「桥已连接 · 越权调用由宿主权限门拒绝并审计」 |
| 5 | 「返回」跳到便签 | 岛的返回固定回退到"首个非岛模块"，不是返回上一处 |
| 6 | 「运费测算」不存在 | 提示里的模块名全仓只此一处，用户按提示找不到 |
| 7 | 供应商维护两个说法互相矛盾 | 一个页面说过来了，另一个页面说还在原处 |
| 8 | 拣货能力有两份 | 岛内有「拣货」页签，宿主侧栏也有「拣货」模块 |
| 9 | 同一份 Excel 导两遍 | 商品信息 Excel 在运费岛和产品库各导一次，且刻意存两张表 |
| 10 | 插件卡片的用户看不懂 | `db` / `storage` 能力名、`L0/L2` 分级、`sha256` 前缀 |

## 1. 用户视角的功能全景

### 1.1 一个新用户实际看到什么

| 阶段 | 用户看到 | 取证 |
| --- | --- | --- |
| 双击图标 | 侧栏三个入口：**便签 / 订单利润 / 拣货** + 底部「账户与设置」 | `modules.config.json:42`（`standard = ["quick-note","order-cost","picking"]`） |
| 点「订单利润」 | 空表 + 一行灰字"还没有订单行 —— 先去「订单归类」导入订单报表，再回来点「刷新」" | `src/modules/order-cost/OrderCostView.vue:221` |
| 找「订单归类」 | **侧栏没有**。六个业务岛（订单归类 / 产品库 / 店铺账号管家 / 无忧物流运费 / TV模版 / 利润追踪）都要从市场装 | `ui-plugins/` 目录；`modules.config.json:17-23` 的"已下记"说明 |
| 想装插件 | 唯一入口：左下角「账户与设置」→「设置」→ 左侧分类「插件」→「插件市场」 | `src/core/AppShell.vue:91-109`（菜单只有 设置/外观/检查更新）、`src/core/components/SettingsModal.vue:230`（`plugins` 分类 order 999，排在最后） |

**体验后果**：首启的三个入口里，两个是"下游"（订单利润、拣货），它们共同的上游「订单归类」不在包里。用户被空态指向一个**自己还没装、也不知道要装**的东西 —— 这是当前最贵的体验缺陷。默认包把"能立刻产生价值的功能"（订单归类导入）留在了市场里。

### 1.3 三条主流程走查（标出用户在哪一步卡住）

**流程 A：这条订单赚多少钱？**（跨 5 个岛、6 次手动接力）

```
① 订单归类·导入与识别   导订单报表 → 映射列 → 导入队列 → 开始识别   ✅ 有引导
② 订单归类·数据纠正     逐单核对识别结果                          ⚠️ 无"哪几条还没核对"的收件箱，靠人翻
③ 店铺账号管家·店铺登记  把历史店名归一成店铺实体                   ⚠️ 用户不知道"为什么算钱要先做这个"
④ 产品库·产品库         建产品 / 维护 SKU 克重                     ⚠️ 需要用户自己知道克重是运费与利润的输入
⑤ 产品库·映射与关联      商品ID ↔ 产品 建映射（③未做则按钮禁用）    🔴 提示：先到「店铺账号管家 → 店铺登记」把「X」归一
⑥ 无忧物流运费·运价表    导运价表 Excel                          ⚠️ 和④是两处独立动作
⑦ 订单利润             点「刷新」才出数字                         🔴 无运价表时提示：先去「运费测算」导入一次运价表 —— 名称不存在
```

**流程 B：这批货要拣什么、要多少？**

```
① 订单归类·导入与识别 → ② 产品库（图/供应商）→ ③ 拣货 or 订单归类·拣货页签
```
🔴 卡点：③有**两个入口**（侧栏「拣货」模块 / 岛内「拣货」页签），界面互不说明，用户不知道以哪个为准（§2-C3）。

**流程 C：这个店铺上面卖得怎么样？**

```
① 店铺账号管家·店铺登记 → ② 产品库·商品清单（导商品 Excel，店铺列固定为未关联）→ ③ 产品库·映射与关联
```
🔴 卡点：②导入时店铺**恒为空**（`ShopProductView.vue` 传 `shopId: 0`），但列表里"店铺"是正式一列 —— 用户会以为已经关联好了（§2-E4）。

### 1.4 现在"用户走不通"的任务

| 用户想做的事 | 能否完成 | 卡在哪 |
| --- | --- | --- |
| 一句话把 6 个功能装齐 | ❌ | 要进设置→插件→市场，逐个点安装 |
| 知道"我现在该做什么" | ❌ | 无任务/向导视图；每条链的信息散在各岛的空态里 |
| 一次导入把订单、商品、成本都用起来 | ❌ | 订单报表、商品信息 Excel、拿货成本快照各要导一次 |
| 在同一处看到"这条订单的进价 / 运费 / 毛利" | ⚠️ | 数字能出来（订单利润页），但需要 7 步前置且中途有悬空指引 |
| 用文档学会上面任何一件事 | ❌ | 用户文档描述的是另一个产品（§2-F1） |

## 2. 问题清单

> 严重度：🔴 阻断（用户自己走不完）· 🟡 摩擦（能走完但体验差）· ⚪ 打磨（细节）

### A. 上手与安装

**A1 🔴 首启空态指向尚未安装的功能**
`src/modules/order-cost/OrderCostView.vue:221` 写"先去「订单归类」导入订单报表"，`src/modules/picking/PickingView.vue:67` 的拣货清单同样依赖订单数据；而「订单归类」是市场分发的岛（`modules.config.json:17-23`）。默认包（`modules.config.json:42`）只装了**下游**。
**影响**：新用户的第一条路径就走断 —— 照提示找不到入口，也没有"去安装"的按钮。
**建议**：① 把「订单归类」移回默认包（它是数据源头，且是唯一无前置的功能）；② 或把空态改成带按钮的引导："「订单归类」还没安装 → 一键安装"（可直接调 `marketClient.installMarketPlugin`）。

**A2 🔴 业务能力的安装入口埋在三级**
安装/更新/卸载/权限审计全在「设置 → 插件 → 已安装/市场」（`src/core/components/SettingsModal.vue:168-170`、`PluginCenter.vue`）。而本产品**所有业务功能都是岛**（`modules.config.json:12-13`）。
**影响**：产品的主能力变成"设置里的一个页签"，与「账户与设置」的语义冲突（安装功能不像"设置"）。
**建议**：侧栏底部或「账户与设置」菜单里加一级「插件中心」入口（复用现成 `PluginCenter` 组件），设置页保留同样的入口。

**A3 🟡 装完不提示"要重启/重载才生效"**
UI 岛的 iframe 文档是**挂载时加载**的，`AppShell.vue:158-166` 以 `:key="activeIslandId"` 建/拆容器；插件更新后若该岛正打开，文档不会重建。安装完成的 toast 反而写着"侧栏入口已就绪"（`PluginCenter.vue:418`）。
**影响**：用户更新插件后看到旧界面，判断为"更新没生效"。
**建议**：安装/更新成功后，若该岛正激活则自动调一次 `UiIslandView.reload()`（`UiIslandView.vue:130` 已有实现），或 toast 里加"点击刷新当前页面"动作。

**A4 🟡 无"首次运行"引导**
没有任何向导说明"这个软件由多个可插拔功能组成、建议装哪几个、先后顺序如何"。
**建议**：首次启动（或侧栏为空时）给一个"推荐功能包"卡片：一键装齐 6 个岛 + 三个空态各带一句"它解决什么问题"。

**A5 ⚪ 插件来源徽标用内部安全分级**
`L0` / `L2` / `外置 · 视图` / `扩展包 · L0`（`PluginCenter.vue:344-371`）对用户无意义。
**建议**：改为"随应用附带 / 从市场安装"两种人类语言，安全分级放 tooltip。

### B. 术语与文案：把开发者的话说给用户听

| # | 位置 | 原文 | 问题 |
| --- | --- | --- | --- |
| B1 🔴 | `src/core/components/UiIslandView.vue:5,10,75-77` | 按钮「宿主→岛事件」；状态「桥已连接 · 越权调用由宿主权限门拒绝并审计」/「等待桥握手…」 | 这是**插件运行时调试台**，直接呈现在每个业务页顶部 |
| B2 🟡 | `PluginCenter.vue:89-99` | 能力标签直接渲染 `db` / `storage` / `mail` 等 id；无声明时显示"未声明（所有受限能力被拒）" | 用户无法判断"同意什么" |
| B3 🟡 | `ui-plugins/ae-profit/src/components/CostRatesPanel.vue` | "行内修改后点「保存」即时生效（ae_rates upsert）"、"按款编码精确匹配（ae_cost_map）" | 表名进界面 |
| B4 🟡 | `ui-plugins/shop-accounts/src/components/AccountEditor.vue:404` | "已删除的企业（ID 3）" | 主键 ID 出现在下拉项 |
| B5 🟡 | `ui-plugins/excel-copy/dist/views/settings.js` | "求值在宿主完成（岛所在 iframe 的 CSP 禁止 eval）" | 实现约束当用户说明 |
| B6 ⚪ | `ui-plugins/shipping-rate/dist/views/rates.js` | "只渲染前 300 条"、"队列上限 50000 行" | 性能上限写死在界面 |

**建议**：统一一条规则 —— **用户可见文案不得出现：能力域/表名/op 名、进程与协议名（宿主 / 桥 / iframe / CSP / realm / token）、内部编号（L0/L2、ID 数字）**。B1 尤其要改：工具条只保留「刷新」，其余移入"开发者诊断"折叠区（或仅在开发模式显示）。

### C. 导航与一致性

**C1 🔴 岛的「返回」按钮语义与用户预期不符**
`UiIslandView.vue:5` 的「← 返回」→ `AppShell.vue:440-448` 的 `backFromIsland()` 固定回退到**首个非岛模块**（当前是「便签」）。
**影响**：用户在订单归类里点"返回"，跳到便签 —— 一个他根本没去过的地方。侧栏本来就能切换，这个按钮制造的是困惑而非便利。
**建议**：删掉它（侧栏足够），或改为"回到上次所在的模块"（`AppShell` 已有 `backId` 机制可复用）。

**C2 🟡 双重工具条 + 两级导航视觉连续**
宿主给每个岛加一条 36px 工具条（`UiIslandView.vue:183-192`），岛内自己还有顶栏与页签。侧栏（一级）与岛内页签（二级）没有视觉层级差异。
**建议**：宿主工具条精简到只剩必要的（刷新/诊断）；岛内页签样式统一（当前各岛自绘）。

**C3 🔴 同名能力两份，用户无法判断用哪个**
「拣货」既是 `ui-plugins/order-insight/dist/views/picking.js` 的页签，也是 `src/modules/picking/meta.ts:10` 的侧栏模块。
**建议**：保留一个（建议保留宿主模块，岛内页签改为跳转），或至少在两边互相注明"与另一处是同一份口径 / 差异是什么"。

**C4 🔴 悬空引用：「运费测算」不存在**
`src/modules/order-cost/OrderCostView.vue:406`：`先去「运费测算」导入一次运价表`。全仓检索"运费测算"仅此一处，实际功能名是「无忧物流运费」，页签是「运费查询」。
**建议**：改成实际名称。同时建议建立**文案级的模块名常量表**，避免同类问题（目前模块中文名散落在各文件字符串里）。

**C5 🟡 供应商维护入口两处说法互相矛盾**
`ui-plugins/product-library/src/components/SupplierView.vue:7` 说"自「订单归类 → 拿货对账」迁移而来"；同目录 `ProductEditor.vue:40` 却说"厂家在「拿货对账」里维护，这里只做关联"。
**影响**：用户在两个页面被指向两个不同的地方，两边都指不到真正的维护入口。
**建议**：以 `SupplierView` 为准，修掉 `ProductEditor.vue:40` 的过期文案（一行改动，收益高）。

**C6 ⚪ 「设置」页签在岛内是异类**
`ShopAccountsView.vue:268-277` 的「设置」页签实际是跳去宿主设置中心（带外链图标）。页签与"跳出去"两种交互混在同一排。
**建议**：视觉上区分（如放右侧 + 明确"打开设置中心"），或改为菜单项。

### D. 状态反馈与危险操作

**D1 🟡 岛加载失败无自助手段**
宿主兜底只有"加载中…"（`AppShell.vue:167-172`）；握手失败只由一个小圆点与一行字表示（`UiIslandView.vue:74-77`），重试按钮是那条工具条上的「重新加载」。
**建议**：超时后把状态行升级为可操作提示（"未能连接，点此重试"），并把技术原因收进折叠区。

**D2 🟡 破坏性操作的确认方式三种混用**

| 方式 | 例子 | 取证 |
| --- | --- | --- |
| 系统原生 `confirm()` | 恢复出厂设置、导入备份 | `SettingsModal.vue:319,362` |
| 按钮变"确认卸载?"（4 秒超时） | 卸载插件 | `PluginCenter.vue:138,483-491` |
| 自绘弹层 | 删除产品（带长文案解释"物理删除不可撤销"） | `ProductEditor.vue` / `ProductListView.vue` |

**建议**：统一为自绘弹层（原生 `confirm` 在 Electron 里像系统错误框，且无法本地化样式），确认文案模板统一为"影响 + 是否可撤销 + 替代方案"。

**D3 ⚪ 空态文案质量参差**
好例：`还没有产品 —— 可以先「下载模板」填好后导入`、`还没有商品 —— 点击「导入商品」从 Excel 导入`。
弱例：`暂无日志`、`暂无数据`（无下一步）。
**建议**：空态统一三段式：**现状 + 原因 + 一个可点的下一步**。

**D4 ⚪ 缺口标签密度高**
「订单利润」页单行能出现 `缺收入/缺国家/缺克重/缺运价卡/未识别款/缺成本/税未知/缺件数` 八种标签（`OrderCostView.vue:288`）。信息诚实，但用户不知道**先补哪个**。
**建议**：按"补齐成本/收益最大"排序并给出跳转（或提供"一键补全"的任务清单页）。

### E. 重复劳动与数据口径

**E1 🟡 同一份 Excel 导两遍**
速卖通「商品信息」Excel：运费岛的「按订单试算」导一次（`pl_item_weights`）；产品库「商品清单」再导一次（`shop-products`）。且两条重量数据源**刻意不混用**（`CHANGELOG.md:378`、`ui-plugins/shipping-rate/dist/views/products.js` 文件头注释）。
**影响**：用户视角是"为什么同一件事要做两次"，且两次结果可能不一致而无人提示。
**建议**：至少在两处导入界面互相说明差异与用途；中期在导入时提示"检测到另一处已有同名文件"。

**E2 🟡 成本要手动同步**
利润追踪的「成本衔接」需手动点「从拿货对账导入/刷新成本」（`ui-plugins/ae-profit/src/components/CostRatesPanel.vue`）。
**建议**：在拿货单落账后提示"成本已更新，去利润页刷新"，或提供一键刷新入口。

**E3 🟡 两处都在讲钱，用户不知道看哪个**
「订单利润」（宿主模块，预测口径）与「利润追踪」（岛，结算口径）。
**建议**：明确分工并在两端互相交叉引用（"预测看这里，已结算看那里"）。

**E4 🟡 界面承诺与数据不符（店铺列）**
商品清单导入固定 `shopId: 0`（不关联店铺），但列表把"店铺"作为正式列展示。
**建议**：未关联时列内显示"未关联（可在映射页处理）"而不是空白。

### F. 帮助与文档

**F1 🔴 用户文档描述的是另一个产品**
`docs/guides/USER_GUIDE.md` 全文仍是"Excel 导入 → 模板替换 → 复制到剪贴板"的工具说明，界面图是旧的三栏布局、工具菜单（`USER_GUIDE.md:143-179`）。现在这些能力都在「TV模版」岛里，且产品的重心已变成订单/产品/店铺/利润。
**影响**：用户照文档找不到界面；新人也据此形成错误认知。`docs/README.md:26` 已标注"覆盖面偏旧"，但仍放在"终端用户"的推荐阅读路径里（`docs/README.md:57`）。
**建议**：要么重写为岛时代的用户手册（按"我要做什么"组织），要么明确降级为"TV模版功能说明"并另写一份产品级指南。

**F2 🟡 无应用内帮助**
所有功能说明都写在空态与 toast 里，窗口内没有可检索的帮助入口（⌘K 只覆盖模块切换与命令，`CommandPalette.vue:107-152`）。
**建议**：⌘K 增加"帮助"分区（功能名 → 打开对应帮助）；或加"这个页面怎么用"按钮，指向随包分发的 Markdown。
